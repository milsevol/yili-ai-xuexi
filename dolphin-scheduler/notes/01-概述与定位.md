# 01 概述与定位

## 一句话

**DolphinScheduler（海豚调度）**：用可视化 DAG 把一批定时/依赖任务串起来，在分布式集群上跑，并能补数、重试、告警、容错。

## 它解决什么问题

数据团队常见痛点：

1. **任务多、依赖乱**：A 跑完才能跑 B，B/C 并行后再跑 D；脚本 + crontab 很快失控。
2. **失败难处理**：半夜任务挂了，谁重跑、从哪重跑、要不要补昨天的数据。
3. **资源与权限**：多团队共用集群，租户隔离、资源文件、数据源账号要管。
4. **运维可见性**：谁在跑、卡在哪、日志在哪、告警发到哪。

海豚调度把「定义 → 调度 → 执行 → 监控」收成一个平台。

## 典型使用场景

| 场景 | 例子 |
| --- | --- |
| 离线数仓 | ODS → DWD → DWS → ADS 分层任务按依赖跑 |
| 报表 / 指标 | 每天 T+1 出报表，失败发钉钉/邮件 |
| 数据同步 | Sqoop / DataX / FlinkCDC 定时拉取 |
| 计算作业 | Spark / Flink / MR / SeaTunnel |
| 运维脚本 | Shell / Python 巡检、清理、备份 |
| ML 流水线 | 特征 → 训练 → 评估 → 发布（配合插件） |

## 核心卖点（相对「一堆 crontab」）

- **可视化 DAG**：拖拽建工作流，依赖一眼能看懂
- **多租户 / 权限**：项目级隔离，适合多人协作
- **丰富任务类型**：Shell、SQL、Spark、Flink、HTTP、子工作流、依赖节点等
- **补数（backfill）**：按时间区间串行/并行补历史
- **高可用**：多 Master、多 Worker，注册中心做心跳与容错
- **国产社区活跃**：中文文档多，国内大数据平台常见选型

## 和同类产品怎么选（粗粒度）

| | DolphinScheduler | Airflow | 传统 crontab / XXL-JOB |
| --- | --- | --- | --- |
| 定义方式 | UI 拖拽为主，也有 API/Python SDK | Python DAG 代码为主 | 单任务或简单编排 |
| 上手 | 偏运维/数仓同学友好 | 偏开发同学友好 | 极简 |
| 大数据任务 | 一等公民（Spark/Hive 等） | 靠 Operator，很强但要写代码 | 弱 |
| 补数 / 依赖 | 产品化做得全 | 强大但要懂框架 | 自己造 |
| 部署 | Java 体系 + 注册中心 + DB | Python + 元数据库 | 轻 |

**经验法则**：

- 团队以 **数仓 / 可视化运维** 为主、希望少写代码 → 优先考虑海豚调度
- 团队以 **Python 工程化** 为主、DAG 当代码管理 → Airflow 更自然
- 只有少量无依赖定时任务 → 不必上重型调度

## 学习时抓住的主线

后面章节都围着这条链：

```
项目(Project) → 工作流定义(Workflow Definition / DAG)
            → 定时或手动触发 → 工作流实例
            → 切分任务 → 任务实例 → Worker 执行 → 状态回流 / 告警
```

先记住两个词：**定义（Definition）** 和 **实例（Instance）**——定义是模板，每次跑出来的是实例。
