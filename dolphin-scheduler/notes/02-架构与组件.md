# 02 架构与组件

## 总览

3.x 大致组件：

```
        ┌─────────┐
        │   UI    │
        └────┬────┘
             │ HTTP
        ┌────▼────┐      ┌─────────────┐
        │   API   │──────│  元数据库    │
        └────┬────┘      │ (MySQL/... )│
             │           └──────▲──────┘
     ┌───────┴────────┐         │
     │                │         │
┌────▼────┐      ┌────▼────┐    │
│ Master  │◄────►│ Worker  │────┘（2.x+ Worker 不再直连 DB）
└────┬────┘      └────┬────┘
     │                │
     └───────┬────────┘
             │ 心跳 / 注册 / 协调
        ┌────▼────────┐
        │  注册中心    │  ZooKeeper / Etcd / JDBC 等
        └─────────────┘

        ┌─────────────┐
        │ Alert Server│  告警插件（邮件、钉钉、企业微信…）
        └─────────────┘
```

## 各组件职责

### API Server

- 对外提供 **RESTful API**，UI 和第三方都走它
- 工作流的增删改查、上线/下线、手动启动、暂停、停止、补数等
- 读写 **元数据库**（流程定义、实例状态、用户权限等）

### Master Server

去中心化多 Master。核心职责：

1. **扫描 Command**：定时扫命令表（如 `t_ds_command`），按命令类型处理（启动、重跑、补数、容错恢复…）
2. **DAG 切分与调度**：按拓扑把就绪任务提交出去
3. **监控与容错**：监听其他 Master / Worker 健康；故障时做 failover
4. **定时调度**：内嵌 **Quartz**（分布式），到点生成启动命令

可以记成：**Master 管「什么时候跑、怎么拆、谁挂了怎么办」**。

### Worker Server

去中心化多 Worker。核心职责：

1. **领取并执行任务**（Shell、SQL、Spark…）
2. **提供任务日志**
3. 向注册中心 **心跳**；任务结果回报 Master

可以记成：**Worker 管「真正干活」**。

3.x 演进要点：Worker **不再直接依赖数据库**，减轻 DB 压力，更利于大规模扩 Worker。

### 注册中心（Registry）

早期强依赖 ZooKeeper；3.2+ 可选用 **Etcd / JDBC** 等，弱化单点依赖。

用途：

- 服务发现（Master / Worker 注册）
- 心跳与宕机感知
- 分布式协调（选举、锁、容错触发）

### Alert Server

- 流程失败、超时、容错等告警
- 插件化：邮件、钉钉、企业微信、Slack 等
- 较新版本支持 Alert HA

### 元数据库

存定义与运行态：项目、工作流、任务、调度、实例状态、用户租户等。生产必须做好备份与监控。

## 一次调度的简化链路

1. 用户在 UI 上线工作流，并配置 cron
2. Quartz 到点 → Master 写入/产生 **启动命令**
3. Master 扫描命令 → 创建 **流程实例** → 按 DAG 找入度为 0 的任务
4. Master 把任务分发给合适的 Worker（按 Worker 分组、负载等）
5. Worker 执行 → 回报成功/失败
6. Master 推进后继节点；全部结束则流程实例成功；失败则按策略重试/告警

## 去中心化在说什么

不是「没有 Master」，而是：

- 多个 Master / 多个 Worker **地位对等、可水平扩展**
- 通过注册中心感知成员变化
- 某台 Master 挂了，其他 Master 接管其负责的实例（failover）
- 避免「唯一中心挂了全家挂」

## Worker 分组（实战常考点）

生产常把 Worker 分成组，例如：

- `default`：普通 Shell
- `spark`：有 Spark Client / Yarn 权限的机器
- `gpu`：训练任务

任务可指定跑在某个 Worker 组，避免「随便一台机器没环境就失败」。
