# 08 部署与快速上手

本章目标：本机快速跑起来 → 理解生产集群该怎么摆。

## 部署形态对比

| 形态 | 适用 | 特点 |
| --- | --- | --- |
| **Standalone** | 快速体验 | 单进程起所有角色，内置注册与存储，**勿用于生产** |
| **Docker Compose** | 学习 / 演示 | 一键拉起全套（PG + ZK + Master/Worker/API/Alert） |
| **伪集群** | 预发 / 验证 | 一台机器多进程，接近真实角色划分 |
| **集群** | 生产 | 多 Master + 多 Worker + 外部 DB + 注册中心 |
| **Kubernetes** | 云原生 | 官方 Helm Chart |

## 方式一：Docker Compose 快速体验（推荐学习用）

前置：本机有 Docker / Docker Compose。

```bash
# 1. 获取源码（或只取部署目录）
git clone https://github.com/apache/dolphinscheduler.git
cd dolphinscheduler/deploy/docker

# 2. 一键拉起
docker compose up -d

# 3. 查看状态
docker compose ps
```

访问 `http://localhost:12345/dolphinscheduler/ui`，默认账号 `admin / dolphinscheduler123`（以所用版本为准）。

也可以直接用官方镜像单容器体验：`apache/dolphinscheduler-standalone-server:<version>`。

## 方式二：二进制伪集群

1. 准备 JDK：3.x 支持 JDK 8 / 11（本机默认 JDK 17 时需把 `JAVA_HOME` 切到 1.8/11，切换方法见仓库根目录《开发环境信息.md》）
2. 下载发行包并解压
3. 初始化元数据库：配好数据库连接后执行 `bash tools/bin/upgrade-schema.sh`
4. 按需修改 `conf/` 下各角色配置
5. 启动各角色：`bash bin/dolphinscheduler-daemon.sh start master-server`（worker-server / api-server / alert-server 同理）

## 生产集群要点

```
                    ┌─ LB（Nginx）─┐
  用户/第三方 ─────►│              │────► API Server ×2+
                    └──────────────┘

  Master ×2+      Worker ×N（按组分机器）     Alert ×2
      │                │                      │
      └─────── 注册中心（ZK ×3 / Etcd ×3）─────┘
                        │
              元数据库 MySQL（主从 + 定时备份）
              资源中心 HDFS / S3
```

检查清单：

- [ ] JDK 版本符合所选 DS 版本要求
- [ ] 元数据库高可用 + 备份；连接池参数按并发调
- [ ] 注册中心独立部署且高可用
- [ ] Master ≥ 2；Worker 按组分机组、按负载扩
- [ ] 资源中心指向 HDFS / S3，不用 API 本地盘
- [ ] Alert 配好通道并**实测一次**
- [ ] 日志目录磁盘监控（任务日志写在 Worker 本地，会胀）
- [ ] 时区全链路统一（Server / DB / Worker / UI）

## 首次使用最小闭环（对着 UI 操作一遍）

1. **安全中心**：建租户（Worker 机上有同名 Linux 用户）→ 建用户并绑租户
2. **数据源中心**：建一个 MySQL / Hive 数据源
3. **项目管理**：建项目 `demo`
4. **工作流定义**：拖一个 Shell 任务，内容 `echo "bizdate=$[yyyy-MM-dd-1]"` → 保存 → **上线**
5. **定时调度**：配 cron `0 0 2 * * ?` → **调度上线**（两个开关别漏）
6. 手动点「运行」→ 到**工作流实例**看状态 → 点任务实例看日志
7. 故意把脚本改成 `exit 1` → 重跑 → 观察失败告警与「从失败节点恢复」

走完这 7 步，第 03 章的概念就全对上了。

## 常见部署问题

| 问题 | 排查 |
| --- | --- |
| 页面打不开 / 502 | API 进程是否活；12345 端口；nginx 转发 |
| 任务一直「提交成功」不运行 | Worker 是否注册成功（看注册中心）；Worker 组是否匹配 |
| Master 频繁容错 | Master 日志；ZK 会话超时参数；机器资源 |
| 元数据库连接爆 | 连接池上限；慢 SQL；实例表是否过大 |
| 改完配置不生效 | 是否重启对应角色；改的是不是对的 conf 目录 |
