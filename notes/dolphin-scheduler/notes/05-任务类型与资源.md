# 05 任务类型与资源

海豚调度的「生产力」很大程度来自：任务类型够不够、资源与数据源管得好不好。

## 常见任务类型（按使用频率）

### 脚本类

| 类型 | 用途 |
| --- | --- |
| **SHELL** | 万能入口：调脚本、拉数据、调 spark-submit |
| **PYTHON** | 直接跑 Python 片段或脚本（注意 Worker 环境） |

实践：复杂逻辑仍建议落 **Git 管理的脚本**，任务里只 `bash run.sh ${bizdate}`，便于评审与复用。

### 数据与 SQL

| 类型 | 用途 |
| --- | --- |
| **SQL** | 连数据源执行查询/DDL/DML；可把结果邮件发出 |
| **PROCEDURE** | 存储过程 |

SQL 任务依赖 **数据源中心** 里配好的连接（MySQL、PostgreSQL、Hive、ClickHouse…）。

### 大数据计算

| 类型 | 用途 |
| --- | --- |
| **SPARK** | Spark 作业 |
| **FLINK** | Flink 作业 |
| **MR** | MapReduce |
| **SeaTunnel / DataX 等** | 同步（视版本与插件） |

要点：Worker 组机器上要有对应客户端、队列权限、配置文件；否则 UI 配得再漂亮也会跑挂。

### 编排与控制

| 类型 | 用途 |
| --- | --- |
| **SUB_WORKFLOW** | 嵌套子工作流，主流程变薄 |
| **DEPENDENT** | 跨流程/跨周期依赖 |
| **CONDITIONS / SWITCH** | 按结果分支 |
| **HTTP** | 调 HTTP API，做探针或触发下游系统 |

### 其他

HTTP、SQOOP、数据质量、机器学习相关插件等——以你部署版本的「任务类型列表」为准；社区在持续加插件。

## 资源中心（Resource）

上传并管理：

- 脚本（`.sh` / `.py`）
- jar 包、配置文件
- UDF、资源文件

任务执行时把资源拉到 Worker 本地再跑。

进阶：对接 **HDFS / S3 / OSS** 等，避免 API 机磁盘当唯一仓库。

**好习惯**：

- 资源命名带版本或用发版目录
- 大 jar 走对象存储 / 制品库，不每次手工上传超大文件到 UI

## 数据源中心（Datasource）

集中管理连接信息：

- JDBC URL、账号密码（加密存储）
- 类型：MySQL、Hive、Oracle、Doris…

SQL 任务、部分同步任务从这里选数据源，避免把密码写死在脚本里。

## 环境与 Worker 组（再强调）

同一任务在测试 Worker 能过、生产挂掉，多半是：

1. Python/Java 版本不一致
2. 没装客户端 / 路径不对
3. 队列或 Kerberos 权限不足
4. 资源文件没关联上

→ 用 **Worker 组 + 环境管理** 把「能跑这类任务的机器」固定下来。

## 参数与出参（任务间协作）

典型模式：

1. 任务 A（SQL/Shell）算出一个分区或文件路径
2. 写成出参
3. 任务 B 引用该参数作为输入

配合业务日期参数，组成可补数的流水线。

## 最小「数仓日批」任务素描

```
1. DEPENDENT   等待上游域昨日成功（可选）
2. SHELL       拉取/校验源数据
3. SQL/Spark   ODS → DWD
4. Spark       DWD → DWS
5. SQL         数据质量检查（失败则让节点失败）
6. SHELL/HTTP  通知或触发报表刷新
```

不必一上来用全任务类型；**Shell + SQL + Spark + Dependent + SubWorkflow** 覆盖大多数离线场景。
