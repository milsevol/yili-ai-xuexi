# 01 概述与定位

## 一句话

**Apache DolphinScheduler（海豚调度）**：一个分布式、去中心化、可视化的 DAG 工作流任务调度平台——把一批有依赖关系的定时任务串成图，在集群上稳定执行，并自带补数、重试、告警、容错与多租户能力。

## 它解决什么问题

数据团队几乎都会经历这三个阶段：

1. **脚本 + crontab 阶段**：几台机器上散落几十个 cron，谁也说不清全貌。
2. **自研脚本编排阶段**：写一个「调度脚本」串行调起各任务，再加 `sleep` 等上游，脆弱且不可维护。
3. **调度平台阶段**：用专业平台统一管理「定义 → 调度 → 执行 → 监控」。

海豚调度针对的具体痛点：

| 痛点 | 裸 crontab 的表现 | 海豚调度的解法 |
| --- | --- | --- |
| 依赖复杂 | A 跑完才能跑 B，只能靠时间错开「赌」 | DAG 显式声明依赖，前驱成功才解锁后继 |
| 失败难恢复 | 半夜挂了人工登录机器找断点 | 任务级自动重试 + 流程级「从失败节点恢复」 |
| 补数痛苦 | 手写 for 循环改日期跑脚本 | 产品化补数：选区间自动生成一批实例 |
| 多团队混用 | 账号、资源、权限一锅粥 | 项目 + 租户 + 用户三级隔离 |
| 看不见 | 不知道谁在跑、卡在哪 | UI 实例时间线 + 任务日志 + 告警 |

一句话：**它把「定义 → 调度 → 执行 → 监控」收成一个平台**，而不是散落各处的脚本。

## 典型使用场景

| 场景 | 例子 | 主要用到的能力 |
| --- | --- | --- |
| 离线数仓 | ODS → DWD → DWS → ADS 分层日批 | DAG 依赖、SQL/Spark 任务、业务日期参数 |
| 报表 / 指标 | 每天 T+1 出经营报表 | cron 定时、失败告警（钉钉/邮件）、优先级 |
| 数据同步 | DataX / SeaTunnel / Sqoop 定时拉取 | 同步任务类型、数据源中心 |
| 计算作业 | Spark / Flink / MR 批作业 | 对应任务插件、Worker 组隔离环境 |
| 跨系统编排 | 跑完数仓后调 HTTP 触发 BI 刷新 | HTTP 节点、子工作流 |
| 运维自动化 | 巡检、清理、备份脚本 | Shell 任务、超时告警 |
| ML 流水线 | 特征 → 训练 → 评估 → 发布 | Python/Shell/HTTP 组合（或 ML 类插件） |

## 核心卖点

- **可视化 DAG 编排**：拖拽建工作流，依赖关系一眼看懂，非研发同学也能维护
- **定义 / 实例分离**：改模板不影响在跑实例；重跑、补数都是针对实例的运维动作
- **丰富的任务类型**：Shell、SQL、Python、Spark、Flink、MR、HTTP、子工作流、依赖、条件分支等 30+ 种
- **产品化补数**：按时间区间串行/并行回补历史
- **去中心化高可用**：多 Master、多 Worker，注册中心做心跳与故障接管
- **多租户与权限**：项目级授权，租户对应执行机 Linux 用户
- **生态与社区**：Apache 顶级项目，中文文档完善，国内大数据平台常见选型

## 发展简史（了解即可）

- 2017 年由易观开源，2019 年进入 Apache 孵化器，2021 年毕业为顶级项目。
- **1.x**：强依赖 ZooKeeper（连任务队列都放 ZK），规模上去后 ZK 压力大。
- **2.x**：架构重构，Worker 不再直连数据库，Master/Worker 之间走 Netty 通信，性能与可扩展性大幅提升。
- **3.x**：注册中心可插拔（ZooKeeper / Etcd / JDBC）、UI 重写、任务插件体系化、Worker 分组与环境管理完善。**本系列笔记以 3.x 为准。**

## 和同类产品怎么选

| 维度 | DolphinScheduler | Airflow | XXL-JOB | crontab |
| --- | --- | --- | --- | --- |
| 定位 | 数据工作流调度平台 | 可编程工作流框架 | 分布式任务调度（轻量） | 单机定时 |
| DAG 定义 | UI 拖拽为主 + OpenAPI/Python SDK | Python 代码 | 简单父子依赖 | 无依赖概念 |
| 上手人群 | 数仓/运维友好 | Python 开发友好 | Java 开发友好 | 人人会用 |
| 大数据任务 | 一等公民（Spark/Hive/Flink 内置插件） | 靠 Operator，能力强但要写代码 | 需自行包装 | 自己写脚本 |
| 补数 | 产品化内置 | 强（catchup / backfill） | 弱 | 手工 |
| 多租户/权限 | 完善 | 一般（RBAC 较晚补齐） | 简单 | 无 |
| 部署栈 | Java + 注册中心 + RDBMS | Python + RDBMS（+Celery/K8s） | Java + RDBMS | 无 |
| 适用规模 | 中大型企业数据平台 | 中大型工程团队 | 中小任务量 | 个人/边角需求 |

**经验法则**：

- 团队以 **数仓 / 可视化运维** 为主、希望少写代码 → 海豚调度
- 团队以 **Python 工程化** 为主、DAG 当代码评审管理 → Airflow
- 只是 Java 服务里的分布式定时任务（无复杂依赖） → XXL-JOB
- 少量无依赖脚本 → crontab 就够了，别上重平台

更详细的对比见第 10 章。

## 学习主线

本系列后面章节都围绕这条链路展开：

```
租户/用户 → 项目 → 工作流定义(DAG) → 上线 + 配置定时
        → 触发(cron/手动/API/补数) → 工作流实例
        → Master 切分任务 → Worker 执行任务实例
        → 状态回流 → 告警 / 重跑 / 恢复
```

先死死记住两个词：**定义（Definition）** 是模板，**实例（Instance）** 是每一次具体运行。
