# 03 核心概念

学海豚调度，先把名词对齐，否则 UI 和文档会绕晕。

## 概念地图

```
租户 Tenant
  └── 用户 User（绑定租户）
        └── 项目 Project（授权）
              └── 工作流定义 Workflow Definition（DAG）
                    ├── 任务定义 Task Definition（节点）
                    ├── 定时 Schedule（cron）
                    └── 每次运行 → 工作流实例 Workflow Instance
                                      └── 任务实例 Task Instance
```

## 租户（Tenant）

- 对应 Linux / 执行环境下的 **系统用户** 概念（Worker 上常以租户用户身份跑任务）
- 多团队隔离资源与权限时用
- 创建用户时要绑定租户；任务实际跑在 Worker 上会落到该租户上下文

> 本地 Docker 试用时也常有 `tenant` 配置；生产务必规划好租户命名与机器账号。

## 用户与权限

- 用户：登录 UI / 调 API 的人
- 权限粒度常见：**管理员 / 项目权限（负责人、可执行、只读等）**
- 实践建议：按项目授权，避免所有人用一个超管账号

## 项目（Project）

协作与隔离的基本单位。一个项目里放一组相关工作流（例如「用户域数仓」「财务报表」）。

## 工作流定义（Process / Workflow Definition）

- 拖拽任务节点 + 连线形成的 **DAG 模板**
- 有版本：编辑后需 **上线** 才按新定义调度；下线后定时不再生效
- 可配置全局参数、失败策略、超时告警等

## 任务定义（Task Definition）

DAG 上的一个节点，例如：

- 业务节点：Shell、SQL、Python、Spark、HTTP…
- 逻辑/控制节点：子工作流、依赖（Dependent）、条件、开关等

每个任务可配：重试次数、超时、Worker 组、环境、资源文件、本地参数等。

## 工作流实例 / 任务实例

| | 定义 Definition | 实例 Instance |
| --- | --- | --- |
| 是什么 | 模板 | 某一次具体运行 |
| 何时产生 | 保存/上线 | 手动启动、定时、补数、API 触发 |
| 状态 | 上线/下线 | 提交成功、运行中、成功、失败、停止、暂停… |

**流程实例状态**由其中任务推进汇总；**任务实例状态**反映单节点执行结果。

## 调度（Schedule）

- 绑定在「已上线的工作流」上
- 用 **cron**（UI 可可视化生成）
- 常见坑：时区、上线未开调度、cron 写错导致空跑或狂跑

## 参数

分层理解即可：

1. **全局参数**：工作流级，所有任务可见
2. **本地参数**：任务级
3. **系统内置参数**：如业务日期 `$[yyyy-MM-dd]`、实例时间等（具体写法以你用的版本文档为准）
4. **上游出参 → 下游入参**：任务间传参

数仓场景几乎总要：**业务日期（biz date）** 驱动分区路径与 SQL where。

## 命令类型（Command）——理解运维操作的钥匙

Master 消费的「命令」决定这次怎么跑，常见包括：

| 操作（用户视角） | 含义 |
| --- | --- |
| 启动 / 定时触发 | 从起始节点正常跑 |
| 重跑 | 从开始重新跑该实例 |
| 从失败节点恢复 | 只重跑失败及后继 |
| 从当前节点执行 | 指定节点起跑 |
| 补数 | 按时间区间生成一批实例 |
| 暂停 / 停止 | 控制运行中实例 |
| 容错恢复 | 系统内部，Master/Worker 故障后恢复 |

区分三个易混概念：

1. **任务失败重试**：任务级，自动，按配置次数
2. **从失败节点恢复**：流程级，通常手动（或运维策略）
3. **重跑**：流程级，从头再来

## 自测

1. 为什么「改了 DAG 却没按新逻辑跑」？可能漏了哪一步？
2. 租户和项目分别隔离的是什么？
3. 「任务重试三次」和「从失败节点恢复」谁自动、谁偏人工？
