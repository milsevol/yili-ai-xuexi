# 07 资源中心 · 数据源 · Worker 组与环境

第 05 章讲「任务干什么」，本章讲「任务依赖的东西放哪、跑在什么环境」。

## 资源中心（Resource）

集中托管任务需要的文件：

- 脚本（`.sh` / `.py` / `.sql`）
- jar 包（Spark / MR 作业）
- 配置文件、UDF 文件

**存储后端**：

| 后端 | 适用 |
| --- | --- |
| API Server 本地磁盘 | 学习 / 演示（默认） |
| HDFS | 已有 Hadoop 体系的生产 |
| S3 / OSS / GCS | 云原生体系 |

生产务必切到 HDFS / 对象存储：否则 API 本地盘是唯一副本，且多 API 实例时文件会不一致。

**使用方式**：任务配置里勾选资源文件 → 执行时 Worker 自动下载到任务工作目录 → 脚本中按文件名直接引用。

**好习惯**：

- 按目录管理：`/etl/scripts/`、`/etl/jars/`
- jar 带版本号（`user-etl-1.3.0.jar`），发布 = 上传新文件 + 改任务引用，可回滚
- 超大制品走制品库 / 对象存储，任务里 `curl` 拉取，不从 UI 传巨型文件

## 数据源中心（Datasource）

集中管理数据库连接，供 SQL、DataX、PROCEDURE 等任务选择：

- 类型：MySQL、PostgreSQL、Hive、Oracle、ClickHouse、Doris、Presto / Trino……
- 内容：JDBC URL、账号密码（加密存储）、连接参数
- 可按用户授权：谁能用哪个数据源

好处：密码不落脚本；换库只改数据源一处。

Hive 数据源注意：填 HiveServer2 的 JDBC 地址（`jdbc:hive2://...`）；Kerberos 环境要配 principal 与 keytab，且 Worker 上有对应凭证。

## Worker 组（Worker Group）

把 Worker 按「能力」分组，任务指定组来选执行机：

| 组 | 装有什么 | 跑什么 |
| --- | --- | --- |
| `default` | 基础环境 | Shell / SQL / HTTP |
| `spark` | Spark 客户端 + Yarn 权限 | spark-submit |
| `hive` | Hive 客户端 | Hive CLI |
| `python-ml` | GPU + Python 科学栈 | 训练任务 |

创建方式：Worker 配置 `worker.groups` 声明自己属于哪些组；UI 任务上选择组。

**组名打错**是「任务一直不运行」的最高频原因之一——任务在等一个永远不存在的组。

## 环境管理（Environment）

3.x 的实用功能：把「执行任务前要 source 的环境」定义成**环境配置**：

```bash
export JAVA_HOME=/usr/lib/jvm/java-8
export SPARK_HOME=/opt/spark
export PATH=$SPARK_HOME/bin:$PATH
source /opt/venvs/etl/bin/activate
```

- 环境绑定到 Worker 组；任务选择环境后，Worker 执行前先 source
- 解决「同一集群要同时支持 Spark2 / Spark3、Py2 / Py3」这类多版本共存问题
- 没有环境管理之前的土办法（每个 Shell 任务开头写一堆 export）不要再用了

## 排障症状对照表

| 症状 | 大概率原因 |
| --- | --- |
| 测试能跑生产挂 | Worker 组指错，机器没对应客户端 |
| 资源文件找不到 | 任务没勾选关联资源 / 资源中心后端不通 |
| SQL 连不上 | 数据源配置错 / Worker 到 DB 网络不通 |
| 环境变量没生效 | 任务没选环境，或环境没绑定该 Worker 组 |
| 所有 Worker 都不接活 | 负载超阈值（CPU / 内存保护），看 Worker 日志 |
