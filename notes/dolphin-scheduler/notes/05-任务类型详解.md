# 05 任务类型详解

海豚的生产力很大程度来自任务类型的丰富度（3.x 有 30+ 种）。本章按使用频率讲常用类型的「干什么、怎么配、注意什么」。

## 脚本类

### SHELL

万能入口，本质是一个 Shell 脚本框，Worker 上 fork `/bin/bash` 执行。

```bash
#!/bin/bash
set -euo pipefail

echo "业务日期: $[yyyy-MM-dd-1]"
bash scripts/etl_user.sh --date $[yyyy-MM-dd-1]
```

注意：

- 复杂逻辑放进 **Git 管理的脚本文件**（上传资源中心后在任务里勾选），任务里只做一行调用——便于评审、复用、回滚
- 脚本退出码非 0 = 任务失败；养成 `set -e` 习惯
- 工作目录是 Worker 为本次任务创建的临时执行目录，别依赖相对路径假设；资源文件会被下载到该目录

### PYTHON

直接执行 Python 代码片段或脚本文件。

注意：用的是 **Worker 机器上的 Python**；三方依赖要在对应 Worker 组预装，或用「环境管理」在任务执行前 `source venv/bin/activate`（见第 07 章）。

## 数据与 SQL 类

### SQL

直连「数据源中心」配置的数据源执行 SQL：

- 查询（SELECT）：结果可邮件发送 / 写日志；单行单列结果可设为**出参**传给下游
- 非查询（DDL / DML）：建分区、`INSERT OVERWRITE` 等
- 多语句：按分隔符拆分逐条执行

```sql
-- Hive SQL 示例：T+1 写 DWD 分区
INSERT OVERWRITE TABLE dwd_user PARTITION(dt='$[yyyy-MM-dd-1]')
SELECT user_id, name, phone
FROM ods_user
WHERE dt='$[yyyy-MM-dd-1]';
```

注意：

- 连接信息（含密码）走**数据源中心**，不要写死在任务里
- 大结果集别用 SQL 任务拉回本地，那是计算引擎的活
- Hive 场景注意执行方式（HiveServer2 直连 vs 走 Spark 引擎）

### PROCEDURE

调用存储过程，配置思路同 SQL。

## 大数据计算类

### SPARK

封装 `spark-submit`，页面化配置：

| 配置项 | 示例 |
| --- | --- |
| 部署模式 | cluster / client / local |
| 主类 | `com.dw.UserDwdJob` |
| 主程序包 | 资源中心里的 `user-etl-1.3.0.jar` |
| 资源 | driver / executor 内存、核数 |
| 程序参数 | `--bizdate $[yyyy-MM-dd-1]` |

注意：Worker 组机器必须装 Spark 客户端、有 Yarn 队列权限；jar 放资源中心（或 HDFS/S3）。

### FLINK / MR / Hive CLI

同理：页面封装 `flink run` / `hadoop jar` / `hive -e/-f`。要点一致——**客户端与权限在 Worker 组机器上**，UI 配得再漂亮，机器没环境照样挂。

### SeaTunnel / DataX / Sqoop

数据同步类（部分版本以插件提供）。适合「DB → Hive」「Hive → ClickHouse」等场景，替代手写同步脚本。

## 编排与控制类

### SUB_WORKFLOW（子工作流）

把一个**已上线**的工作流作为节点嵌进来。用途：

- 大平台按域拆分：主流程 = 各域子流程的编排
- 公共链路复用（如「数据质量检查」子流程）

注意：子流程要先上线；子流程失败 = 该节点失败。

### DEPENDENT（依赖）

跨流程 / 跨周期等待，详见第 04 章。

### CONDITIONS / SWITCH

- **CONDITIONS**：按上游任务**状态**分支（A 成功走这条、失败走那条）
- **SWITCH**：按上游**出参的值**分支（如 `row_count > 0` 走增量，否则走全量）

### HTTP

发 HTTP 请求。典型用途：

- 调下游系统 API（触发报表刷新、通知算法侧开始训练）
- 健康探针

可配置 URL、方法、Header、Body、校验条件（响应码 / 内容匹配）。

## 其他常用

| 类型 | 用途 |
| --- | --- |
| K8s | 把任务提交到 Kubernetes |
| Jupyter / Zeppelin | Notebook 场景 |
| MLflow / PyTorch 等 | ML 流水线（以版本插件为准） |
| DataQuality（数据质量） | 单表 / 两表校验规则，校验不过即节点失败 |

> 任务插件在持续增加，以你所部署版本的「任务类型」下拉框为准。

## 一个「数仓日批」工作流素描

```
1. DEPENDENT     等上游 ODS 域昨日实例成功
2. SHELL         拉取/校验源数据          (worker=default)
3. SQL           ODS → DWD               (datasource=hive_dw)
4. SPARK         DWD → DWS               (worker=spark, 资源=etl.jar)
5. SQL           DWS → ADS 报表表         (datasource=hive_dw)
6. DataQuality   关键指标校验，异常即失败
7. HTTP          触发 BI 平台刷新缓存
8. SHELL         成功后发通知（或交给告警组）
```

**经验**：Shell + SQL + Spark + Dependent + SubWorkflow 五种即可覆盖大多数离线场景，不必求全。
