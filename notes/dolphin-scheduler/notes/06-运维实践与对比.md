# 06 运维实践与对比

## 部署形态（从易到难）

| 形态 | 适用 | 说明 |
| --- | --- | --- |
| **Docker Compose 单机** | 学习、演示 | 官方/社区 compose 一键起，数据别当真 |
| **伪集群** | 预发 | 多进程或多容器模拟 Master/Worker |
| **生产集群** | 正式 | 多 Master、多 Worker、独立 DB、注册中心、监控告警 |

生产最低心理预期：

- 元数据库高可用或至少可靠备份
- 注册中心可靠
- Master ≥ 2，Worker 按负载扩
- Alert 配好；磁盘（日志）与连接数监控

## 容错你需要知道的

1. **Master 宕机**：其他 Master 接管未完成实例（failover 命令）
2. **Worker 宕机**：运行中任务被标记失败或迁移（视策略与版本）；需结合任务幂等
3. **任务重试**：短抖动优先靠任务级重试
4. **流程恢复**：长链路失败用「从失败节点恢复」，别总整库重跑

## 日志与排障顺序

1. UI 看流程实例 / 任务实例状态与时间线
2. 打开失败任务日志（Worker 侧）
3. 区分：**调度问题**（没触发、依赖不满足）vs **执行问题**（脚本/SQL/环境）
4. 查 Worker 组是否指错、资源是否拉取成功、数据源能否连通

## 和 Airflow 对照（选型谈话用）

| 维度 | DolphinScheduler | Airflow |
| --- | --- | --- |
| DAG 定义 | UI 为主 | Python 代码为主 |
| 版本管理 | 平台内版本 + 上线 | Git 自然友好 |
| 数仓 UI 运维 | 强 | 中（偏工程） |
| 生态 / 运营商 | 国内多 | 全球多 |
| 测试 DAG | 相对弱于「纯代码」 | pytest 等更顺 |
| 学习曲线 | 概念 + UI | 概念 + Python 框架 |

很多公司是：**调度平台用海豚，复杂自定义编排或 ML 用 Airflow / 自研**——不必二选一宗教信仰。

## 落地检查清单（你接手一套海豚时）

- [ ] 版本号（3.x？插件列表？）
- [ ] 注册中心类型与地址
- [ ] 元数据库备份与清理策略（实例表会胀）
- [ ] 默认租户、Yarn/K8s 队列、Worker 组划分
- [ ] 告警通道是否通
- [ ] 补数规范：业务日期参数、并行度上限
- [ ] 资源文件与脚本的发布流程（谁上传、如何回滚）

## 建议学习节奏（结合本仓库）

1. 读完 01–04，把 Definition / Instance / Master / Worker 讲清楚给别人听
2. 跑本主题 `demos/main.py` 把 DAG 执行、失败策略、补数在脑中「动画化」
3. 本机 Docker 起一套官方 demo，跟一遍：建租户 → 项目 → Shell 任务 → 上线 → 定时 → 故意失败 → 恢复
4. 在真实项目里画一张域内 DAG，标清业务日期与依赖，再落到平台
