# 06 参数传递与内置时间变量

参数体系是海豚实战里最容易踩坑、也最值得吃透的部分。核心问题就两个：**时间怎么算**、**值怎么在任务间传**。

## 参数的四个层级

| 层级 | 定义位置 | 作用域 | 典型用途 |
| --- | --- | --- | --- |
| 系统内置变量 | 无需定义 | 全局 | 业务日期、实例时间 |
| 全局参数 | 工作流定义 → 全局参数 | 整个工作流 | bizdate、环境标识 |
| 本地参数 | 任务定义 → 自定义参数 | 当前任务 | 表名、路径 |
| 上游出参 | 上游任务输出 → 下游引用 | 跨任务 | 分区值、行数、文件路径 |

引用方式统一：`${参数名}`。

**同名优先级**：本地参数 > 上游传递 > 全局参数。建议关键参数名全局唯一，别依赖覆盖行为。

## 内置时间变量（数仓刚需）

格式：`$[时间表达式]`。基于**流程实例的调度时间**（schedule time）计算——补数时每个实例的调度时间不同，这正是补数能跑对的原因。

假设调度时间为 `2026-11-01 02:00:00`：

| 表达式 | 含义 | 取值 |
| --- | --- | --- |
| `$[yyyy-MM-dd]` | 当天 | `2026-11-01` |
| `$[yyyyMMdd]` | 当天（紧凑格式） | `20261101` |
| `$[yyyy-MM-dd HH:mm:ss]` | 精确到秒 | `2026-11-01 02:00:00` |
| `$[yyyy-MM-dd-1]` | 前一天（T+1 日批的业务日期） | `2026-10-31` |
| `$[yyyyMMdd-1]` | 前一天紧凑格式 | `20261031` |
| `$[yyyy-MM-01]` | 本月 1 号 | `2026-11-01` |
| `$[add_months(yyyy-MM-dd,-1)]` | 上个月同日 | `2026-10-01` |
| `$[yyyy-MM-dd HH:mm:ss-2/24]` | 前 2 小时 | `2026-11-01 00:00:00` |

规则要点：

- 格式串后直接 `-N` = 减 N 天；`+N` = 加 N 天
- 小时级：`±N/24`；分钟级：`±N/(24*60)`
- 月 / 年用函数：`add_months(格式, N)`、`add_years(格式, N)`
- 格式遵循 Java `SimpleDateFormat`：`yyyy` 年、`MM` 月、`dd` 日、`HH` 24 小时制、`mm` 分、`ss` 秒

> 易混：`MM`（月）vs `mm`（分）；`HH`（24 时制）vs `hh`（12 时制）。写错不会报语法错误，只会拿到错误的值——新流程务必先用 echo 任务验证取值。

## 典型模式：T+1 日批

工作流每天 02:00 跑，处理「昨天」的数据：

1. 不显式定义日期参数，直接用内置变量
2. 各任务引用 `$[yyyy-MM-dd-1]` 作为业务日期：

```sql
-- SQL 任务
INSERT OVERWRITE TABLE dwd_trade PARTITION(dt='$[yyyy-MM-dd-1]')
SELECT * FROM ods_trade WHERE dt='$[yyyy-MM-dd-1]';
```

```bash
# Shell 任务
bash etl_trade.sh --date $[yyyy-MM-dd-1]
```

补数 10 月数据时：系统生成 31 个实例，每个实例调度时间依次为 10-02 ~ 11-01 的 02:00，`$[yyyy-MM-dd-1]` 自动等于 10-01 ~ 10-31，SQL 不用改一个字。

**反例（补数必错的写法）**：

```bash
# 用执行时刻推算昨天——补数时「昨天」永远是真正的昨天
date -d 'yesterday' +%F
```

## 任务间传参（出参 → 入参）

场景：任务 A 算出一个值（分区、文件路径、行数），任务 B 要用。

1. 任务 A 产生输出：
   - SQL 任务：把单行单列查询结果设为出参
   - Shell 任务：按特定格式打印（`echo '${setValue(key=value)}'`，以所用版本语法为准）
2. 任务 A 的「自定义参数」里把该参数方向设为 **OUT**
3. 任务 B 定义同名参数、方向 **IN**，脚本中用 `${key}` 引用

```
任务A detect_partition ──OUT(max_dt=2026-10-31)──► 任务B sync_data 使用 ${max_dt}
```

注意：

- 出参只适合传**小数据**（字符串 / 数字），别当数据管道
- 下游必须声明接收（IN），否则拿不到
- 手动启动工作流时可在启动弹窗临时覆盖全局参数，回刷时很好用

## 参数实战清单

- [ ] 所有分区 / 路径由内置时间变量驱动，无 `date` 命令推算
- [ ] 关键参数在工作流「全局参数」声明并给默认值
- [ ] 跨任务传值走 OUT / IN，不写临时文件硬传
- [ ] 新流程先用 echo / print 任务验证各时间变量取值，再接真实逻辑

## 常见坑

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| 用 `date -d yesterday` | 补数数据全跑到同一天 | 改 `$[yyyy-MM-dd-1]` |
| `mm` / `MM` 写反 | 日期里出现奇怪数字 | echo 验证 |
| 时区不一致 | 业务日期偏一天 | 统一 Server / DB / Worker 时区 |
| 参数名冲突 | 拿到意料外的值 | 理清优先级，命名带前缀 |
| SQL 引号嵌套错 | SQL 语法错误 | 字符串用 `'${var}'`，数字直接 `${var}` |
