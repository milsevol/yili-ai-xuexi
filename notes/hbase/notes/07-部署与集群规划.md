# 07 部署与集群规划

## 一句话

HBase 集群的规划围绕「**RegionServer 扛数据、HMaster 管分配、ZooKeeper 做协调、HDFS 存文件**」——RegionServer 跟 HDFS DataNode 混布是标准做法，ZooKeeper 必须奇数台独立部署，JVM 和 Linux 内核参数决定集群能扛多大的压力。

## 集群规模估算

先给个起点参考：

| 集群规模 | RegionServer 数 | HMaster | ZooKeeper | HDFS DataNode | 单 RS 配置 |
| --- | --- | --- | --- | --- | --- |
| 小型（< 50TB 数据） | 3–5 | 2 台 | 3 台 | 3–5（与 RS 混布） | 16–32GB 堆，8–16 核 |
| 中型（50–500TB） | 10–20 | 2 台（独立） | 5 台 | 10–20（混布） | 32–64GB 堆，16–32 核 |
| 大型（> 500TB） | 20–50+ | 2 台（独立） | 5 台 | 20–50（混布） | 64–128GB 堆，32+ 核 |

### RegionServer 内存估算

```
RegionServer 总堆
├── BlockCache  ≈ 40%（读缓存）
├── MemStore    ≈ 40%（写缓冲）
└── JVM 预留    ≈ 20%

每个 Region 的 MemStore 上限 = flush.size = 128MB
每个 CF 一个 MemStore
RegionServer 全局 MemStore 上限 = 堆 × 0.40

RS 能承载的 Region 上限 ≈ (堆 × 0.40) / (每个 Region 的 MemStore × CF 数)

例如：
  RS 堆 = 32GB
  CF 数 = 2
  每个 Region MemStore = 128MB × 2 = 256MB
  RS 全局 MemStore 上限 = 32GB × 0.40 = 12.8GB
  RS 能承载 Region 数 ≈ 12.8GB / 256MB = 50 个 Region

经验上限：1 台 RS 一般承载 100–200 个 Region，超过 200 要小心（Flush/Compaction 风暴）
```

### 数据量估算

```
HBase 原始数据量
= 实际业务数据 × (RowKey + CF 名 + Qualifier + 时间戳 + 版本) 的存储开销 × 3（HDFS 副本）

粗略估算：
  RowKey ≈ 30 字节
  CF:Qualifier ≈ 10 字节
  时间戳 ≈ 8 字节
  平均每行 10 列
  平均每列 value ≈ 50 字节
  
  单行 HFile 存储 ≈ 每行 10 列 × (30 + 10 + 8 + 50) ≈ 980 字节 ≈ 1KB
  
  1 亿行 ≈ 100GB 原始 HFile × 3 副本 ≈ 300GB HDFS 占用
```

## HMaster 部署

### HA 架构

```
┌────────────────────┐     ┌────────────────────┐
│  HMaster Active    │     │  HMaster Standby    │
│  (抢 /hbase/master) │     │  (监听 /hbase/master) │
└────────┬───────────┘     └────────────────────┘
         │ 写 hbase:meta / assign / split
         ▼
    ZooKeeper（3-5 台）
```

- **至少 2 台 HMaster**：1 Active、1 Standby。Active 挂了 Standby 自动顶。
- **HMaster 进程不扛读写**：它只做管理（Region 分配、Split 处理、元数据变更），所以**不跟 RegionServer 混布**（节省 RS 机器资源给真正扛读写的进程）。
- **HMaster 内存**：堆一般 4–8GB 足够，它不缓存业务数据。

### HMaster 端口

| 端口 | 说明 |
| --- | --- |
| 16000 | HMaster RPC（管理 API） |
| 16010 | HMaster Web UI |
| 16020 | RegionServer RPC |
| 16030 | RegionServer Web UI |

## RegionServer 部署

- **RegionServer 跟 HDFS DataNode 混布**：数据在本机 HDFS 上 → RegionServer 读 HFile 就是本地读 → 数据本地性 → 省网络。
- **RegionServer 进程不跟 HMaster 混布**：让 RS 独占机器资源。
- **同一台机器只跑 1 个 RegionServer**：一个 RS 能管 100–200 个 Region，足够了。
- **网络带宽**：RegionServer 跟 DataNode 之间没有额外大流量，但 HDFS 读 HFile 和 WAL 写 HDFS 都要网络。建议千兆起步，万兆更好。

### RegionServer 配置（hbase-site.xml）

```xml
<!-- 最核心的几个参数 -->
<property>
  <name>hbase.regionserver.handler.count</name>
  <value>200</value>  <!-- RPC handler 线程数，默认 30，大集群 100-200 -->
</property>

<property>
  <name>hbase.regionserver.ipc.server.handler.count</name>
  <value>200</value>
</property>

<!-- MemStore 全局上限：堆的 40% -->
<property>
  <name>hbase.regionserver.global.memstore.size</name>
  <value>0.40</value>
</property>

<property>
  <name>hbase.regionserver.global.memstore.lowerLimit</name>
  <value>0.38</value>
</property>

<!-- BlockCache：堆的 40% -->
<property>
  <name>hfile.block.cache.size</name>
  <value>0.40</value>
</property>

<!-- Region 最大文件大小（触发 Split 的阈值） -->
<property>
  <name>hbase.hregion.max.filesize</name>
  <value>10737418240</value>  <!-- 10GB -->
</property>

<!-- WAL 配置 -->
<property>
  <name>hbase.regionserver.wal.impl</name>
  <value>AsyncFSWAL</value>
</property>
<property>
  <name>hbase.wal.provider</name>
  <value>filesystem</value>  <!-- 共享 WAL；perregion 独立 WAL -->
</property>

<!-- 心跳与会话超时 -->
<property>
  <name>hbase.regionserver.lease.period</name>
  <value>60000</value>  <!-- 默认 60s；集群大可以调到 120s -->
</property>
```

## ZooKeeper 数量

HBase **强依赖 ZooKeeper**：

- **必须奇数台**（2F+1）：3 台容忍 1 台故障、5 台容忍 2 台故障。偶数台没用（例如 4 台要 3 台过半，跟 3 台的容错力一样）。
- **至少 3 台**；中型集群推荐 5 台；超大型可能 7 台。
- **ZooKeeper 必须独立部署**——不要和 RegionServer / HMaster / HDFS 混布到同一批机器上。ZooKeeper 的稳定性对 HBase 至关重要。

| ZooKeeper 数量 | 最大容忍故障 | 过半写 |
| --- | --- | --- |
| 3 | 1 | 2 |
| 5 | 2 | 3 |
| 7 | 3 | 4 |

### ZooKeeper 配置要点

```properties
# zoo.cfg
tickTime=2000
initLimit=10
syncLimit=5
dataDir=/data/zookeeper
dataLogDir=/data/zookeeper/log
clientPort=2181
maxClientCnxns=300

# 集群节点
server.1=zk1:2888:3888
server.2=zk2:2888:3888
server.3=zk3:2888:3888
```

## HDFS 配置配合

HBase 的 HFile 和 WAL 都存 HDFS，HDFS 的配置直接影响 HBase 性能：

### HDFS 必须启用短Circuit读取（Short-Circuit Read）

让 RegionServer 直接读 DataNode 本地磁盘（绕过 DataNode RPC），**这是 HBase 读性能的关键**：

```xml
<!-- hdfs-site.xml -->
<property>
  <name>dfs.client.read.shortcircuit</name>
  <value>true</value>
</property>
<property>
  <name>dfs.domain.socket.path</name>
  <value>/var/run/hadoop-hdfs/dn_socket</value>
</property>
<property>
  <name>dfs.blockreader.cache.enabled</name>
  <value>true</value>
</property>
```

### DataNode 磁盘

- DataNode 磁盘用 **JBOD（Just a Bunch of Disks）**，不做 RAID。坏盘靠副本恢复。
- 预留磁盘空间：`dfs.datanode.du.reserved` 留 10%–15%，别让磁盘 100% 满。
- WAL 写入对延迟敏感，如有条件可以把 WAL 的 DataNode 磁盘放到 SSD。

### 副本数与块大小

- HBase 表默认 3 副本，块大小跟 HDFS 配置一致。
- Region 级复制（2.6+）可以把 Region 热副本放到另一个 RegionServer 上，读请求优先走本地副本。

## JVM 参数

### RegionServer（最重要）

```bash
# hbase-env.sh 中设置
export HBASE_REGIONSERVER_OPTS="
  -Xms24g -Xmx24g
  -XX:+UseG1GC
  -XX:MaxGCPauseMillis=100
  -XX:G1HeapRegionSize=16m
  -XX:+ParallelRefProcEnabled
  -XX:ConcGCThreads=8
  -XX:+AlwaysPreTouch
  -XX:+UnlockExperimentalVMOptions
  -XX:+DisableExplicitGC
  -XX:+ExitOnOutOfMemoryError
  -XX:+HeapDumpOnOutOfMemoryError
  -XX:HeapDumpPath=/var/log/hbase/
"
```

### HMaster

```bash
export HBASE_MASTER_OPTS="
  -Xms6g -Xmx6g
  -XX:+UseG1GC
  -XX:MaxGCPauseMillis=200
"
```

## 部署步骤

```bash
# 1. 准备 JDK 8 或 11
java -version  # 确认版本

# 2. 下载 HBase 二进制包
wget https://archive.apache.org/dist/hbase/2.5.8/hbase-2.5.8-bin.tar.gz
tar -xzf hbase-2.5.8-bin.tar.gz
mv hbase-2.5.8 /opt/hbase

# 3. 配置 hbase-site.xml、hbase-env.sh（见上）
# 4. 配置 regionservers 文件（列出所有 RegionServer 主机）
cat > /opt/hbase/conf/regionservers << EOF
rs-node-01
rs-node-02
rs-node-03
EOF

# 5. 分发到所有节点
rsync -avz /opt/hbase/ rs-node-01:/opt/hbase/
rsync -avz /opt/hbase/ rs-node-02:/opt/hbase/

# 6. HDFS 创建 rootdir（可选，首次启动自动创建）
hdfs dfs -mkdir -p /hbase
hdfs dfs -chown hbase:hadoop /hbase

# 7. 启动
# 先启动 ZooKeeper
# 再启动 HDFS（DataNode 和 HBase RegionServer 混布）
# 最后启动 HBase
/opt/hbase/bin/start-hbase.sh

# 8. 验证
jps  # 看到 HMaster、HRegionServer
hbase shell
> status
> list
```

## 易错点清单

1. **HMaster 跟 RegionServer 混布**：HMaster 本身不吃资源，但 RS 需要独占机器资源给读写；生产分开。
2. **ZooKeeper 偶数台**：4 台和 3 台一样只能容错 1 台，但 5 台容错 2 台更安全。
3. **BlockCache + MemStore > 80% 堆**：HBase 预留 20% 给 JVM，超了会 OOM。
4. **没禁用 swap**：集群偶发性心跳超时的最大元凶。
5. **没开 Short-Circuit Read**：RegionServer 读本机 HDFS 还要走 RPC，性能差好几倍。
