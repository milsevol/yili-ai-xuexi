# 07 记忆与上下文管理

## 一句话

**上下文窗口是 Agent 最稀缺的资源**：多轮工具调用几轮就能吃掉几十万 token。记忆管理的本质是**分层**——工作记忆放对话历史（满了就压缩），长期记忆放带元数据的向量库（用时按需召回），工具结果在源头就压缩。谁管住预算，谁的 Agent 就能跑得又长又稳。

## 为什么记忆是生产分水岭

Demo 里的 Agent 只跑 3 轮，生产里的 Agent 跑 30 轮：

```text
第 1 轮   system 2K + 用户问题 0.1K                 → 2K
第 5 轮   + 4 次工具结果 × 2K                       → 10K
第 15 轮  + 14 次工具结果 + 中间推理                 → 30K（撞 32K 窗口）
第 30 轮  爆窗 / 成本爆炸 / 关键指令被淹没，忘记最初目标
```

| 后果 | 表现 | 根因 |
| --- | --- | --- |
| 爆窗报错 | `context_length_exceeded` | 历史无上限增长 |
| 成本失控 | 单任务账单翻十倍 | **每轮重发全部历史**，累计成本 ≈ O(n²) |
| 注意力稀释 | 忘约束、重复调工具 | 关键信息落在长上下文中部（Lost in the Middle） |

## 记忆分层：四种记忆

| 类型 | 存什么 | 存储介质 | 生命周期 | 读写时机 |
| --- | --- | --- | --- | --- |
| 工作记忆 | 当前对话、本轮工具结果 | 进程内 messages | 单次会话 | 每轮读写；70% 预警、90% 强制压缩 |
| 情景记忆 | 会话摘要、任务轨迹 | 文档库 / 时序库（Zep） | 数周至数月 | 会话结束写；开场按时间召回 |
| 语义记忆 | 用户偏好、实体事实 | 向量库 + metadata | 月至年（TTL） | 确认时写；每轮注入 top_k |
| 程序性记忆 | 提示词、工具 Schema、成功案例 | 代码仓库 / 提示词库 | 版本化 | 开发期写；运行时不参与压缩 |

**分层原则**：工作记忆求「短」，情景记忆求「可追溯」，语义记忆求「准」，程序性记忆求「稳」。LangGraph checkpointer 持久化工作记忆详见第 06 章。

## 先解决计量：estimate_tokens

```python
import json, os, time
from openai import OpenAI

client = OpenAI(api_key=os.getenv("DEEPSEEK_API_KEY"), base_url="https://api.deepseek.com")
MODEL = "deepseek-chat"

def _count(text: str) -> int:
    """中文 1 字 ≈ 1 token，英文 4 字符 ≈ 1 token，误差约 ±10%。"""
    cjk = sum(1 for ch in text if "\u4e00" <= ch <= "\u9fff")
    return int(cjk + (len(text) - cjk) / 4) + 1
def estimate_tokens(messages) -> int:
    if isinstance(messages, str):
        return _count(messages)
    total = 0
    for m in messages:
        total += _count(m.get("content") or "") + 8      # role/分隔符固定开销
        if m.get("tool_calls"):
            total += _count(json.dumps(m["tool_calls"], ensure_ascii=False))
    return total
def call_llm(prompt: str) -> str:
    resp = client.chat.completions.create(
        model=MODEL, temperature=0,
        messages=[{"role": "user", "content": prompt}])
    return resp.choices[0].message.content or ""
```

**校准**：每次调用后拿 `resp.usage.prompt_tokens` 与估算值比对，用比例系数修正。别用 `len(text) // 4` 拍脑袋，中文会低估 3 倍以上。

## 短期记忆：三种截断策略

### 1. 滑动窗口

```python
def truncate_messages(messages: list, max_tokens: int) -> list:
    """system 永保留，其余从最新往回装，装不下就丢最老的。"""
    system = [m for m in messages if m["role"] == "system"]
    rest = [m for m in messages if m["role"] != "system"]
    kept, total = [], 0
    for m in reversed(rest):
        t = estimate_tokens([m])
        if total + t > max_tokens:
            break
        kept.insert(0, m)
        total += t
    return system + kept
```

零成本，但可能丢掉用户开头说的硬约束（目标漂移的根源）。

### 2. 摘要压缩

老消息交给 LLM 压成一段摘要替换原文：信息保留好，但多一次调用、质量依赖模型——工程化实现见「摘要压缩工程化」。

### 3. Token 感知截断（生产推荐）

| 消息类型 | 策略 |
| --- | --- |
| System prompt | 永远保留 |
| 用户最初目标与硬约束 | 永远保留（防目标漂移） |
| 最近 N 轮 | 完整保留 |
| 更早的轮次 | 摘要化，原始消息丢弃 |
| 历史工具结果 | 降级为一行 `[已压缩] 结论` |
| 本轮工具结果 | 压缩后立即使用，用完即降级 |

## 走一遍真实的多轮对话：messages 是怎么长起来的

场景：分析某上市公司基本面。窗口 32K、输出预留 4K，可用 28K；70% 预警线 19.6K，90% 强压线 25.2K。system + 工具 Schema 固定 2.6K，长期记忆注入 0.6K。

| 轮次 | 用户意图 / 工具 | 新增 | 累计 | 动作 |
| --- | --- | --- | --- | --- |
| 1 | 查最新股价 | 1.8K | 4.4K | ok |
| 2 | 查近三年营收 | 3.1K | 7.5K | ok |
| 3 | 查毛利率对比 | 3.9K | 11.4K | ok |
| 4 | 拉年报 PDF | 2.4K | 13.8K | 外部化，只回引用 |
| 5 | 算 CAGR | 1.6K | 15.4K | ok |
| 6 | 查行业政策 | 4.0K | 19.4K | ok（临界） |
| 7 | 查竞对 | 5.6K | 25.0K | warn |
| 8 | 写初稿大纲 | 3.2K | 28.2K | **hard → 压缩到 10.8K** |
| 9 | 补估值 | 3.5K | 14.3K | ok |
| 10 | 反驳观点 | 2.2K | 16.5K | ok |
| 11 | 查最新公告 | 4.1K | 20.6K | warn |
| 12 | 修订结论 | 2.4K | 23.0K | ok |
| 13 | 生成图表数据 | 2.9K | 25.9K | **hard → 压缩到 12.8K** |
| 14 | 输出成稿 | 2.6K | 15.4K | ok，结束 |

压缩前后 messages 的真实结构：

```text
压缩前（第 8 轮调用前，34 条消息，25.6K）
├─ system + 记忆注入                3.2K  ← 永远不动
├─ 第 1-7 轮 31 条消息              22.2K ← 9 条工具原文占 14.8K
└─ 第 8 轮 user 消息                 0.2K

压缩后（12 条消息，7.8K）
system 2.6K + 摘要 0.5K + 最近 6 条 3.3K + 工具降级 0.7K + 新记忆 0.5K + 本轮 0.2K
```

**关键点**：压缩发生在「调用之前」；用户目标、硬约束、关键数字永远不进摘要的黑洞。

## 预算控制：ContextBudget

```python
class ContextBudget:
    """70% 预警（异步压缩），90% 强制（同步压缩 + 兜底）。"""
    def __init__(self, window=32_000, reserve_output=4_000, warn=0.70, hard=0.90):
        self.usable = window - reserve_output
        self.warn_at, self.hard_at = int(self.usable * warn), int(self.usable * hard)

    def act(self, messages, tools=None) -> dict:
        n = estimate_tokens(messages) + (
            _count(json.dumps(tools, ensure_ascii=False)) if tools else 0)
        lv = "hard" if n >= self.hard_at else ("warn" if n >= self.warn_at else "ok")
        return {"used": n, "level": lv, "headroom": self.usable - n,
                "action": {"ok": "proceed", "warn": "compress_async",
                           "hard": "compress_now"}[lv]}

budget = ContextBudget(window=32_000)
if budget.act(messages)["action"] == "compress_now":
    messages = compress_history(messages)      # 见下节工程化实现
```

70% 只是预警：后台异步压缩，不阻塞当前请求；90% 是红线：同步压缩，摘要失败则退化为滑动窗口，绝不允许把超限请求发出去。

## 上下文预算分配与速查表

| 区块 | 预算占比 | 说明 |
| --- | --- | --- |
| System prompt + 工具 Schema | 5-10% | 工具别超过 20 个，Schema 很吃 token |
| 长期记忆注入 | 5-10% | top_k 控制在 3-5 条 |
| 对话历史（含摘要） | 30-40% | 超阈值触发压缩 |
| 工具结果 | 30-40% | **最大消耗源**，重点压缩 |
| 输出预留 | 10-20% | 别让最终答案被截断 |

| 窗口 | 可用预算 | 70% 预警 | 90% 强压 | 历史上限 | 单次工具结果上限 |
| --- | --- | --- | --- | --- | --- |
| 32K | 28K | 19.6K | 25.2K | 10K | 1.5K |
| 128K | 112K | 78.4K | 100.8K | 45K | 3K |
| 1M | 900K | 630K | 810K | 200K | 5K |

**1M 长窗口为什么仍要管理**：① 成本线性计费，塞满 1M 的单次调用可达几十美元；② 延迟随输入长度上升；③ 长上下文中部信息利用率下降（Lost in the Middle）；④ 无关内容稀释指令，工具调用错误率上升。窗口是天花板，不是目标。

## 摘要压缩工程化

保护清单：system、用户原始目标、最近 N 轮不参与摘要；摘要内强制保留数字与硬约束，再做质量校验。

```python
import re
NUM_RE = re.compile(r"\d+(?:\.\d+)?%?")

SUMMARY_PROMPT = """把历史对话压成 {max_chars} 字内的摘要。必须保留：①用户最初目标与全部硬约束；
②所有关键数字、日期、来源；③已做决策与已排除方案；④未完成待办。
丢弃工具原始返回、寒暄与失败重试，不要推测。
按「目标/约束、关键事实、决策、待办」四段输出。
历史对话：
{history}"""
def protected_numbers(messages: list, recent: int = 6) -> list[str]:
    picked = ([m for m in messages[1:] if m["role"] == "user"][:2]
              + [m for m in messages[-recent:] if m["role"] in ("user", "assistant")])
    return sorted({n for m in picked for n in NUM_RE.findall(m.get("content") or "")})
def compress_history(messages: list, keep_recent: int = 8, max_chars: int = 600) -> list:
    system, convo = messages[0], messages[1:]
    if len(convo) <= keep_recent:
        return messages
    old, recent = convo[:-keep_recent], convo[-keep_recent:]
    history = "\n".join(f"{m['role']}: {(m.get('content') or '')[:800]}" for m in old)
    required, missing = protected_numbers(messages), []
    for attempt in range(2):                       # 失败重试一次，仍失败则截断兜底
        summary = call_llm(SUMMARY_PROMPT.format(max_chars=max_chars, history=history)
                           + ("" if attempt == 0 else f"\n必须出现：{missing}"))
        missing = [n for n in required if n not in summary]
        if len(summary) >= 120 and not missing:
            return [system, {"role": "system", "content": f"【前情摘要】\n{summary}"}, *recent]
    return truncate_messages(messages, max_tokens=estimate_tokens(recent) + 500)
```

质量校验三个硬指标：**数字命中率 100%**、**摘要长度下限**（防敷衍）、**来源可追溯**（保留「据 XX 财报」）。校验失败宁可退化截断，也不静默丢事实。

## 长期记忆：带元数据的向量记忆

```python
import hashlib
from dataclasses import dataclass
from datetime import datetime, timedelta

@dataclass
class MemoryItem:
    id: str; text: str; embedding: list[float]; source: str
    tenant: str; created_at: datetime; key: str
    confidence: float = 0.8; ttl_days: int = 180; superseded_by: str | None = None
def embed(text: str) -> list[float]:
    """DeepSeek 无 embedding 接口，向量化走独立服务。"""
    return OpenAI(api_key=os.getenv("EMBEDDING_API_KEY")).embeddings.create(
        model="text-embedding-3-small", input=text).data[0].embedding
def cosine(a: list[float], b: list[float]) -> float:
    return sum(x * y for x, y in zip(a, b)) / (
        (sum(x * x for x in a) ** 0.5) * (sum(y * y for y in b) ** 0.5) + 1e-9)
class VectorMemory:
    def __init__(self, tenant: str, min_confidence: float = 0.6):
        self.tenant, self.min_confidence = tenant, min_confidence
        self.items: dict[str, MemoryItem] = {}       # 生产换 Qdrant / pgvector

    def _fresh(self, item: MemoryItem, now: datetime) -> bool:
        return (item.tenant == self.tenant and item.superseded_by is None
                and now - item.created_at <= timedelta(days=item.ttl_days)
                and item.confidence >= self.min_confidence)

    def remember(self, text, source, key=None, confidence=0.8, ttl_days=180) -> str:
        now = datetime.now()
        key = key or f"free:{hashlib.md5(text.encode()).hexdigest()[:8]}"
        vec = embed(text)
        for item in self.items.values():             # 近重复 → 刷新，不新增
            if (item.tenant == self.tenant and item.superseded_by is None
                    and cosine(vec, item.embedding) > 0.95):
                item.confidence, item.created_at = max(item.confidence, confidence), now
                return item.id
        new_id = f"mem_{len(self.items) + 1}"
        for item in self.items.values():             # 同 key 冲突 → 旧值标记取代
            if (item.tenant == self.tenant and item.key == key
                    and item.superseded_by is None):
                item.superseded_by = new_id
        self.items[new_id] = MemoryItem(new_id, text, vec, source,
                                        self.tenant, now, key, confidence, ttl_days)
        return new_id
    def recall(self, query: str, top_k: int = 3) -> list[MemoryItem]:
        now, q = datetime.now(), embed(query)

        def score(it: MemoryItem) -> float:
            recency = 0.5 ** ((now - it.created_at).days / 90)    # 90 天半衰
            return cosine(it.embedding, q) * it.confidence * (0.7 + 0.3 * recency)

        cands = [it for it in self.items.values() if self._fresh(it, now)]
        return sorted(cands, key=score, reverse=True)[:top_k]
memory = VectorMemory("fund_001")
memory.remember("用户偏好低波动策略，回撤容忍度 8%", source="session:42",
                key="user:risk_preference", confidence=0.9)
```

召回结果按 `- {text}（来源 {source}，置信 {confidence}）` 拼进 system，top_k 不超过 5。召回过滤顺序：**租户 → 未过期 → 未失效 → 置信度阈值 → 相似度 × 置信度 × 时间衰减**。冲突不物理删除，写 `superseded_by` 链，既保留审计，也避免「旧事实复活」。

**存什么**：用户画像、跨会话项目上下文、确认过的事实。**不存什么**：一次性中间过程、凭据、可实时查询的行情。知识图谱记忆（实体 + 关系）适合关系密集场景，可参考 Zep / Mem0。

## 记忆写入策略

| 策略 | 触发时机 | 延迟 | 风险 | 适用 |
| --- | --- | --- | --- | --- |
| 实时写入 | 每轮结束提取事实 | 高（多一次 LLM 调用） | 噪音多、断言未验证 | 强交互、事实确认即生效 |
| 会话结束写入 | 整段会话总结后批量入库 | 中 | 会话中断则丢失 | 大多数生产场景 |
| 显式指令 | 用户说「记住……」 | 低 | 依赖用户主动 | 偏好、长期约束 |
| 离线批处理 | 每日跑历史会话 | 最低 | 时效差 | 画像、统计类记忆 |

**去重与更新**：写入前做近重复检测（余弦 > 0.95 视为同一条，刷新置信度与时间）；同一 `key` 的新值走「标记取代」而非覆盖；未验证的推断置信度压到 0.5 以下，不参与召回。

## 记忆安全

| 风险 | 攻击面 / 成因 | 对策 |
| --- | --- | --- |
| 记忆投毒 | 网页、邮件、工具返回里的恶意指令被写入记忆，污染后续会话 | 工具内容标记 `untrusted`，默认不写长期记忆；写入前审核；按 source 分级信任 |
| 隐私泄露 | 记忆里存了手机号、身份证、持仓明细 | 写入前 PII 脱敏；TTL 到期删除；提供删除接口与租户隔离 |
| 越权召回 | 召回查询漏了 tenant 过滤 | 召回层强制拼 tenant 条件；跨租户测试用例回归 |
| 过期数据 | 用户偏好已变化，旧记忆仍在注入 | TTL + 时间衰减 + 取代链；关键事实定期回问确认 |

**底线**：记忆是「可被外部内容间接写入的持久化状态」，必须按不可信输入对待——写入要审、读取要滤、过期要删。

## 工具结果压缩：四层防御

一次网页抓取可能上万 token，四层缺一不可。

```python
def trim_tool_output(raw: str, max_items: int = 5, max_chars: int = 1200) -> str:
    """① 源头裁剪：只留结构化字段 + 截断。"""
    try:
        items = [{"title": x.get("title", ""), "snippet": x.get("snippet", "")[:200]}
                 for x in json.loads(raw)[:max_items]]
        return json.dumps(items, ensure_ascii=False)[:max_chars]
    except (ValueError, TypeError, AttributeError):
        return raw[:max_chars]
def externalize(raw: str, name: str) -> str:
    """② 外部化：大结果落盘，上下文只放引用。"""
    path = f"/tmp/agent_artifacts/{name}_{int(time.time())}.txt"
    os.makedirs(os.path.dirname(path), exist_ok=True)
    with open(path, "w", encoding="utf-8") as f:
        f.write(raw)
    return json.dumps({"saved_to": path, "chars": len(raw), "preview": raw[:300],
                       "hint": "用 read_file_slice 按需读取"}, ensure_ascii=False)
def extract_relevant(goal: str, raw: str, max_chars: int = 800) -> str:
    """③ 回灌前提取：只保留与当前目标相关的事实。"""
    resp = client.chat.completions.create(model=MODEL, temperature=0, messages=[
        {"role": "system", "content": "只输出与目标相关的事实，保留数字与来源，"
                                      "不超过 300 字；无关输出「无关」。"},
        {"role": "user", "content": f"目标：{goal}\n\n材料：\n{raw[:20000]}"}])
    return (resp.choices[0].message.content or "")[:max_chars]
def degrade_old_tool_messages(messages: list, keep: int = 3) -> list:
    """④ 历史降级：旧工具消息只留一行摘要，仅在压缩点执行一次。"""
    idx = [i for i, m in enumerate(messages) if m["role"] == "tool"]
    old = set(idx[:-keep]) if keep else set(idx)
    return [{**m, "content": f"[已压缩] {extract_relevant('保留结论与数字', m.get('content') or '', 80)}"}
            if i in old and not (m.get("content") or "").startswith("[已压缩]") else m
            for i, m in enumerate(messages)]
def absorb_tool_result(goal: str, tool_name: str, raw: str) -> str:
    """统一入口：超大外部化，其余裁剪后提取。"""
    if len(raw) > 8000:
        return externalize(raw, tool_name)
    trimmed = trim_tool_output(raw) if raw.lstrip().startswith(("[", "{")) else raw[:1200]
    return extract_relevant(goal, trimmed)
```

①让工具少返回，②让大结果不占上下文，③让回灌内容只留相关部分，④让历史旧结果随时间降级。①+② 通常能消掉 80% token，③④ 兜住长尾。

## 常见问题

**Q：摘要会不会丢关键信息导致答错？**
A：会，这是根本风险。缓解：① prompt 强制保留数字、日期、约束；② 校验命不中数字就重试或退化为截断；③ 关键事实同时写入结构化长期记忆；④ 高风险场景只压工具结果、保对话原文。

**Q：长期记忆会不会把错误信息记住，越用越错？**
A：会。每条记忆必须带来源、时间戳、置信度、租户；召回过滤过期与低置信；同 key 冲突用取代链而非追加，避免新旧事实同时被注入。

**Q：怎么防记忆投毒？**
A：把外部内容当不可信输入：默认不写长期记忆、写入前审核、按来源分级信任、只注入高置信条目；敏感操作前重新向用户确认，而不是信任记忆里的指令。
