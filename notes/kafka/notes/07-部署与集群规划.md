# 07 部署与集群规划

## 一句话

集群规划要先算**数据量 → Partition 数 → Broker 数**，再考虑磁盘、网络、JVM、OS 内核参数。KRaft 模式下，Controller Quorum 可以和 Broker 合并部署（小集群）或独立部署（大集群）。

## 规划四步

### 第一步：数据量 → 分区数

```
每日消息量 = QPS × 86400 × 单条消息平均字节数
每日磁盘占用 = 每日消息量 × replication.factor
历史保留总磁盘 = 每日磁盘占用 × 保留天数

单 Broker 可用磁盘（按 JBOD 多盘）
  = 盘数 × 单盘容量 × (1 - OS + Kafka 预留 10%)

Broker 数 = 历史保留总磁盘 / 单 Broker 可用磁盘
```

### 第二步：分区数

```
Partition 数 = max(
  并发 Consumer 数,          ← Consumer Group 最多要多少并行度
  总写入 QPS / 单 Partition 目标 QPS,
  总读取 QPS / 单 Partition 目标 QPS
)
```

**经验值**：单 Partition 写入 ~10-50 MB/s（磁盘顺序写），单 Partition 读可更高。

### 第三步：Broker 数 vs 分区数预算

| Broker 数 | 建议单 Broker Partition 上限 | 适用场景 |
| --- | --- | --- |
| 3-5 | ~100-500 | 中小规模 |
| 6-10 | ~500-1500 | 中等规模 |
| 10+ | ~1500-3000 | 大规模 |

**⚠️ Broker 上总 Partition 数过多** → Controller 压力大、ISR 同步风暴、元数据广播延迟。

### 第四步：Controller 数量（KRaft）

| 规模 | Controller 部署 |
| --- | --- |
| < 10 Broker | 和 Broker 合并部署（3 个进程：broker + controller） |
| 10-50 Broker | 独立 3 个 Controller（Raft 选主），Broker 纯 Broker 角色 |
| 50+ Broker | 独立 5 个 Controller，Metadata 分片 |

**Raft 选主需要奇数节点**（3 → 允许 1 个挂；5 → 允许 2 个挂）。不要偶数。

## KRaft 最小部署模板

### 合并部署（Broker + Controller 在同一进程，推荐 < 10 Broker）

每个节点的 `server.properties`：

```properties
# 三个节点分别是 node.id=1/2/3
broker.id=1
node.id=1
process.roles=broker,controller

controller.quorum.voters=1@kafka1:9093,2@kafka2:9093,3@kafka3:9093

listeners=PLAINTEXT://:9092,CONTROLLER://:9093
advertised.listeners=PLAINTEXT://kafka1:9092

# 必须唯一的 log 目录（Broker 数据 + Controller Metadata Log）
log.dirs=/data/kafka-logs
```

### 独立 Controller（推荐 ≥ 10 Broker）

Controller 节点：
```properties
process.roles=controller
node.id=1
controller.quorum.voters=1@ctrl1:9093,2@ctrl2:9093,3@ctrl3:9093
listeners=CONTROLLER://:9093
log.dirs=/data/kafka-logs-controller
```

Broker 节点：
```properties
process.roles=broker
node.id=4                   # 和 Controller 的 node.id 不重复
controller.quorum.voters=1@ctrl1:9093,2@ctrl2:9093,3@ctrl3:9093
listeners=PLAINTEXT://:9092
advertised.listeners=PLAINTEXT://broker1:9092
log.dirs=/data/kafka-logs
```

## JVM 参数

```bash
# JDK 17 或 21（Kafka 3.7+ 推荐）
# 堆内存：建议 8-16GB（太大 GC 停顿长，太小 OOM）
export JAVA_OPTS="-Xms12g -Xmx12g \
  -XX:+UseG1GC \
  -XX:MaxGCPauseMillis=200 \
  -XX:+ParallelRefProcEnabled \
  -XX:InitiatingHeapOccupancyPercent=45 \
  -Djdk.tls.ephemeralDHKeySize=2048 \
  -Dlog4j.configuration=file:log4j.properties"
```

**G1GC 要点**：
- `MaxGCPauseMillis=200`：把 GC 停顿压到 200ms 以内，避免 Consumer 心跳超时触发 Rebalance。
- Kafka 3.x 默认用 G1GC。老版本（2.x）可能推荐 CMS，现已 deprecated。
- 堆内存不是越大越好：16GB G1 停顿一般，32GB 会变长，64GB 建议分多 Broker。

## Linux 内核调优

```bash
# /etc/sysctl.conf

# 网络
net.core.somaxconn=32768                    # listen backlog
net.core.netdev_max_backlog=32768           # 网络设备队列
net.ipv4.tcp_max_syn_backlog=32768
net.ipv4.tcp_tw_reuse=1                     # TIME_WAIT 复用，高并发必需

# 内存
vm.swappiness=1                             # 禁用 swap（Kafka 用 PageCache，不要换出去）
vm.max_map_count=262144                     # RocksDB 需要（Streams 状态存储）
vm.dirty_ratio=80                           # PageCache 脏页写回阈值（Broker 可以高一点）
vm.dirty_background_ratio=5

# 文件句柄
fs.file-max=1000000
```

```bash
# /etc/security/limits.conf
*      soft    nofile     65536
*      hard    nofile     65536
*      soft    memlock    unlimited
*      hard    memlock    unlimited
```

## 磁盘选择

| 类型 | 顺序写吞吐 | 随机写 | 价格 | 推荐 |
| --- | --- | --- | --- | --- |
| HDD（7.2K） | ~150-200 MB/s | 差 | 低 | 冷数据、历史保留 |
| SATA SSD | ~500 MB/s | 好 | 中 | 主流，推荐 |
| NVMe SSD | ~1-3 GB/s | 极好 | 高 | 高吞吐热数据 |

**Kafka 磁盘最佳实践**：
- JBOD 多盘，**不做 RAID**（坏盘靠副本恢复，JBOD 吞吐最大化）
- 每盘预留空间：`log.retention.bytes` 不要打满，留 10-20%
- 多盘时 `log.dirs=/data1,/data2,/data3`，Broker 自动均衡 Partition
- 用 `df` 而不是 `du` 监控磁盘（du 要遍历文件）

## 网络带宽计算

```
网卡带宽 = Producer 写入带宽 + Consumer 读取带宽 + ISR 同步带宽

Producer 写入 = 每日消息量 / 86400 （MB/s）
Consumer 读取 = Producer 写入 × Consumer Group 数（多个 Group 独立读）
ISR 同步 = Producer 写入 × (replication.factor - 1)（Follower 从 Leader 拉）

单 Broker 网卡 = 上三项之和 ÷ Broker 数
```

**经验**：25Gbps NIC 足够多数场景，100Gbps 只有 TB 级 QPS 才需要。

## 启动 KRaft 集群

```bash
# 1. 格式化集群 ID（只需做一次）
kafka-storage.sh random-uuid        # 比如：abc123def456
kafka-storage.sh format -t abc123def456 -c server.properties

# 2. 每个节点启动
kafka-server-start.sh -daemon server.properties

# 3. 验证
kafka-metadata-quorum.sh --bootstrap-server kafka1:9093 describe --status

# 4. 创建主题（Broker 端口 9092）
kafka-topics.sh --bootstrap-server kafka1:9092 --create \
  --topic demo --partitions 6 --replication-factor 3
```
