# 06 高级特性

## 一句话

Kafka 不只是消息队列：**Streams API** 把它变成有状态流处理引擎，**Connect API** 把它变成数据同步总线，**Exactly-Once 事务**让跨 Partition 写入原子化，**动态分区分配**让扩容不停服。

## Streams API 简介

Kafka Streams 是**一个 JVM 客户端库**（不单独起服务），让你在 Producer/Consumer 代码里直接做流处理：

```java
StreamsBuilder builder = new StreamsBuilder();
KStream<String, String> source = builder.stream("input-topic");
source
    .filter((k, v) -> v.startsWith("error:"))
    .groupByKey()
    .count()                       // 有状态聚合：按 key 统计
    .toStream()
    .to("count-output-topic");

KafkaStreams streams = new KafkaStreams(builder.build(), props);
streams.start();
```

### Streams 核心概念

| 概念 | 含义 |
| --- | --- |
| **拓扑（Topology）** | Processor DAG：Source → Processor → Sink 的有向无环图 |
| **有状态算子** | count、reduce、aggregate、windowed join —— 需要状态存储 |
| **状态存储（State Store）** | 本地 RocksDB（默认）+ 远端 Kafka 主题（changlog 备份） |
| **窗口（Window）** | Hopping（滑动）、Tumbling（滚动）、Session（会话） |
| **时间语义** | Event Time（推荐，Watermark 处理乱序）、Processing Time |
| **Exactly-Once** | 可开启 `processing.guarantee=exactly_once_v2` |

### Streams vs Flink vs Spark Structured Streaming

| 维度 | Kafka Streams | Flink | Spark Structured Streaming |
| --- | --- | --- | --- |
| 部署方式 | 嵌入 Producer/Consumer JVM | 独立 Flink 集群 | Spark on YARN/K8s |
| 状态存储 | RocksDB（本地）+ Kafka changelog | Managed Memory + RocksDB | 内存 + 外部 checkpoint |
| 流处理能力 | 中等（窗口/聚合/Join） | 强（CEP/SQL/Golang UDF） | 强（SQL/批流统一） |
| 运维成本 | 低（无额外集群） | 中 | 高（Spark 集群） |
| 适用场景 | 轻量级流处理（埋点/风控规则） | 重流处理、复杂计算 | 批流一体、数仓 |

## Connect API 简介

Kafka Connect 是一个**独立运行的服务**，专门做外部系统 ↔ Kafka 的数据同步：

```
外部系统 ←→ Kafka Connect ←→ Kafka
           ├─ Source Connector: 外部系统 → Kafka
           └─ Sink Connector:  Kafka → 外部系统
```

### 常用 Connector

| Connector | 类型 | 用途 |
| --- | --- | --- |
| **Debezium** | Source | MySQL/PostgreSQL/Oracle binlog CDC |
| **MongoDB Kafka Connector** | Source/Sink | MongoDB ↔ Kafka |
| **JDBC Source/Sink** | Source/Sink | 通用关系库同步 |
| **Elasticsearch Connector** | Sink | Kafka → ES 建索引 |
| **S3 Connector** | Sink | Kafka → S3/HDFS（分区文件） |
| **File Connector** | Source/Sink | 文件 ↔ Kafka（测试/简单场景） |

### Connect 架构

```
Worker 进程（3+ 个，分布式）
  ├─ 每个 Worker 可以跑多个 Connector 实例
  ├─ Connector 拆成 Task（并行度 = 分区数 / 配置）
  └─ 分布式协调靠 Kafka 内部主题（config / offsets / status）
```

## Exactly-Once 事务

### Producer 端事务

```java
// 1. 初始化：申请 PID + 持久化 transactional.id
producer.initTransactions();

// 2. 开启事务
producer.beginTransaction();

// 3. 业务逻辑：写多个 Topic
try {
    producer.send(new ProducerRecord<>("order", order));
    producer.send(new ProducerRecord<>("inventory", inventory));
    producer.commitTransaction();   // 原子提交
} catch (Exception e) {
    producer.abortTransaction();     // 回滚
}
```

### Consumer 端配合

```java
props.put("isolation.level", "read_committed"); // 只读已提交事务
props.put("enable.auto.commit", "false");
// Consumer 处理完 → 写 DB → commitSync() → 完成
```

### EOS v2（Kafka 3.0+）

老版本 EOS 需要 Consumer + Producer 在同一个事务里（事务里不能有外部系统交互）。**EOS v2** 把 Producer 事务和 Consumer 偏移提交解耦：Producer 端事务写 Kafka 保证 Atomic，Consumer 端手动 commit offset，外部系统需要幂等。

## 动态分区分配与重分配

Kafka 支持在线调整分区、跨 Broker 重新分配 Partition：

```bash
# 加分区（只能增不能减）
kafka-topics.sh --bootstrap-server kafka1:9092 \
  --alter --topic demo --partitions 6

# 跨 Broker 重分配（比如扩容新 Broker）
kafka-reassign-partitions.sh --bootstrap-server kafka1:9092 \
  --generate --topics-to-move-json-file topics.json \
  --broker-list 4,5,6
```

重分配流程（Controller 内部）：
1. Controller 选新 Broker → 给目标 Partition 新增一个 Replica（OSR）
2. 新 Replica 从 Leader 同步日志（跟普通 Follower 一样 Fetch）
3. 同步完后把新 Replica 加进 ISR
4. ISR 投票选新 Leader → 完成切换
5. 老 Replica 被移除

**注意**：重分配期间新 Replica 在 OSR 里，会参与 ack=all 吗？不会——只有 ISR 里的副本才算。

## 压缩详解

| 配置 | 值 | 含义 |
| --- | --- | --- |
| Producer `compression.type` | lz4 / zstd / snappy / gzip / none | Producer 端压缩 |
| Broker `compression.type` | producer / `lz4` / `uncompressed` | 默认沿用 Producer；设成 `lz4` 强制 Broker 重压缩 |
| Producer `compression.level` | -1..9（gzip） | 压缩等级，越高越慢但率好 |

**Broker 端重压缩场景**：
- 多个 Producer 用不同压缩 → Broker 统一重压缩，减少存储
- 老 Producer 用 none → Broker 可以强制压缩节省磁盘

## 关键配置

| 特性 | 关键配置 | 默认 |
| --- | --- | --- |
| Streams EOS | `processing.guarantee` | at_least_once（3.0+） |
| Streams 状态 | `state.dir` + `rocksdb.config.setter` | /tmp/kafka-streams |
| Connect Worker | `connect.distributed.config` | 3+ Worker |
| 事务超时 | `transaction.timeout.ms` | 60000（Producer）；900000（Broker） |
| 动态配置 | `config.providers` | file（可扩展 JNDI / Kubernetes） |
