# 03 数据模型与存储格式

## 一句话

Hive 用 **表（Table）** 管理文件，内部表和外部表的区别是「DROP 时删不删数据」；**分区（Partition）** 是目录级切分，**分桶（Bucket）** 是文件级切分；存储格式选 **ORC**（ACID）还是 **Parquet**（通用列式）是高频决策。

## 内部表 vs 外部表

| 维度 | 内部表（MANAGED） | 外部表（EXTERNAL） |
| --- | --- | --- |
| 默认位置 | `/user/hive/warehouse/db.db/table/` | 自己指定 `LOCATION '/path/to/data'` |
| **DROP 表行为** | **删元数据 + 删 HDFS 数据目录** | **只删元数据，数据目录不动** |
| 数据所有权 | Hive 管理 | 外部管理（比如 Flink/Spark 写的、CDC 落的） |
| LOAD DATA | 数据**移动**到 warehouse | 数据**复制**或**引用**原位置 |
| 典型场景 | Hive 创建的临时表、结果表 | 原始 ODS 层、Flink CDC 落的、多引擎共享 |

```sql
-- 内部表
CREATE TABLE t_managed (id INT, name STRING)
ROW FORMAT DELIMITED FIELDS TERMINATED BY ','
STORED AS TEXTFILE;
-- DROP TABLE t_managed; → /user/hive/warehouse/default.db/t_managed/ 整个目录删掉

-- 外部表
CREATE EXTERNAL TABLE t_external (id INT, name STRING)
ROW FORMAT DELIMITED FIELDS TERMINATED BY ','
STORED AS TEXTFILE
LOCATION '/data/raw/external';
-- DROP TABLE t_external; → Hive Metastore 删掉 t_external，但 /data/raw/external 还在
```

**记住**：外部表 DROP 不动数据是最关键的行为差异。ODS 原始层几乎都是外部表，因为数据由 Flink/DataX 写入，Hive 只是读。

## 分区（Partition）

分区是**目录级切分**，每个分区对应一个子目录。最常见的分区键是日期（dt / ds）。

```
/user/hive/warehouse/orders.db/
  └── t_order/
      ├── dt=2026-11-01/
      │   └── part-00000.orc
      ├── dt=2026-11-02/
      │   └── part-00000.orc
      └── ...
```

```sql
CREATE TABLE t_order (id BIGINT, user_id BIGINT, amount DECIMAL(10,2))
PARTITIONED BY (dt STRING)
STORED AS ORC;

-- 静态分区：写死 dt 值
INSERT OVERWRITE TABLE t_order PARTITION (dt='2026-11-01')
SELECT id, user_id, amount FROM raw_order WHERE dt='2026-11-01';

-- 动态分区：自动把最后一列当分区值
SET hive.exec.dynamic.partition=true;
SET hive.exec.dynamic.partition.mode=nonstrict;
INSERT OVERWRITE TABLE t_order PARTITION (dt)
SELECT id, user_id, amount, dt FROM raw_order;
```

**分区裁剪（Partition Pruning）**：查询时只扫描匹配分区，跳过其他目录。

```sql
-- 只扫 dt=2026-11-01 的目录，其他分区不读
SELECT SUM(amount) FROM t_order WHERE dt='2026-11-01';
```

## 分桶（Bucket）

分桶是**文件级切分**，同一个分区内的数据按 `CLUSTERED BY` 的列 hash 到固定数量的文件。

```sql
CREATE TABLE t_order_bucketed (id BIGINT, user_id BIGINT, amount DECIMAL(10,2))
PARTITIONED BY (dt STRING)
CLUSTERED BY (user_id) INTO 16 BUCKETS
STORED AS ORC;
```

```
dt=2026-11-01/
  ├── part-00000.orc   ← user_id hash % 16 == 0 的记录
  ├── part-00001.orc   ← user_id hash % 16 == 1 的记录
  └── ...
  └── part-00015.orc   ← user_id hash % 16 == 15 的记录
```

分桶的作用：

| 场景 | 为什么用分桶 |
| --- | --- |
| **同桶 JOIN** | 两张表按同一列同一桶数分桶，JOIN 时数据天然对齐，可做 **Bucket MapJoin**（无 Shuffle） |
| **采样** | `TABLESAMPLE(BUCKET 3 OUT OF 16 ON user_id)` 直接读第 3 桶，快速抽样 |
| **ACID Upsert** | Bucket + 事务表 = 真正的 upsert（同一 bucket 内文件可合并） |

## 分区 vs 分桶：到底用哪个

| 维度 | 分区 Partition | 分桶 Bucket |
| --- | --- | --- |
| 粒度 | 目录级 | 文件级 |
| 数量 | 通常几十~几百（按天/按小时） | 固定数量（8/16/32/64） |
| 裁剪 | WHERE dt='...' 跳过目录 | 无裁剪，但 JOIN/SAMPLE 可利用 |
| 典型键 | dt / ds（时间） | user_id / order_id（高频 JOIN 键） |
| 注意 | 分区过多会拖慢 Metastore | 桶数要一致才能同桶 JOIN |

**实战口诀**：时间维度 → 分区；高频 JOIN 键 → 分桶；两个都要 → 分区 + 分桶组合。

## 存储格式对比

| 格式 | 类型 | 压缩 | ACID 支持 | 适用场景 |
| --- | --- | --- | --- | --- |
| **TextFile** | 行存，按行分隔 | 行级 gzip/lzo/snappy | ❌ | 最简单、调试方便、小数据量 |
| **ORC** | 列存，带索引 | ZLIB/SNAPPY/ZSTD，列级压缩 | ✅（Hive ACID 唯一支持） | **Hive 首选**，数仓标准格式 |
| **Parquet** | 列存，Spark 默认 | SNAPPY/GZIP/ZSTD | ❌ | Spark SQL、Iceberg/Delta 通用 |
| **Avro** | 行存，带 Schema 定义 | SNAPPY/DEFLATE | ❌ | Schema 演进友好、跨语言数据交换 |

### ORC 的优势

```
ORC 文件内部结构:
  [Stripe 0]
    [Row Group 0] → Column 0 → Column 1 → ...  ← 列式存储，只读需要的列
    [Row Group 1] → Column 0 → Column 1 → ...
    [Index + Bloom Filter 每列]                   ← 跳过不满足条件的 Row Group
  [Stripe 1]
  ...
  [File Footer + Statistics]                       ← 整个文件的 min/max/sum/count
```

- 列存：查 `SELECT name FROM t WHERE id=5` 只读 name 列，IO 减少 90%
- Bloom Filter：`WHERE id=123456` 可以跳过整个 Stripe（如果 Bloom Filter 说没有）
- 列统计：File Footer 存每个 Stripe 的 min/max/sum，WHERE 条件直接跳过

### ORC vs Parquet 怎么选

| 场景 | 推荐 | 理由 |
| --- | --- | --- |
| 纯 Hive 数仓、需要 ACID | **ORC** | Hive ACID 唯一支持、Bloom Filter 和统计更完善 |
| Spark 主引擎 | **Parquet** | Spark 默认格式、Catalyst 优化路径更优 |
| 多引擎共享（Trino + Spark + Flink） | **Parquet** | 通用格式，Iceberg/Hudi/Delta 的默认物理格式 |
| 历史 Hive 3.x 存量 | **ORC** | 迁移成本低，Hive 调优参数已成熟 |

### 压缩算法选择

| 算法 | 压缩比 | 解压速度 | 是否可切分 | 推荐场景 |
| --- | --- | --- | --- | --- |
| **SNAPPY** | 中 | 快 | ✅（ORC/Parquet 自动处理） | 默认推荐，读多写多的常规场景 |
| **ZSTD** | 高 | 中 | ✅ | 冷数据 / 存储紧张，写入慢一点换空间 |
| **GZIP** | 很高 | 慢 | ❌（TextFile 不可切分） | 历史归档、几乎不再读 |

## 常见问题

**Q：分区数太多会有什么问题？**
A：每个分区在 Metastore 里是一条记录。几千分区还好，几万分区 HMS 查询明显变慢，几十万分区可能 OOM。建议单表分区数 ≤ 10 万。可以用二级分区（如 `dt + hour`）减少分区数。

**Q：动态分区需要什么配置？**
A：`hive.exec.dynamic.partition=true` + `hive.exec.dynamic.partition.mode=nonstrict`（允许全动态分区）。默认 `mode=strict` 要求至少有一个静态分区。

**Q：为什么 DDL 之后数据没了？**
A：大概率是把内部表和外部表搞混了。内部表 `DROP` 会删数据。可以用 `DESCRIBE FORMATTED t;` 看 `Table Type` 是 `MANAGED_TABLE` 还是 `EXTERNAL_TABLE`。

**Q：分桶表的桶数能改吗？**
A：不能。`CLUSTERED BY ... INTO N BUCKETS` 在建表时固定了。要改只能 `CREATE TABLE 新表 CLUSTERED BY ... INTO M BUCKETS` + `INSERT OVERWRITE 新表 SELECT * FROM 旧表`。
