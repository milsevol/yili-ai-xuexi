# 02 架构与核心组件

## 一句话

Hive 的执行链路是：**Client（Beeline/JDBC）→ HiveServer2（入口网关）→ Compiler（解析、校验、生成执行计划）→ Execution Engine（Tez/Spark/Flink）→ HDFS/对象存储**，整个过程中 Metastore 提供表结构和分区元数据。

## 角色职责

| 组件 | 一句话职责 | 核心端口 | 说明 |
| --- | --- | --- | --- |
| **HiveServer2 (HS2)** | SQL 入口网关：接收 JDBC/Beeline 连接，维护会话，调度查询 | **10000**（JDBC），**10001**（Web UI） | 4.x 中 CLI `hive` 已废弃，统一用 `beeline` |
| **Compiler** | HiveQL → 执行计划：Parse → Semantic Analyze → Optimize → Gen Plan | — | 4.x 拆为 **Metacat**（负责元数据查询）+ **Calcite**（SQL 解析优化） |
| **Execution Engine** | 真正跑 SQL：把 DAG 里的每个节点变成任务 | — | 4.x 默认 **Tez**；Spark / Flink 可选 |
| **Metastore** | 元数据服务：表、列、分区、存储位置的真相 | **9083**（Thrift 服务） | 三种部署模式，见下文 |
| **WebHCat** | REST 接口的 HS2 替代 | **50111** | 轻量级 HTTP API，适合程序化提交 |
| **HCatalog** | 已废弃的「表管理层」 | — | 功能合并进 Metastore，4.x 不再提及 |

## 一次查询的完整链路

```
Beeline 执行: SELECT COUNT(*) FROM orders WHERE dt = '2026-11-01'

① Beeline → HS2 [10000]
   JDBC/HiveServer2 协议，建立会话、鉴权、提交 SQL

② HS2 → Compiler
   Parse（Antlr）→ AST → 语义分析（查 Metastore 拿 orders 表结构）
   → Calcite 优化器生成物理计划（分区裁剪 dt='2026-11-01'，只用当天分区）

③ Compiler → Tez / Spark
   生成 DAG：读取 /user/hive/warehouse/orders/dt=2026-11-01/* 的 ORC 文件
   → 发送 YARN / Spark Master

④ Tez DAGAppMaster 调度 Task
   MapTask 读 ORC → 聚合 → LocalTask 汇总 → 结果返回 HS2

⑤ HS2 → Beeline
   把结果集通过 JDBC 返回客户端
```

## Metastore 的三种部署模式

这是新手最容易混淆的点：

| 模式 | 元数据存储 | 启动方式 | 适用场景 | 缺点 |
| --- | --- | --- | --- | --- |
| **Embedded** | 内嵌 Derby（单机文件） | 随 HS2 一起启动 | 单机开发/测试 | 只能单连、数据丢 Derby 文件就全没了 |
| **Local** | MySQL/PostgreSQL 本地 | 随 HS2 一起启动（元数据库独立） | 小团队、单 HS2 | HS2 和 Metastore 同进程，HS2 挂了元数据也不可用 |
| **Remote** | MySQL/PostgreSQL 远程 | 独立起 `metastore` 服务（端口 9083） | **生产环境推荐** | 多一个进程要维护，但可做 HA |

**Remote 模式的好处**：Spark、Flink、Trino 可以直接通过 Thrift 协议连 HMS（9083），不需要经过 HS2。HiveServer2 变成了一个可选的查询入口。

## 执行引擎切换

| 引擎 | 默认？ | 优点 | 缺点 | 配置 |
| --- | --- | --- | --- | --- |
| **Tez** | Hive 4.x 默认 | DAG 减少中间落盘，比 MR 快 2–10x | 强依赖 YARN + DAGAppMaster，不擅长迭代 | `hive.execution.engine=tez` |
| **Spark** | 可选 | Catalyst 优化好、可迭代、支持流 | AM 资源大、JVM 开销 | `hive.execution.engine=spark` |
| **MapReduce** | 3.x 默认，4.x 废弃 | 最稳定、兼容性好 | 慢（每个 MR 作业都有 Shuffle） | `hive.execution.engine=mr` |
| **Flink** | 可选（4.x 新增） | 流批一体、实时 | 生态还在完善中 | `hive.execution.engine=flink` |

**切换引擎示例**：

```sql
-- 会话级别切换，不用重启 HS2
SET hive.execution.engine=tez;
-- 跑一个查询，看 Tez DAG
SELECT * FROM orders JOIN users ON orders.user_id = users.id;

SET hive.execution.engine=spark;
-- 同一个查询跑 Spark 引擎（注意 Spark Session 会复用）
SELECT * FROM orders JOIN users ON orders.user_id = users.id;
```

## Tez vs Spark 内部的 DAG 差异

```
同一个 JOIN 查询

Tez DAG（Hive on Tez 默认）:
  Source(orders) → Filter → Map 端预聚合
  Source(users)  → Filter → Map 端预聚合  → Join → Aggregate → Sink
                                           ↕
                                       Shuffle（一次）

Spark DAG（Hive on Spark）:
  orders → Filter → Exchange → Shuffle → Map端聚合
  users  → Filter → Exchange → Shuffle → Map端聚合 → SortMergeJoin → Aggregate → Collect
                                        ↓
                                   Exchange → BroadcastHashJoin（小表 ≤ spark.sql.autoBroadcastJoinThreshold）
```

Tez 的 DAG 更紧凑，适合 Hive 这种「翻译生成的计划」；Spark 的 DAG 可以被 Catalyst 进一步改写和复用。

## 关键配置

```properties
# hive-site.xml（HiveServer2 和 Metastore 都要读）

# —— Metastore 远程模式 ——
hive.metastore.uris=thrift://hms1:9083,thrift://hms2:9083
# 留空则为 Local/Embedded 模式

# —— 执行引擎 ——
hive.execution.engine=tez
# 4.x 默认 tez，可选 spark / flink / mr

# —— HS2 端口 ——
hive.server2.thrift.port=10000
hive.server2.webui.port=10001

# —— Metastore 端口（远程模式）——
hive.metastore.server.port=9083

# —— Tez 相关（跑在 YARN 上）——
hive.tez.container.size=4096       # 单个 Tez Task 容器内存（MB）
hive.tez.java.opts=-Xmx3072m       # JVM 堆（比容器小 ~20%）
```

## 常见问题

**Q：Metastore 远程模式的多节点 URI 怎么写？**
A：`thrift://hms1:9083,thrift://hms2:9083`。客户端按顺序尝试，第一个可用的就连上；但**不是负载均衡**，只是 failover。真正的高可用需要 ZooKeeper 注册 HMS。

**Q：HS2 和 Metastore 分开部署后，HS2 怎么找 HMS？**
A：通过 `hive.metastore.uris` 配置。HS2 启动时读 hive-site.xml，用 Thrift 客户端连 HMS。

**Q：为什么 Hive 4.x 把 MR 弃用了？**
A：Tez 是 DAG 引擎，同一个查询可以一次 Shuffle 完成；MR 每个作业至少两次 Shuffle（Map → Reduce）。性能差 5–10x，没有理由继续用。
