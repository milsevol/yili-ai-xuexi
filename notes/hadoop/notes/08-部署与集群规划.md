# 08 部署与集群规划

## 一句话

**Hadoop 部署的难点不在「装」，而在「规划」**——角色怎么放、内存怎么分、磁盘怎么留、网络怎么走，决定了集群未来三年的稳定性和扩容成本。

## 三种部署模式

| | 本地模式 | 伪分布式 | 完全分布式 |
| --- | --- | --- | --- |
| `fs.defaultFS` | `file:///` | `hdfs://localhost:8020` | `hdfs://mycluster` |
| 守护进程 | 无，单 JVM | 所有角色挤一台 | 角色分散多台 |
| 适用 | 写代码、单测 | 学习、开发验证 | 生产 |
| 常见坑 | 路径写成 HDFS 直接报错 | 端口冲突、内存不够 | 配置不一致、格式化顺序错 |

## 集群规划

| 原则 | 原因 |
| --- | --- |
| NameNode / Standby **独立机器**，不与 DN 混布 | NN 对 GC 停顿和磁盘延迟敏感，DN 的 IO 抖动会拖垮它 |
| RM 可与 NN 合布（小集群），大集群独立 | RM 也是内存大户，规模大了要拆开 |
| DataNode + NodeManager **混布** | 数据本地性：任务尽量在数据所在节点跑 |
| JournalNode / ZK 各 3 台（奇数） | QJM 过半写，容忍 1 台故障 |
| 边缘/网关节点放客户端、HS2、调度器 | 避免客户端 jar、SQL 会话影响核心服务 |

| 角色 | 3 节点（学习） | 10 节点（中小生产） | 50 节点（中大型） |
| --- | --- | --- | --- |
| NameNode（HA） | node1 active、node2 standby | 2 台独立（32C/128G） | 2 台独立（32C/256G） |
| ResourceManager（HA） | node1 + node2 | 2 台（可与 NN 合布） | 2 台独立 |
| JournalNode / ZooKeeper | 3 台（node1–3） | 3 + 3 台 | 3–5 + 3–5 台 |
| DataNode + NodeManager | 3 台 | 7 台 worker | 45 台 worker |
| Hive Metastore / HS2 | node3 | edge1 | 3 台 edge |
| 磁盘 | 1–2 块 SSD | 12×4TB HDD + 2×SSD | 12–24 块 HDD |

## 硬件与网络

| 部件 | 建议 | 说明 |
| --- | --- | --- |
| **数据盘** | JBOD 单盘直通，不要 RAID5 | HDFS 自己三副本；RAID5 有写惩罚、重建慢，还会把单盘故障放大成整机风险 |
| 单盘容量 | 4–8TB，7.2K SATA 性价比最高 | 盘越大，故障重建越久 |
| **NN 元数据盘** | SSD / NVMe，RAID1 或双目录 | edits 写入延迟直接决定 NN 性能 |
| 内存 | DN 堆 4–8GB，其余给 page cache | DN 靠 OS 缓存，不是堆越大越好 |
| NN 堆 | 百万级 block 从 8–16GB 起步 | 最终按实际对象数和 GC 定，别拍脑袋 |
| 网络 | 10GbE 起步，ToR + 骨干 | 三副本写入 = 3 倍网络流量 |

机架感知配置 `net.topology.script.file.name=/etc/hadoop/conf/topology.sh`；不配的话所有节点都在 `/default-rack`，跨机架副本策略失效。

## OS 调优清单

| 项 | 做法 | 原因 |
| --- | --- | --- |
| **swap** | `swapoff -a` 或 `vm.swappiness=1` | JVM 被 swap 会出现秒级 STW |
| **透明大页** | `echo never > /sys/kernel/mm/transparent_hugepage/enabled` | 减少 GC 延迟抖动 |
| **ulimit** | `nofile=65536`、`nproc=65536` | 数据节点会开大量文件和线程 |
| **时钟同步** | chrony/ntp，偏差控制在秒级 | Kerberos 默认容忍 5 分钟 |
| **hosts / DNS** | 内网 DNS，主机名可正反解析 | 解析不一致会导致 DN 注册失败 |
| **SELinux** | 关闭或配策略 | 否则绑端口、写数据目录被拒绝 |
| **防火墙** | 关闭或放通端口 | 8020/9870/8032/8088/8041/8042/9083/10000/2181/16020 |
| **磁盘预留** | `dfs.datanode.du.reserved=10GB` | 防磁盘写满拖垮整机 |

## 四个核心配置文件

```xml
<!-- core-site.xml -->
<configuration>
  <property><name>fs.defaultFS</name><value>hdfs://mycluster</value></property>
  <property><name>hadoop.tmp.dir</name><value>/data/hadoop/tmp</value></property>
  <property><name>ha.zookeeper.quorum</name><value>zk1:2181,zk2:2181,zk3:2181</value></property>
</configuration>
```

```xml
<!-- hdfs-site.xml：HA + QJM 精简版 -->
<configuration>
  <property><name>dfs.replication</name><value>3</value></property><property><name>dfs.blocksize</name><value>134217728</value></property>
  <property><name>dfs.namenode.name.dir</name><value>/data/dfs/nn</value></property><property><name>dfs.datanode.data.dir</name><value>/data/dfs/dn1,/data/dfs/dn2</value></property>
  <property><name>dfs.nameservices</name><value>mycluster</value></property><property><name>dfs.ha.namenodes.mycluster</name><value>nn1,nn2</value></property>
  <property><name>dfs.namenode.rpc-address.mycluster.nn1</name><value>nn1:8020</value></property><property><name>dfs.namenode.rpc-address.mycluster.nn2</name><value>nn2:8020</value></property>
  <property><name>dfs.namenode.shared.edits.dir</name><value>qjournal://jn1:8485;jn2:8485;jn3:8485/mycluster</value></property><property><name>dfs.journalnode.edits.dir</name><value>/data/dfs/jn</value></property>
  <property><name>dfs.client.failover.proxy.provider.mycluster</name><value>org.apache.hadoop.hdfs.server.namenode.ha.ConfiguredFailoverProxyProvider</value></property><property><name>dfs.ha.automatic-failover.enabled</name><value>true</value></property>
  <property><name>dfs.ha.fencing.methods</name><value>sshfence</value></property><property><name>dfs.ha.fencing.ssh.private-key-files</name><value>/home/hdfs/.ssh/id_rsa</value></property>
</configuration>
```

```xml
<!-- yarn-site.xml -->
<configuration>
  <property><name>yarn.resourcemanager.hostname</name><value>rm1</value></property><property><name>yarn.resourcemanager.webapp.address</name><value>rm1:8088</value></property>
  <property><name>yarn.nodemanager.aux-services</name><value>mapreduce_shuffle</value></property><property><name>yarn.nodemanager.aux-services.mapreduce_shuffle.class</name><value>org.apache.hadoop.mapred.ShuffleHandler</value></property>
  <property><name>yarn.nodemanager.resource.memory-mb</name><value>51200</value></property><property><name>yarn.nodemanager.resource.cpu-vcores</name><value>16</value></property>
  <property><name>yarn.nodemanager.local-dirs</name><value>/data/yarn/local</value></property><property><name>yarn.log-aggregation-enable</name><value>true</value></property>
</configuration>
```

```xml
<!-- mapred-site.xml -->
<configuration>
  <property><name>mapreduce.framework.name</name><value>yarn</value></property><property><name>mapreduce.jobhistory.address</name><value>jhs:10020</value></property>
  <property><name>mapreduce.jobhistory.webapp.address</name><value>jhs:19888</value></property><property><name>yarn.app.mapreduce.am.env</name><value>HADOOP_MAPRED_HOME=/opt/hadoop</value></property>
  <property><name>mapreduce.map.env</name><value>HADOOP_MAPRED_HOME=/opt/hadoop</value></property><property><name>mapreduce.reduce.env</name><value>HADOOP_MAPRED_HOME=/opt/hadoop</value></property>
</configuration>
```

RM HA 另需 `yarn.resourcemanager.ha.enabled=true`、`yarn.resourcemanager.cluster-id`、`yarn.resourcemanager.ha.rm-ids=rm1,rm2`，以及每个 rm 的 hostname/webapp 地址；状态恢复靠 `yarn.resourcemanager.recovery.enabled=true` + ZK。`HADOOP_MAPRED_HOME` 三个环境变量是**必踩坑**，不写会报 `Could not find or load main class`。

## 格式化与启动顺序

```bash
hdfs --daemon start journalnode          # 三台 JN
hdfs zkfc -formatZK                      # 格式化 ZK 中的 HA 状态
hdfs namenode -format                     # 只在第一台 NN，且只一次
hdfs --daemon start namenode             # 启动 nn1 + zkfc
hdfs namenode -bootstrapStandby          # 在 nn2 上从 nn1 同步元数据
hdfs --daemon start namenode             # 启动 nn2 + zkfc
start-dfs.sh && start-yarn.sh
mapred --daemon start historyserver
```

```bash
jps                      # NameNode/DataNode/JournalNode/ZKFC/ResourceManager/NodeManager
hdfs dfsadmin -report    # DN 数量、容量、剩余
hdfs haadmin -getServiceState nn1
```

**format 的坑**：`-format` 会生成新 `clusterID` 写进 NN 的 `VERSION`；DN 目录还是旧 ID 时会报 `Incompatible clusterIDs in /data/dfs/dn`。处理：清空所有 DN 数据目录并重启 DN（会丢数据），或恢复 NN 元数据。生产格式化前必须确认目录为空，运行中的集群永远不要执行 format。

## HA 部署要点

| 要点 | 说明 |
| --- | --- |
| JournalNode 奇数台 | 3 台容忍 1 台故障，5 台容忍 2 台；QJM 写需过半数 |
| ZooKeeper 奇数台 | 3 或 5 台，独立部署更稳，`ha.zookeeper.quorum` 写全 |
| ZKFC | 每个 NN 节点一个，监控健康、抢锁、触发 failover |
| **fencing** | 必须配，防脑裂；`sshfence` 需要免密 SSH 和私钥路径 |
| 自动 failover | `dfs.ha.automatic-failover.enabled=true`，靠 ZK 选举 |

`shell(/bin/true)` 只适合「有存储层保证旧 NN 已死」的场景，生产直接用它等于放弃防脑裂。验证：`kill -9` 掉 Active NN，10–30 秒内 `getServiceState nn2` 变 active，客户端读写不中断。

## Kerberos 简介与坑

```bash
kinit -kt /etc/security/keytabs/hdfs.keytab hdfs/nn1@EXAMPLE.COM
klist
```

核心配置：`hadoop.security.authentication=kerberos`、`hadoop.security.authorization=true`、`hadoop.http.authentication.type=kerberos`。

| 坑 | 表现 | 处理 |
| --- | --- | --- |
| 时间偏差 | `Clock skew too great` | chrony 同步，控制在 5 分钟内 |
| keytab 权限 | 手动 kinit 能过，服务不行 | keytab 必须 600，属主是服务用户 |
| principal 不匹配 | `Client not found in Kerberos database` | principal 里的 host 必须与主机名一致 |
| 浏览器访问 | 401 / `GSS initiate failed` | 配 `auth_to_local`，浏览器需支持 SPNEGO |

## 部署验证清单

1. `jps` 全部角色在线，进程无反复重启。
2. `hdfs dfsadmin -report` 的 Live DataNodes 数量与容量符合规划。
3. `hdfs dfs -mkdir /tmp/test && hdfs dfs -put local.txt /tmp/test/` 成功。
4. `hdfs fsck / -files -blocks` 无 missing / corrupt。
5. `hdfs haadmin -getServiceState nn1/nn2` 一主一备，手动 failover 可切换。
6. `yarn node -list` 全部 RUNNING，可用内存/vcore 符合预期。
7. `yarn jar hadoop-mapreduce-examples-*.jar pi 2 1000` 能跑通。
8. `yarn logs -applicationId <id>` 能拿到聚合日志。
9. 19888 / 8088 / 9870 三个 UI 可访问。
10. `chronyc tracking` 正常，DNS 正反解析一致。
