# 04 多租户与资源管理

## 一句话

OceanBase 用**租户（Tenant）** 做资源与安全隔离：一个集群可以创建多个租户，每个租户像一个小型数据库实例，拥有独立的 CPU、内存、日志盘、数据库、用户和兼容模式。租户之下再通过 **资源单元（Resource Unit）→ 资源池（Resource Pool）** 来分配资源。

## 三层资源模型

```
集群
 └── 资源单元配置（Unit Config）   ← 定义「一份资源长什么样」
      └── 资源池（Resource Pool）  ← 定义「用多少份、放在哪些 Zone」
           └── 租户（Tenant）      ← 真正承载业务的逻辑实例
```

| 概念 | 作用 | 关键属性 |
| --- | --- | --- |
| **Unit Config** | 资源规格模板 | CPU、内存、日志盘、IOPS |
| **Resource Pool** | 资源的集合 | Unit 数量、Zone 列表、绑定的 Unit Config |
| **Tenant** | 业务实例 | 兼容模式、字符集、资源池、白名单 |

## 创建租户的完整流程

```sql
-- 1. 创建资源单元配置
CREATE RESOURCE UNIT unit_2c8g
  MAX_CPU = 2, MIN_CPU = 2,
  MEMORY_SIZE = '8G',
  LOG_DISK_SIZE = '10G',
  MAX_IOPS = 10000, MIN_IOPS = 10000, IOPS_WEIGHT = 1;

-- 2. 创建资源池（三个 Zone 各一个 Unit）
CREATE RESOURCE POOL pool_app
  UNIT = 'unit_2c8g',
  UNIT_NUM = 1,
  ZONE_LIST = ('zone1', 'zone2', 'zone3');

-- 3. 创建 MySQL 模式租户
CREATE TENANT ob_app
  RESOURCE_POOL_LIST = ('pool_app'),
  PRIMARY_ZONE = 'zone1;zone2,zone3',
  LOCALITY = 'FULL{1}@zone1, FULL{1}@zone2, FULL{1}@zone3',
  CHARSET = 'utf8mb4',
  COLLATE = 'utf8mb4_general_ci'
  SET ob_compatibility_mode = 'mysql',
      ob_tcp_invited_nodes = '%';

-- 4. 创建 Oracle 模式租户
CREATE TENANT ob_orcl
  RESOURCE_POOL_LIST = ('pool_orcl'),
  PRIMARY_ZONE = 'zone1;zone2,zone3',
  LOCALITY = 'FULL{1}@zone1, FULL{1}@zone2, FULL{1}@zone3'
  SET ob_compatibility_mode = 'oracle';
```

> 兼容模式在建租户时确定，之后不能修改。MySQL 模式与 Oracle 模式要建不同租户。

## 资源规格怎么规划

| 资源 | 说明 | 规划建议 |
| --- | --- | --- |
| **CPU** | `MIN_CPU` / `MAX_CPU` | 先按业务峰值估，再留 20%–30% 余量 |
| **内存** | `MEMORY_SIZE` | 包含 MemStore、缓存、SQL 执行内存；不要挤占系统内存 |
| **日志盘** | `LOG_DISK_SIZE` | 与写入量、副本同步延迟相关，建议单独规划 |
| **IOPS** | `MIN_IOPS` / `MAX_IOPS` | 按存储介质能力设置，避免互相打爆 |

单机资源估算的粗略公式：

```
单机可分配资源 ≈ 物理 CPU / 内存 - 系统预留
每个租户所需 Unit 数 = 租户分布 Zone 数 × UNIT_NUM
```

例如三 Zone、`UNIT_NUM=1`，每个租户需要 3 个 Unit；如果单机只能放 4 个 Unit，那么这个集群最多承载约 1 个该规格租户（还要给 sys 租户留资源）。

## 租户类型

| 类型 | 说明 |
| --- | --- |
| **sys 租户** | 系统租户，管理集群元数据，不能承载业务表 |
| **用户租户** | 业务租户，MySQL 或 Oracle 模式 |
| **Meta 租户** | 每个用户租户自动关联，存放该租户的元数据，不直接对外服务 |

## 用户与权限

```sql
-- MySQL 模式
CREATE USER 'app'@'%' IDENTIFIED BY '******';
GRANT SELECT, INSERT, UPDATE, DELETE ON appdb.* TO 'app'@'%';

-- Oracle 模式
CREATE USER app IDENTIFIED BY ******;
GRANT CONNECT, RESOURCE TO app;
GRANT SELECT ON app.t_order TO readonly_user;
```

连接串要带租户信息：

```bash
# 直连 OBServer
obclient -h10.0.0.1 -P2881 -uapp@ob_app -p -Dappdb

# 经过 OBProxy，格式：用户@租户#集群
obclient -h10.0.0.10 -P2883 -uapp@ob_app#obcluster -p -Dappdb
```

> `ob_tcp_invited_nodes` 控制允许登录的客户端 IP。生产上不要长期放开 `%`。

## 隔离与配额

- **CPU 隔离**：通过 cgroup 控制，租户之间按 Unit 规格分配。
- **内存隔离**：租户内存独立，避免一个大查询拖垮整个集群。
- **IO 隔离**：按 IOPS 权重分配。
- **连接隔离**：每个租户独立连接池与白名单。

需要注意：隔离不是绝对的物理隔离。同一台 OBServer 上的多个租户仍共享磁盘和网络，规划时要避免把高 IO 租户堆在一起。

## 扩缩容

| 操作 | 方式 | 影响 |
| --- | --- | --- |
| 租户扩容 | 调整 Unit Config 的 CPU/内存 | 在线生效，需关注主机余量 |
| 增加副本 | 修改 Locality | 后台补副本，期间有数据同步 |
| 增加 Unit | 修改 `UNIT_NUM` | 用于单 Zone 多副本/多节点打散 |
| 集群扩容 | 增加 OBServer / Zone | 自动负载均衡，业务无感 |

```sql
-- 调整租户资源规格（先改 Unit Config，再生效到租户）
ALTER RESOURCE UNIT unit_2c8g MAX_CPU = 4, MIN_CPU = 4, MEMORY_SIZE = '16G';

-- 修改副本分布
ALTER TENANT ob_app LOCALITY = 'FULL{1}@zone1, FULL{1}@zone2, FULL{1}@zone3, FULL{1}@zone4';
```

## 主备租户

生产上可以做「主租户 + 备租户」：

- 主租户承载读写；
- 备租户通过日志同步保持准实时一致；
- 可用于异地容灾、读写分离、迁移切换。

备租户默认只读，切换时需要执行 `SWITCHOVER` / `FAILOVER`（具体语法随版本变化，以官方文档为准）。

## 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 建租户报资源不足 | Unit 规格超过剩余资源 | 缩小 Unit、加机器、清理空闲租户 |
| 租户连不上 | 白名单、租户名、集群名错误 | 检查 `ob_tcp_invited_nodes` 与连接串 |
| 租户内存告警 | 大查询、并发高、MemStore 占用高 | 限流、优化 SQL、扩容 |
| 修改 Unit 失败 | Unit Config 正在被使用 | 先确认资源池引用关系，再调整 |

## 常见问题

**Q：一个租户能当多个库用吗？**
A：可以。一个租户内可以建多个 Database（MySQL 模式）或 Schema（Oracle 模式），但它们的资源是共享的。

**Q：多租户和分库分表是什么关系？**
A：多租户解决的是「不同业务/环境之间的资源与安全隔离」，不是单表水平拆分。单表拆分靠分区。

**Q：Unit 数量和副本数是一回事吗？**
A：不是。副本数由 Locality 决定；Unit 数量决定资源份数与分布。三 Zone 三副本通常配 3 个 Unit。
