# 01 概述与定位

## 一句话

**OceanBase（OB）** 是蚂蚁集团自研的**分布式关系型数据库**：shared-nothing 架构 + Paxos 多副本，把「金融级高可用、在线水平扩展、MySQL/Oracle 双兼容、HTAP」放在同一个引擎里。它既不是中间件拼出来的分库分表，也不是单机数据库加只读副本，而是从存储、事务到 SQL 引擎都为分布式重新设计。

## 它解决什么问题

传统单机数据库（MySQL / Oracle 单实例）在金融核心场景会遇到三个硬墙：

| 痛点 | 单机数据库的做法 | OceanBase 的做法 |
| --- | --- | --- |
| 容量/并发到顶 | 分库分表中间件，跨库事务靠应用补偿 | 原生分区 + 多副本，一个逻辑库可跨多机 |
| 高可用 | 主从复制，切换有 RPO/RTO 风险 | Paxos 多数派同步，RPO=0，故障自动切主 |
| 成本 | 高端小型机 + 商业存储，扩容要停机 | x86 通用服务器 + 本地 SSD，在线扩容 |
| 多业务隔离 | 一库一实例，资源浪费 | 多租户，一个集群承载多个隔离实例 |
| Oracle 迁移 | 改造成本高、语法不兼容 | Oracle 模式兼容大部分 PL/SQL 与数据字典 |

## 核心能力

| 能力 | 说明 |
| --- | --- |
| **原生分布式** | 数据按分区打散到多台 OBServer；分区副本组成 Paxos 组，自动选主 |
| **金融级高可用** | 三副本容忍单 Zone 故障；官方口径 RPO=0、RTO 小于 8 秒（取决于部署形态） |
| **在线扩展** | 增加 OBServer / Zone 后自动负载均衡，扩缩容不中断业务 |
| **多租户** | 一个集群可创建多个租户，CPU、内存、IO 隔离，近似「一租户一实例」 |
| **双兼容模式** | 建租户时选择 MySQL 模式或 Oracle 模式，分别兼容对应生态 |
| **HTAP** | 行存为主，4.3 起支持列存副本/列存表，兼顾 OLTP 与实时分析 |
| **高压缩** | 基于 LSM-Tree 的编码与压缩，通常比行式数据库节省大量存储（倍数随数据特征变化） |
| **在线 DDL** | 加列、建索引、改分区等操作可在线执行，减少停机窗口 |

## 产品家族

| 组件 | 作用 |
| --- | --- |
| **OBServer** | 数据库核心进程，承担 SQL 解析、事务、存储、Paxos 日志 |
| **OBProxy** | 无状态反向代理，负责 SQL 路由、连接管理、故障摘除 |
| **OCP** | 运维管理平台：集群/租户/备份/监控/告警 |
| **OMS** | 数据迁移服务：结构迁移、全量迁移、增量同步、数据校验 |
| **ODC** | 开发者中心：SQL 开发、数据管理、审核 |
| **OBD** | 命令行部署工具，适合测试与 POC |
| **OBLoader / OBDumper** | 批量导入导出工具 |

## 和其他数据库怎么比

| 维度 | OceanBase | MySQL 主从 | Oracle RAC | TiDB |
| --- | --- | --- | --- | --- |
| **架构** | shared-nothing + Paxos | 单机 + 主从复制 | 共享存储集群 | shared-nothing + Raft |
| **故障切换** | 自动选主，RPO=0 | 依赖 MHA/Orchestrator，可能丢数据 | RAC 节点故障切换 | 自动选主 |
| **扩展方式** | 加机器/加 Zone，自动均衡 | 分库分表 | 纵向扩容为主 | 加 TiKV 节点 |
| **事务** | 分布式事务，快照隔离 | 单机事务 | 单机/共享存储事务 | 分布式事务 |
| **兼容性** | MySQL / Oracle 双模式 | MySQL | Oracle | MySQL |
| **典型场景** | 金融核心、政务、运营商 | 中小业务、互联网 | 传统核心系统 | 互联网 HTAP |

## 适用与不适用

| 适用 | 原因 |
| --- | --- |
| 金融核心交易、账务 | 强一致、多副本、故障自动切换 |
| 政务/运营商大集中 | 多租户整合、国产化替代 |
| Oracle 存量系统替换 | Oracle 模式降低改造成本 |
| 高并发 OLTP + 实时报表 | HTAP，避免交易库与分析库两套链路 |
| 需要在线扩容的业务 | 分区 + 自动负载均衡 |

| 不适用 | 替代方向 |
| --- | --- |
| 单机小应用、数据量很小 | MySQL / PostgreSQL 更简单 |
| 纯离线大数据分析 | Hive / Spark / ClickHouse 更合适 |
| 超高频 KV 点查 | Redis / HBase |
| 团队完全没有分布式运维能力 | 先做 POC 与运维培训，或选托管服务 |

## 常见问题

**Q：OceanBase 和 MySQL 是什么关系？**
A：OB 的 MySQL 模式兼容 MySQL 协议和大部分语法，可以用 MySQL 客户端、JDBC 连接；但 OB 是独立实现的分布式数据库，执行计划、参数、系统视图都不同。

**Q：OceanBase 能完全替代 Oracle 吗？**
A：Oracle 模式覆盖了大部分常用语法、PL/SQL、数据字典视图，但 IOT、部分高级包、AQ 等仍有限制，迁移前必须做兼容性评估和 POC。

**Q：社区版和企业版差在哪？**
A：社区版开源、可免费使用；企业版提供更多企业级能力与商业支持。具体差异以官方版本说明为准。
