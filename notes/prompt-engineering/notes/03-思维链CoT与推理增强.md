# 03 思维链 CoT 与推理增强

## 一句话

**思维链（Chain-of-Thought, CoT）是让模型「把推理过程写出来再作答」的技巧**，对数学、逻辑、多步推理任务提升显著；进阶玩法包括 Zero-shot CoT（一句话触发）、Self-Consistency（多路径投票）、Tree-of-Thought（树搜索推理）。代价是更多输出 token 和更高延迟。

## 为什么需要 CoT

LLM 逐 token 生成，「直接给答案」意味着模型必须在一步之内完成全部推理。对多步推理任务，一步出答案 ≈ 瞎猜。

```text
问题：一个商店上午卖出 23 个苹果，下午卖出 17 个，晚上进货 50 个后共有 87 个。
      商店原来有多少个苹果？

❌ 直答：模型直接蹦一个数 → 65（错）

✅ CoT：设原来有 x 个。
  上午后：x - 23
  下午后：x - 23 - 17 = x - 40
  进货后：x - 40 + 50 = x + 10 = 87
  所以 x = 77。（对）
```

**本质**：让模型用自然语言展开中间步骤，等于给了它「草稿纸」，每一步只需处理一个简单推理。

## Zero-shot CoT：一句咒语

在最简形式下，只要在问题后加一句：

```text
Let's think step by step.
（中文场景可用：让我们一步一步思考。）
```

| 直答 Prompt | Zero-shot CoT Prompt |
| --- | --- |
| `问题：...。答案：` | `问题：...。让我们一步一步思考。` |
| 输出短，快 | 输出长，慢，但推理任务准确率显著提升 |
| 适合事实问答、分类 | 适合数学、逻辑、规划 |

**注意**：在 GPT-4o / Claude 3.5 之后的新一代模型上，简单任务加 CoT 收益变小（模型已被 RLHF 训练出隐式推理），但**复杂多步任务**收益依然明显。是否使用要跑评估集验证，不要想当然。

## Few-shot CoT：给带推理过程的示例

比一句咒语更强的方式：示例里**展示完整推理过程**。

```text
【示例】
问题：停车场原来有 12 辆车，开走 5 辆，又开来 8 辆，现在有几辆？
推理：12 - 5 = 7；7 + 8 = 15。
答案：15

问题：小明买了 3 支笔，每支 2 元，付了 10 元，应找回多少？
推理：3 × 2 = 6；10 - 6 = 4。
答案：4

【待处理】
问题：{question}
推理：
```

**示例编写要点**：

- 推理步骤要**短而准**，每步一个运算
- 示例的推理风格会被模仿，写啰嗦模型就啰嗦
- 末尾用 `答案：` 显式标记最终答案，方便程序用正则提取

## Self-Consistency：多路径投票

对同一问题，用较高 temperature 采样 N 条推理路径，取**多数答案**。

```python
# OpenAI SDK 风格伪代码：采样 5 条路径，多数投票
from collections import Counter
from openai import OpenAI

client = OpenAI()

def solve(question: str, n: int = 5) -> str:
    prompt = f"问题：{question}\n让我们一步一步思考，最后用「答案：」给出最终答案。"
    answers = []
    for _ in range(n):
        resp = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": prompt}],
            temperature=0.7,        # 要多样性，温度调高
        )
        text = resp.choices[0].message.content
        if "答案：" in text:
            answers.append(text.split("答案：")[-1].strip())
    # 多数投票
    return Counter(answers).most_common(1)[0][0]
```

```text
路径1：…推理A… → 答案：77
路径2：…推理B… → 答案：77   ┐
路径3：…推理C… → 答案：65   ├─ 投票 → 77（3/5）
路径4：…推理D… → 答案：77   │
路径5：…推理E… → 答案：80   ┘
```

| 单次 CoT | Self-Consistency |
| --- | --- |
| 成本 1x | 成本 Nx（通常 N=5~10） |
| 一次推理出错就错 | 单条路径出错可被投票纠正 |
| 延迟 = 单次 | 可并行采样，延迟 ≈ 单次 |

**适用**：答案唯一、可聚合的任务（数学题、选择题）。**不适用**：开放式生成（摘要、翻译没法投票）。

## Tree-of-Thought（ToT）：树搜索推理

CoT 是一条直线走到底；ToT 把推理变成**树**：每一步生成多个候选思路，评估候选质量，剪掉差的，展开好的。

```text
                    问题
              ┌──────┼──────┐
           思路A    思路B    思路C      ← 每步生成多个候选
            │        │       ✗ 剪掉（评估分低）
         ┌──┴──┐     │
        A1    A2    B1                  ← 展开有希望的
         ✗     │     │
              A2.1  B1.1
               │     │
            答案    答案               ← 找到解或回溯
```

**典型应用**：24 点游戏、填字游戏、需要规划/回溯的任务。

**工程现实**：ToT 需要多次调用模型做「生成候选 + 评估打分」，实现复杂、成本高。业务中优先级：**先用 CoT → 不够上 Self-Consistency → 还不够再考虑 ToT**。多数业务任务到不了 ToT。

## 推理增强技术对比

| 技术 | 核心思想 | 成本 | 适用场景 | 一句话评价 |
| --- | --- | --- | --- | --- |
| Zero-shot CoT | 加一句「逐步思考」 | 1x | 简单推理 | 免费午餐，先试它 |
| Few-shot CoT | 示例展示推理过程 | ~1.5x | 风格化推理 | 稳定但写示例费劲 |
| Self-Consistency | 多路径 + 投票 | 5~10x | 答案唯一的任务 | 花钱买准确率 |
| Tree-of-Thought | 树搜索 + 剪枝 | 10x+ | 规划/搜索类任务 | 学术价值 > 业务价值 |
| ReAct | 推理 + 工具调用交替 | 视工具数 | Agent 场景 | 见 Function Calling 章 |

## 适用场景与失效场景

| ✅ CoT 有效 | ❌ CoT 无效甚至有害 |
| --- | --- |
| 数学题、算术 | 事实性问答（「姚明多高」不需要推理） |
| 多步逻辑推理 | 简单分类（加了只增加成本和延迟） |
| 代码调试分析 | 创意写作（推理痕迹破坏文采） |
| 复杂规则判断（合规审核） | 模型知识盲区（想再多步也不知道） |
| 需要审计的中间过程 | 对延迟敏感的实时场景 |

**失效的典型原因**：

1. **错误传播**：第一步推错，后面步步错——CoT 不保证中间步骤正确
2. **事后编造**：模型先有了答案倾向，再编一个「看起来合理」的推理过程
3. **上下文膨胀**：长推理占用窗口，反而挤掉关键信息

## 工程建议

1. **隐藏推理过程**：让模型输出 `思考过程` + `最终答案` 两段，只把答案展示给用户（或要求推理放在 `<thinking>` 标签内，程序剥掉）
2. **限制推理长度**：「推理过程不超过 5 步」，防止模型无限啰嗦
3. **结构化收尾**：强制「最后一行必须是 `答案：xxx`」，便于程序提取
4. **用推理模型替代手工 CoT**：o1 / DeepSeek-R1 类推理模型已内置长链推理，手工写 CoT 提示的必要性在下降

## 常见问题

**Q：CoT 会让输出变慢吗？**
A：会。输出 token 数从几个涨到几百个，延迟和成本同步上升。对延迟敏感的在线场景，可只在「疑难 case」上启用 CoT（简单 case 走直答，用路由器分流）。

**Q：Self-Consistency 的 N 取多大？**
A：经验值 5~10。超过 10 收益趋于平缓，成本线性上升。注意要配合 temperature > 0 才有路径多样性，temperature=0 时 N 条路径几乎一样，白花钱。

**Q：模型推理过程是错的但最终答案对，怎么回事？**
A：常见现象。推理链不是模型「真实思考」的忠实记录，而是「为答案生成的合理化解释」。所以**不要把 CoT 输出当作可审计的证据**，它仅供参考。

**Q：推理模型（o1/R1）出来了，CoT 技巧还要学吗？**
A：要。① 推理模型贵且慢，简单任务用普通模型 + 轻量 CoT 性价比更高；② Self-Consistency、ToT 的思想在 Agent 设计中仍在复用；③ 面试常考。

**Q：怎么评估 CoT 带来的提升？**
A：固定评估集，分别跑「直答」和「CoT」两个版本，对比准确率。同时记录平均 token 消耗和延迟，算清楚「每提升 1% 准确率多花多少钱」。
