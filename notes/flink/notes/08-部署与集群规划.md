# 08 部署与集群规划

## 一句话

Flink 有三种部署模式：**Standalone（单机/小集群本地测试）、YARN（跑在 Hadoop YARN 上）、Kubernetes（生产首选）**。规划时先算好** JM 数量（HA 至少 2）+ TM 数量 + Slot 预算 = 并行度 + 冗余**，每个 TM 的内存分成 **Heap、Off-Heap、Managed（RocksDB 用）、Network Buffer** 四块；JVM 参数和 RocksDB 内存必须一起调，否则 Checkpoint 慢、GC 频繁。

## 三种部署模式

| 模式 | 适用场景 | 资源管理 | HA 方案 |
| --- | --- | --- | --- |
| **Standalone** | 本地调试、小集群（< 10 节点） | Flink 自己管 | ZooKeeper + 共享存储 |
| **YARN** | 已有 Hadoop YARN 集群 | YARN RM 管 | YARN RM HA + Flink JM HA |
| **Kubernetes** | 生产首选、云原生 | K8s 管 | K8s Leader Election + ConfigMap/Secret |

### Standalone 启动

```bash
# 单机
bin/start-cluster.sh     # 起 1 JM + 1 TM，默认 Slot = CPU 核数

# 多节点：conf/flink-conf.yaml 里改 jobmanager.rpc.address
# conf/slaves 里写 TM 节点列表
bin/start-cluster.sh
```

### YARN 提交

```bash
# Per-Job（每个作业独立集群，推荐）
bin/flink run -m yarn-cluster -p 8 -yjm 2048 -ytm 8192 -ys 4 \
    -d /path/to/job.jar

# 参数解释：
# -p 8    并行度 8
# -yjm    JM 堆内存 2GB
# -ytm    TM 总内存 8GB
# -ys 4   TM Slot 数 4
```

### Kubernetes 部署（推荐）

**Session 模式**（长驻集群，多个作业共享）：

```yaml
# flink-configuration-configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: flink-config
data:
  flink-conf.yaml: |
    parallelism.default: 4
    taskmanager.numberOfTaskSlots: 4
    state.backend: rocksdb
    state.checkpoints.dir: hdfs:///flink/checkpoints
  log4j2.properties: ...
```

**Application 模式**（每个作业独立集群，隔离更好）：

```bash
bin/flink run-application -t kubernetes-application \
    -c com.example.Main \
    k8s://namespace/ \
    hdfs:///path/to/job.jar
```

| K8s 模式 | 特点 | 适用 |
| --- | --- | --- |
| **Session** | 提前起好 JM/TM，作业 Submit 即分配 Slot | 作业多、生命周期短 |
| **Application** | 每个作业独立 Pod，结束自动释放 | 生产推荐 |
| **Per-Job** | 已废弃，用 Application 代替 | - |

## JM / TM 数量规划

### JM

| 数量 | 场景 |
| --- | --- |
| 1 | 本地调试 / Standalone 非 HA |
| 2+ | **生产必须 HA**：Active + Standby；ZK 或 K8s Leader Election 选主 |

JM 负责：

- 接收作业提交
- 向 ResourceManager 申请 Slot
- 触发 Checkpoint
- 运行时状态监控

JM 内存需求**不大**（1~4GB 通常足够），但 CPU 不能太低（作业提交、Checkpoint 协调都是 CPU 密集）。

### TM 数量

TM 数量的本质：**总 Slot 数 = 并行度 × N（N 是冗余倍数）**

```
假设最大并行度需求 = 16，SlotSharingGroup 无隔离：
  - 冗余 20% → 总 Slot ≈ 20
  - 每 TM Slot = CPU 核数（比如 8 核）
  - TM 数量 = ceil(20 / 8) = 3 台
```

### Slot 预算

```
总 Slot ≥ max(所有算子的并行度) × SlotSharingGroup 数
```

> **规则 1**：Sink 并行度通常和 Source 对齐。
> **规则 2**：大算子（ProcessFunction、异步 IO）可以单独占 SlotSharingGroup。
> **规则 3**：不要把并行度压到极限，至少留 10% 余量。

## TaskManager 内存分配

TM 内存是**生产调优的核心**：

```
┌──────────────────────────────────────────────┐
│  TaskManager 总内存 (Total Memory)            │
│  ┌──────────────┐  ┌──────────────────────┐  │
│  │ Heap Memory  │  │   Off-Heap Memory     │  │
│  │ (堆内存)       │  │  ┌────────────────┐  │  │
│  │              │  │  │ Managed Memory  │  │  │
│  │              │  │  │ (RocksDB 用)     │  │  │
│  │              │  │  ├────────────────┤  │  │
│  │              │  │  │ Network Buffer  │  │  │
│  │              │  │  │ (网络传输缓冲)   │  │  │
│  │              │  │  └────────────────┘  │  │
│  │              │  │  + JVM Metaspace    │  │
│  │              │  │  + JVM Overhead     │  │
│  └──────────────┘  └──────────────────────┘  │
└──────────────────────────────────────────────┘
```

### 各部分怎么配

| 部分 | 配置项 | 默认 | 建议 |
| --- | --- | --- | --- |
| **Total Memory** | `taskmanager.memory.process.size` | 1728mb | 每 TM 8~32GB |
| **Heap** | `taskmanager.memory.task.heap.size` | (自动) | 给算子、对象；8GB 机器堆约 3GB |
| **Managed** | `taskmanager.memory.managed.size` | (自动) | RocksDB 用；至少 1~2GB/Slot |
| **Network** | `taskmanager.memory.network.size` | 1024mb | 网络缓冲；大流量加 |
| **Overhead** | `taskmanager.memory.process.size - 其他` | 自动 | 必须留，否则 OOM Kill |

### RocksDB 内存调优

```properties
# RocksDB 吃的是 Managed Memory
taskmanager.memory.managed.size: 4gb

# RocksDB 预定义（根据你的磁盘）
state.backend.rocksdb.predefined-options: FLASH_SSD_OPTIMIZED

# 手动调（可选）
state.backend.rocksdb.localdir: /data1,/data2,/data3
taskmanager.disk.flush-sync: false   # 提升 checkpoint 吞吐
```

**RocksDB 内存模型**：

| 组件 | 作用 | 约占 Managed % |
| --- | --- | --- |
| Block Cache | SST 文件数据读缓存 | ~50% |
| Write Buffer (MemTable) | 写缓冲，满了 flush 成 SST | ~30% |
| Index/Filter Block | SST 的元数据 | ~15% |
| Bloom Filter | 快速判断 Key 是否在 SST 中 | ~5% |

## JVM 参数建议

```properties
# flink-conf.yaml 里
env.java.opts.all: "-XX:+UseG1GC -XX:MaxGCPauseMillis=200 -XX:+ParallelRefProcEnabled -XX:+DisableExplicitGC"
env.java.opts.jobmanager: "-XX:+UseG1GC -Xlog:gc*:file=/var/log/flink/gc-jm.log:time,uptime:filecount=3,filesize=100M"
env.java.opts.taskmanager: "-XX:+UseG1GC -Xlog:gc*:file=/var/log/flink/gc-tm.log:time,uptime:filecount=3,filesize=100M"
```

| GC | 适用场景 | 特点 |
| --- | --- | --- |
| **G1GC** | Flink 默认推荐，通用 | 可预测停顿时间；大堆（> 8GB）首选 |
| **ZGC** | 超大堆（> 16GB），超低延迟 | 暂停时间 < 10ms，但 CPU 开销高 |
| **ParallelGC** | 小堆 | 吞吐高但停顿不可预测 |

> **生产规则**：堆 > 8GB 用 G1，> 16GB 考虑 ZGC。

## K8s 资源请求

```yaml
# TM Pod 的 resources
resources:
  requests:
    memory: "16Gi"    # = Total Memory + Overhead
    cpu: "8"
  limits:
    memory: "18Gi"    # 稍大于 requests，避免 OOM Kill
    cpu: "8"
```

> **K8s 内存 Overhead**：Flink 会申请 Total Memory（Heap + Managed + Network），但 JVM 还要 Metaspace、Thread Stack、Direct Memory。K8s Pod 的 `requests.memory` 必须比 `taskmanager.memory.process.size` 大 10~20%。

## 关键配置清单

```properties
# === JM ===
jobmanager.memory.process.size: 4gb
jobmanager.rpc.address: jm-host
jobmanager.rpc.port: 6123
jobmanager.heap.size: 2048mb      # 老配置，和上面对应

# === TM ===
taskmanager.numberOfTaskSlots: 4
taskmanager.memory.process.size: 16gb
taskmanager.memory.managed.size: 4gb
taskmanager.memory.network.size: 1gb
taskmanager.tmp.dirs: /data1,/data2,/data3

# === 全局 ===
parallelism.default: 4
execution.checkpointing.enabled: true
execution.checkpointing.interval: 60000
state.backend: rocksdb
state.checkpoints.dir: hdfs:///flink/checkpoints

# === HA ===
high-availability: org.apache.flink.runtime.highavailability.zookeeper.ZooKeeperHaServices
high-availability.storageDir: hdfs:///flink/ha/
high-availability.zookeeper.quorum: zk1:2181,zk2:2181,zk3:2181
```

## 常见问题

- **JM 挂了作业会怎样？** Standalone 非 HA：作业挂，需要重提。HA 模式：备 JM 从 Checkpoint 恢复作业，业务基本无感。
- **Slot 数 = CPU 核数吗？** 不一定。CPU 密集型建议 Slot ≤ 核数；IO 密集型（大量网络等待）可以多开（Slot = 核数 × 2~4），但要注意线程数上限。
- **RocksDB 用 Managed Memory 还是 Heap？** **必须用 Managed Memory**（Off-Heap），这样不会触发 Full GC。如果用 Heap，大 State 下 GC 会非常频繁。
- **K8s Session vs Application 怎么选？** 作业多、生命周期短（分钟级）选 Session；作业少、生命周期长（小时/天级）、需要隔离选 Application。
