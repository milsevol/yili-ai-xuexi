# 06 开源模型巡礼

## 一句话

**开源模型已经能覆盖 90% 的企业需求，选型的核心不是「哪个最强」，而是「许可能不能用、中文够不够好、显存装不装得下、生态好不好接」**。这一章给你一张能直接拿去做决策的对比表。

## 主流开源模型全景

| 模型 | 代表规格 | 上下文 | 许可 | 中文 | 特点 |
| --- | --- | --- | --- | --- | --- |
| **LLaMA 3.x** | 8B / 70B / 405B | 8K~128K | Llama 社区许可 | 中 | 生态最全，微调工具链支持最好 |
| **Qwen 2.5 / 3** | 0.5B~72B / MoE | 32K~128K | Apache 2.0（多数规格） | **强** | 中文与代码均衡，尺寸覆盖全 |
| **DeepSeek V2/V3/R1** | 236B MoE（激活 21B） | 64K~128K | MIT（V3/R1 系列） | **强** | 推理能力强，MoE 推理成本低 |
| **GLM-4** | 9B / 32B 等 | 128K | 各有不同 | **强** | 中文场景优化，工具调用完善 |
| **Mistral / Mixtral** | 7B / 8x7B MoE | 32K~128K | Apache 2.0 | 弱 | 欧洲生态，英文效率高 |
| **Gemma 2/3** | 2B / 9B / 27B | 8K~128K | Gemma 许可 | 中 | 单卡可跑，端侧友好 |
| **Phi 系列** | 3.8B / 14B | 128K | MIT | 弱 | 小参数推理强，适合边缘 |

> 具体规格与许可会随版本变化，落地前务必查官方 Model Card——**许可是法律问题，不是技术偏好**。

## 选型四道闸

```
① 许可能不能商用？
   ├─ Apache 2.0 / MIT → 基本无限制
   ├─ Llama 社区许可 → 需看月活阈值与命名要求
   └─ 非商用 / 研究许可 → 直接淘汰（商用场景）
        ↓
② 中文能力够不够？
   ├─ 中文为主 → Qwen / GLM / DeepSeek 优先
   └─ 英文为主 → LLaMA / Mistral / Gemma
        ↓
③ 显存装得下吗？
   ├─ 单卡 24G → 7B~9B（BF16 需 ~18G）
   ├─ 单卡 48G~80G → 32B / 70B 量化
   └─ 多卡 → 70B+ 或 MoE
        ↓
④ 生态好不好接？
   ├─ 推理：vLLM / SGLang 是否已支持该架构
   ├─ 微调：LLaMA-Factory / transformers 是否内置模板
   └─ 工具调用：是否支持 function calling 模板
```

### 显存估算（推理）

```
BF16 权重显存 ≈ 参数量 × 2 GB
INT8          ≈ 参数量 × 1 GB
INT4          ≈ 参数量 × 0.5 GB
+ KV Cache（随上下文线性增长，长文本场景不可忽略）
```

| 模型规模 | BF16 | INT8 | INT4 |
| --- | --- | --- | --- |
| 7B | ~14 GB | ~7 GB | ~4 GB |
| 14B | ~28 GB | ~14 GB | ~8 GB |
| 32B | ~64 GB | ~32 GB | ~18 GB |
| 70B | ~140 GB | ~70 GB | ~38 GB |

> 实际还要加 10-20% 的框架开销与 KV Cache；70B 用 INT4 跑在单张 48G 卡上很勉强，长上下文一定 OOM。

## 常见组合方案

| 场景 | 推荐 | 理由 |
| --- | --- | --- |
| 个人学习 / 原型 | Qwen 7B / Gemma 9B（INT4） | 单卡可跑，中文够用 |
| 企业知识库问答 | Qwen 14B~32B + RAG | 中文强 + 32K 上下文够塞片段 |
| 代码助手 | Qwen-Coder / DeepSeek-Coder | 代码语料配比高 |
| 复杂推理 / 数学 | DeepSeek R1 系列 | 显式推理链，长思考 |
| 高并发低成本 | MoE 模型 + vLLM 张量并行 | 激活参数少，吞吐高 |
| 端侧 / 隐私本地 | Gemma 2B / Phi-3.5-mini | 内存与算力友好 |

## 评估：别只看榜单

榜单（MMLU、C-Eval、GSM8K）只能做初筛，真正的选型要靠**自己的业务评估集**：

```python
# 最小可用评估脚本框架
import json
from statistics import mean

def evaluate(model_call, cases, judge):
    """cases: [{"question": ..., "reference": ...}]"""
    results = []
    for c in cases:
        answer = model_call(c["question"])
        score = judge(c["question"], answer, c["reference"])  # 人工规则或 LLM 打分
        results.append({"q": c["question"], "a": answer, "score": score})
    return {
        "avg_score": round(mean(r["score"] for r in results), 3),
        "badcases": [r for r in results if r["score"] < 0.6],
    }
```

建议评估维度：

| 维度 | 说明 |
| --- | --- |
| 任务准确率 | 你的真实业务题，≥ 100 条 |
| 指令遵循 | 格式、长度、角色约束是否守住 |
| 中文表达 | 术语正确性、书面语自然度 |
| 幻觉率 | 不知道时是否承认 |
| 延迟与成本 | P95 延迟、每千 token 成本 |
| 工具调用 | function calling 成功率（Agent 场景） |

## FAQ

**Q：开源模型能追上闭源吗？**
A：通用能力差距在缩小，但闭源在长上下文稳定性、工具调用鲁棒性、多模态上仍领先。判断标准应是「你的任务上差多少」，不是「榜单差多少」。

**Q：MoE 模型是不是更省钱？**
A：推理时激活参数少、吞吐高，但**显存按总参数算**，小规模部署反而更贵。适合高并发场景。

**Q：许可里的「月活 7 亿」条款怎么理解？**
A：Llama 社区许可对超大平台有额外要求。中小企业基本不受影响，但**要留存合规记录**，别假设「开源 = 随便用」。

**Q：中文模型一定要用国产的吗？**
A：不一定，但中文语料配比与分词效率上，Qwen/GLM/DeepSeek 通常更划算；LLaMA 需要更多中文微调数据才能追平。

**Q：模型版本升级会不会破坏我的微调成果？**
A：会。换底座等于换 tokenizer 与权重分布，SFT/LoRA 都要重训。选型时优先选**版本迭代稳定、尺寸齐全**的模型家族。
