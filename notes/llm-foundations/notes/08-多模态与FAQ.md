# 08 多模态与FAQ

## 一句话

**多模态的核心思路是「把不同模态都变成 token 序列，塞进同一个 Transformer」**：图像切成 patch 当视觉 token，语音切成帧当音频 token，然后和文本 token 一起做注意力。它不是新范式，而是同一套 Transformer 的输入扩展。

## 视觉语言模型（VLM）

### 三段式架构

```
图片 → 视觉编码器（ViT/CLIP）→ patch 特征
                                    ↓
                          投影层（MLP / Q-Former）
                                    ↓
                    视觉 token + 文本 token 拼在一起
                                    ↓
                            LLM 解码输出文本
```

| 组件 | 作用 | 代表 |
| --- | --- | --- |
| 视觉编码器 | 把图切成 patch 并编码 | ViT、SigLIP、CLIP ViT |
| 投影/对齐层 | 把视觉特征映射到 LLM 的词嵌入空间 | MLP（LLaVA）、Q-Former（BLIP-2） |
| LLM 主干 | 统一做多模态推理 | Qwen-VL、LLaVA、InternVL |

### 训练两阶段（以 LLaVA 为例）

| 阶段 | 冻结什么 | 训练什么 | 数据 |
| --- | --- | --- | --- |
| ① 对齐预训练 | 视觉编码器 + LLM | 只训投影层 | 图文对（描述级） |
| ② 指令微调 | 视觉编码器 | 投影层 + LLM | 多模态指令数据（VQA、对话） |

### 视觉 token 的代价

```
一张 1024×1024 图，patch=14 → 约 (1024/14)² ≈ 5300 个 patch
经池化后常见 256~2048 个视觉 token
```

这直接影响成本和上下文：**图片越多、分辨率越高，吃掉的上下文越多**，长文档 OCR 类任务尤其明显。

## 语音：Whisper 与语音对话

| 环节 | 代表模型 | 说明 |
| --- | --- | --- |
| 语音识别 ASR | Whisper | 音频 → 梅尔频谱 → Encoder-Decoder → 文本 |
| 语音合成 TTS | CosyVoice / FishSpeech | 文本 → 声学特征 → 波形 |
| 端到端语音对话 | Qwen-Audio / GPT-4o audio | 音频 token 直接进 LLM，保留语气情绪 |

关键差异：传统级联（ASR → LLM → TTS）延迟高、丢情绪；端到端把音频当 token，能感知语气但训练数据要求高。

## 文生图简述

```
文本 → 文本编码器（CLIP/T5）→ 条件向量
                                  ↓
噪声潜变量 → Diffusion 去噪（多步）→ VAE 解码 → 图像
```

| 概念 | 作用 |
| --- | --- |
| Latent Diffusion | 在压缩潜空间去噪，算力降一个量级 |
| Classifier-Free Guidance | 控制「贴合提示词」的强度 |
| LoRA / ControlNet | 风格定制 / 结构控制（姿态、深度图） |

> 文生图与 LLM 是两条技术线（扩散模型 vs 自回归），只是都在「生成」这个大类下。

## 多模态能力边界

| 能做 | 不能做（或很不可靠） |
| --- | --- |
| 图片描述、图表读数（清晰时） | 高精度像素级测量 |
| 文档 OCR 与版面理解 | 手写潦草文本的稳定识别 |
| 视频关键帧问答 | 长视频细粒度时序推理 |
| 语音转写与情绪粗判 | 多人重叠语音分离 |

## 面试 FAQ

**Q1：Transformer 的 Self-Attention 为什么要除以 √d_k？**
A：点积随维度增大方差变大，softmax 会饱和到接近 one-hot，梯度消失。除以 √d_k 把方差归一化到 1 左右，训练更稳。

**Q2：多头注意力（MHA）的意义是什么？**
A：不同头学习不同的关注模式（语法、指代、位置），拼起来表达更丰富；单头只能学一种平均关系。

**Q3：为什么 Decoder-only 成为主流，而不是 Encoder-Decoder？**
A：训练目标统一（next token）、可无缝做生成与对话、工程实现简单、Scaling 表现好；Encoder-Decoder 的优势在翻译类「输入输出结构清晰」的任务上。

**Q4：位置编码为什么从正弦改成 RoPE？**
A：RoPE 用旋转把相对位置编码进 Q·K 内积，天然表达相对距离，外推性更好，且实现开销小。

**Q5：LayerNorm 放在 Attention 前还是后？**
A：Post-LN 训练不稳需精调 warmup；Pre-LN（现代主流）梯度更稳、可堆更深，代价是表达略有差异。

**Q6：BPE 和 WordPiece 的区别？**
A：BPE 合并最高频相邻对；WordPiece 合并「使语言模型似然提升最大」的对。结果相似，训练准则不同。

**Q7：为什么中文模型词表里常见单字 token？**
A：中文没有空格，整词组合爆炸；单字 + 常用词组合能覆盖更大表达空间，但序列变长，需靠更大词表与更好训练弥补。

**Q8：Scaling Law 能预测「能力涌现」吗？**
A：不能精确预测。Loss 平滑下降，但特定任务（如多步算术）可能出现非线性跃升，这是当前研究的开放问题。

**Q9：SFT 和 RLHF 的本质区别？**
A：SFT 是「模仿」（最大化标准答案的似然）；RLHF 是「偏好优化」（在好/坏答案之间拉开差距），能表达「哪个更好」而不仅是「这个对」。

**Q10：为什么推理要 KV Cache，训练不需要？**
A：训练是并行处理整条序列（一次前向拿到所有位置），缓存无意义还会占显存；推理是逐 token 串行，历史 K/V 必须复用否则重复计算。

**Q11：temperature 和 top_p 同时设会怎样？**
A：两者是串联过滤：先按温度缩放分布，再按 top_p 截断。同时设会过度收窄，通常只调一个。

**Q12：MoE 相比 Dense 模型的优劣？**
A：优：同算力下总参数更大、容量更高、推理激活少；劣：显存按总参数算、负载均衡难、训练与推理工程复杂度高。

## 学完本主题之后

```
Transformer 原理 ✅
   ├─→ 提示词工程：在输入侧做优化，零训练成本
   ├─→ 微调技术：LoRA/QLoRA/DPO，在参数侧做优化
   ├─→ 向量库 + RAG：在知识侧做补充
   └─→ Agent：在能力侧做组合
```

**一句话总结**：模型原理决定了「能力的上限」，Prompt/RAG/Agent 决定了「能不能把上限用出来」。
