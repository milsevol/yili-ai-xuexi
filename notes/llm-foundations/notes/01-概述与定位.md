# 01 概述与定位

## 一句话

**大语言模型（LLM）是用 Transformer 架构在海量文本上做「下一个词预测」训练出的概率模型**，它把 NLP 从「一个任务训一个模型」带入「一个通用模型 + Prompt 解决所有任务」的时代。理解 LLM 能做什么、不能做什么，是学习后续所有章节的前提。

## 大模型时代：为什么是现在

三个要素在同一时间点成熟，缺一不可：

| 要素 | 关键事件 | 作用 |
| --- | --- | --- |
| 算法 | 2017 Transformer 论文《Attention Is All You Need》 | 并行化训练、长程依赖建模，取代 RNN/LSTM |
| 算力 | GPU 显存与互联（NVLink/InfiniBand）逐年翻倍 | 单集群可训练千亿参数模型 |
| 数据 | CommonCrawl、书籍、代码等万亿 token 语料 | 「大力出奇迹」的燃料 |

关键时间线：

```
2017  Transformer 论文发布
2018  BERT（3.4 亿参数，理解任务）/ GPT-1（1.17 亿，生成任务）
2019  GPT-2（15 亿，"太危险不公开"的营销出圈）
2020  GPT-3（1750 亿，Few-shot 涌现，不用微调就能干活）
2022  ChatGPT（RLHF 对齐，2 个月 1 亿用户）
2023  GPT-4 / LLaMA 开源 / 百模大战
2024  GPT-4o 多模态 / DeepSeek-V2 价格战 / o1 推理模型
2025  DeepSeek-R1 开源推理模型 / Agent 元年
```

**核心范式转移**：GPT-3 证明了「规模本身就是能力」——模型大到一定程度后，涌现出小模型不具备的上下文学习（In-context Learning）、思维链（Chain-of-Thought）等能力。

## LLM 能做什么

| 能力 | 典型场景 | 可靠性 |
| --- | --- | --- |
| 文本生成 | 文案、邮件、报告、翻译、摘要 | 高（需人工校对） |
| 代码生成 | 补全、重构、写测试、解释代码 | 高（主流 IDE 已集成） |
| 知识问答 | 概念解释、学习辅导、方案对比 | 中（可能幻觉） |
| 推理规划 | 数学解题、多步分析、Agent 任务拆解 | 中→高（推理模型大幅提升） |
| 信息抽取 | 从非结构化文本提字段、分类、打标 | 高（配合结构化输出） |
| 多语言 | 跨语言翻译、跨语言检索 | 高 |

## LLM 不能做什么（边界与误区）

| 短板 | 说明 | 工程对策 |
| --- | --- | --- |
| 幻觉（Hallucination） | 会编造看似合理的错误事实、文献、法条 | RAG 检索增强、引用溯源、人工核验 |
| 知识截止 | 训练数据有截止日期，不知道最新事件 | RAG / 联网搜索工具 |
| 精确计算 | 多位数乘法、长串计数经常出错 | 调用计算器/代码解释器等工具 |
| 确定性输出 | 同样输入可能给不同输出（采样机制） | temperature=0 + 结构化输出约束 |
| 长上下文遗忘 | 声称支持 128K 但中间内容易"丢失"（Lost in the Middle） | 关键信息放开头/结尾、分块处理 |
| 真实世界行动 | 本身只能输出文本，不能操作数据库/API | Function Calling / Agent 框架 |
| 隐私合规 | 直接调用云端 API 有数据出域风险 | 私有化部署开源模型 |

**最重要的认知**：LLM 是**概率模型**，不是数据库，也不是规则引擎。它输出的是「统计上最可能的下一个词」，不是「事实」。

## 与传统 NLP 的范式差异

| 维度 | 传统 NLP（2018 前） | 预训练微调（BERT 时代） | 大模型时代（GPT-3 后） |
| --- | --- | --- | --- |
| 模型 | 每任务单独训练（分词器、NER、分类器） | 一个预训练模型 + 每任务微调 | 一个模型 + Prompt 通吃 |
| 数据需求 | 大量标注数据 | 中等标注数据微调 | 零样本/少样本即可 |
| 泛化能力 | 弱，换领域重训 | 中，需少量领域数据 | 强，Prompt 描述任务即可 |
| 工程成本 | 算法团队 + 训练管线 | 微调管线 | API 调用 / Prompt 工程 |
| 典型代表 | jieba + CRF + TextCNN | BERT / ERNIE | GPT / Qwen / DeepSeek |

```
传统 NLP:   任务 A → 标注数据 A → 训练模型 A → 只能做任务 A
BERT 时代:  通用预训练 → 任务 A 微调 → 模型 A（每个任务一份副本）
LLM 时代:   一个基座模型 → 写好 Prompt → 同时做任务 A/B/C/...
```

## 大模型应用的技术栈分层

从底向上，越往上越贴近业务：

```
L1 基础设施层：GPU 集群、RDMA 网络、CUDA、Megatron/DeepSpeed
L2 模型层：    基座模型（Qwen/DeepSeek/LLaMA）+ 微调（SFT/LoRA）
L3 能力层：    RAG（检索增强）、Function Calling、Prompt 工程
L4 应用层：    ChatBot、Copilot、Agent、垂直行业应用
```

本主题聚焦 **L2 模型层的原理**（Transformer、Tokenizer、预训练、对齐），并覆盖 L3 必需的推理基础知识（采样、KV Cache）。

## 常见误区

**误区 1：LLM 在"理解"语言。**
更准确的说法是：LLM 学到了语言和世界知识的统计规律，表现出类似理解的行为。是否算"理解"是哲学问题，工程上只关心它能否稳定完成任务。

**误区 2：参数越大越好。**
7B 模型在特定任务上微调后常常超过通用的 70B。选型要看任务匹配度、成本、延迟，不是单纯比大小（详见第 06 章）。

**误区 3：Prompt 工程是玄学。**
Prompt 有明确的工程方法论：角色设定、Few-shot 示例、思维链、结构化输出。本质是用自然语言"编程"模型的条件概率分布。

**误区 4：自己训练一个模型很便宜。**
从零预训练一个可用模型最少数百万美元（详见第 04 章成本估算）。99% 的团队应该基于开源模型做微调和 RAG。
