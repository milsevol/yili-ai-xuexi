# 05 上线验收与 FAQ

## 一句话

**上线验收不是"功能点都点过一遍"，而是用清单证明四件事：越权进不来、故障扛得住、成本算得清、出问题查得到。** 本章给出一份可直接照着执行的准入清单、压测与演练方案，以及评审时最常被追问的问题。

## 上线准入清单

### 功能与流程

- [ ] 租户、用户、角色可以正常开通与变更，离职用户即时失效
- [ ] Agent 五个状态流转全部走服务端校验，前端无法绕过
- [ ] 只有租户管理员能审批，开发者不能自审自发
- [ ] 已下线 Agent 无法被调用，历史运行记录仍可查
- [ ] MCP 停用后，引用它的 Agent 调用会明确提示"工具不可用"

### 权限与安全

- [ ] 跨租户读写全部返回 403，且每次都有审计
- [ ] 创建 Agent 时只能选本租户已启用且有权限的工具
- [ ] 运行时逐工具二次鉴权，越权调用被拦截
- [ ] 工具凭据只存在网关，日志与前端不出现明文
- [ ] 出网白名单生效，平台无法访问任意外网
- [ ] 提示词注入用例集跑过，未出现越权工具调用

### 合规与审计

- [ ] 所有输出带"AI 生成"标识与免责声明
- [ ] 运行记录能定位到：谁、何时、哪个 Agent 版本、调了哪些工具、用的哪份数据
- [ ] 审计日志只追加不修改，保留期满足监管要求
- [ ] 审计写入失败时相关写操作被阻断，而不是静默丢日志

### 运维与成本

- [ ] 健康检查、监控指标、告警规则全部生效并演练过一次
- [ ] 备份可恢复，且做过一次真实恢复演练
- [ ] 单次调用成本可归集到租户与 Agent，日预算告警生效
- [ ] 发布与回滚脚本可用，回滚时间在目标 RTO 内

## 压测方案

| 场景 | 并发 | 目标 | 观察点 |
| --- | --- | --- | --- |
| 短问答（单工具） | 20 | P95 ≤ 5s，成功率 ≥ 99% | API 与模型网关延迟 |
| 多工具链路（3 工具） | 10 | P95 ≤ 12s | 工具串行耗时、超时率 |
| 长任务提交 | 50 次/分钟 | 队列不丢、可查询进度 | 队列积压与 worker 扩容 |
| 权限拦截风暴 | 100 QPS | 403 稳定、审计不丢 | 审计写入能力 |
| 单租户打满配额 | 1 租户 | 只影响自己，其他租户不受影响 | 限流隔离 |

压测通过标准：**错误率 ≤ 1%，P95 达标，且租户间无相互影响**。只压总 QPS 不压隔离，等于没压。

## 灰度策略

```
第 1 天：1 个租户 + 10 个内部用户，观察错误率与拦截率
第 2 天：扩到 1 个部门，观察采纳率与成本
第 3 天：全量，保留一键回滚开关
```

灰度期间重点看三个数：运行成功率、人工采纳率、单次成本。任何一个明显劣化就停。

## 故障演练

| 故障 | 注入方式 | 期望行为 |
| --- | --- | --- |
| 模型供应商不可用 | 网关返回 429/503 | 主备切换；全挂时明确报错，不返回编造答案 |
| MCP 工具超时 | 延迟 30s | 8s 超时、重试 1 次、降级并标注数据缺失 |
| 数据库主库切换 | 手动切换 | 30s 内恢复，运行记录不丢 |
| 审计写入失败 | 断开审计表写入权限 | 相关写操作被阻断并告警 |
| 越权访问 | 用 A 租户 token 访问 B 租户资源 | 403 + 审计 + 告警 |
| 提示词注入 | 工具结果中嵌入"忽略以上指令" | 不触发越权工具调用 |

每项演练都要留下记录：注入方式、观察到的行为、是否符合预期、修复项。

## FAQ

**Q1：为什么不直接用 Dify / Coze，非要自研？**
A：如果只是几个部门做 Demo，直接用没问题。金融场景的差异在于：多租户强隔离、内网工具接入、审批与审计、成本归集到部门。这些开源产品要么不支持，要么需要改到接近重写。常见做法是"自研平台壳 + 复用成熟运行时"，而不是从零写 Agent 框架。

**Q2：Agent 上架审核到底审什么？**
A：四件事：工具权限是否最小、系统提示词是否包含合规约束与拒答规则、是否声明数据来源与引用方式、是否配置了评测集。四项缺一就驳回，并在审核意见里写清楚。

**Q3：开发者能不能给自己创建的 Agent 加任意工具？**
A：不能。创建时校验"本租户已启用 + 创建人有权限"，运行时再按调用人的 scope 校验一次。这样即使 Agent 被转授，也不会扩大数据权限。

**Q4：MCP 工具挂了怎么办？**
A：单工具超时 8s、只对幂等工具重试 1 次、连续失败熔断 30s。熔断期间快速失败并降级，答案里标注"该部分数据不可用"，不允许模型编造。

**Q5：多租户用逻辑隔离够吗？**
A：当前规模够用。前提是四层都做到：请求上下文注入、数据库 RLS 兜底、检索强制 filter、日志带租户标识。大租户或强监管客户再升级为独立 namespace 或独立集群。

**Q6：怎么防止 Agent 被用来套取数据？**
A：工具返回做脱敏与截断，敏感字段按角色裁剪；限制单次结果条数与总 token；对高频、异常模式的调用做检测；审计可按用户回放。平台不提供"任意 SQL"类工具。

**Q7：成本怎么控制？**
A：四道闸：租户 QPS 与日 token 硬上限、Agent 级预算、运行时 token 预算与工具结果压缩、模型路由（简单任务走小模型）。成本按租户 / Agent / 用户三维归集，月底能对账。

**Q8：Agent 回答错了怎么追责？**
A：运行记录保存完整步骤（工具、参数摘要、返回摘要、模型版本、提示词版本），可以精确复现。责任划分是：平台负责链路与权限，开发者负责提示词与工具选择，业务方负责人工复核与最终发布。

**Q9：能不能让业务方自己写代码接工具？**
A：可以，但只能通过注册 MCP 的方式，且在独立沙箱里运行。禁止业务代码直接连生产库，也禁止把凭据写进 Agent 配置。

**Q10：平台上线后，第一个月最该盯什么？**
A：三个数：跨租户拦截次数（应为 0 之外的异常突增）、运行成功率、单次成本。前两个决定能不能继续用，后一个决定能不能长期用。

**Q11：创建完 Agent 之后，业务方到底怎么用？**
A：三条路径，前提都是**已通过审核上线**：

1. **平台内调试台**：选 Agent → 输入问题 → 查看 thought / action / observation 与最终答复，适合验证与演示。
2. **OpenAPI**：业务系统直接调用 `POST /api/runs`（生产换成 Bearer Token 或平台签发的 API Key），入参是 `agent_id` + `question`，返回答案、步骤、tokens 与耗时；长任务再换成异步任务接口。
3. **嵌入业务系统**：把同一接口封装成企微机器人、CRM 侧边栏、投研工作台的一个按钮，前端只负责传问题和展示引用。

调用时平台会重新做一次运行时鉴权：调用人没有工具 scope 就直接拦截，不会因为"Agent 已上线"就放大权限。Demo 的调试台里展开「查看 API 调用方式」就能看到 curl 示例。

## 评审常被追问的五个问题

| 问题 | 回答要点 |
| --- | --- |
| 和现有 AI 中台是什么关系？ | 平台是中台的"应用编排层"，模型与数据仍由中台提供 |
| 出事故谁负责？ | 平台负责链路与权限，业务方负责内容与发布，合规负责抽查 |
| 为什么审批不能自动化？ | 一期人审建立基线；积累评测集后可对低风险 Agent 开放自动发布 |
| 如何证明隔离有效？ | 越权测试用例 + 审计记录 + 定期红队演练 |
| 迁移成本高吗？ | Agent 与 MCP 都是配置资产，可导出；运行时无状态，迁移只换存储与网关 |

## 演进路线

```
一期：租户 + Agent/MCP 上架 + 调试 + 审计（本主题）
二期：评测集与自动门禁、版本灰度、成本看板
三期：跨租户 Agent 市场、模板市场、自动生成 Agent
四期：多模态工具、复杂工作流编排、Agent 间协作
```

每一期都以"治理能力跟得上"为前提，而不是先放开再补权限。

## 本章对应演示

```bash
cd notes/agent-platform
./start.sh --reset
```

把清单变成可操作的自检：

1. **越权**：切「王研（研究员）」调用「财报对比助手」，应看到权限拦截并写入审计；
2. **跨租户**：切「陈璐（t-am 管理员）」，看不到 t-sec 的任何 Agent；
3. **状态机**：草稿状态的 Agent 没有"通过并上线"按钮，接口直接调用也会 409；
4. **停用工具**：管理员停用「财报中心」后，再调用相关 Agent，运行记录出现"工具不可用"；
5. **审计**：以上动作在审计页均可按时间追溯。
