# 01 项目需求与业务场景

## 一句话

**在金融集团内部建一个垂直 Agent 平台：平台方提供模型、工具、知识库、运行时与审计，业务部门不再各自造轮子，而是通过"注册 MCP → 创建 Agent → 提交审核 → 上线调用"自助完成 AI 应用落地。** 项目的难点不是把 Agent 跑起来，而是让几十个业务团队在同一套底座上安全、可控、可计量地跑起来。

## 业务背景

集团内 8 个业务部门（研究所、资管、财富管理、合规、运营、客服、风控、IT）在过去一年各自做 AI 应用，出现四个典型问题：

| 问题 | 具体表现 | 平台要解决的 |
| --- | --- | --- |
| 重复建设 | 每个部门都自己接模型、写 RAG、搭工具调用 | 模型网关 + 知识库 + 工具注册中心统一提供 |
| 数据越权 | 应用直接连数据库，权限绕过业务系统 | 工具网关统一鉴权，Agent 拿不到直连凭据 |
| 不可审计 | 出了错误回答查不到是谁、调了什么、用了哪份数据 | 全链路 trace + 审计日志 |
| 无法复用 | 行情、财报、研报工具在每个项目里重写 | MCP 标准化注册，一次接入多处复用 |

平台不做"万能助手"，只做**底座 + 治理**：把能力做成可注册、可授权、可观测的资产，把上线变成一个有审批的流程。

## 平台定位

```
┌─────────────────────────────────────────────────────────┐
│  业务方（研究所 / 资管 / 合规 / 客服）                    │
│  创建 Agent、编排提示词、选工具、调试、上线               │
├─────────────────────────────────────────────────────────┤
│  平台方（IT / 数据中台）                                  │
│  模型网关 · MCP 网关 · 知识库 · 运行时 · 权限 · 审计      │
├─────────────────────────────────────────────────────────┤
│  基础设施：K8s · PostgreSQL · Redis · 对象存储 · 向量库    │
└─────────────────────────────────────────────────────────┘
```

**做什么**：多租户隔离、Agent 生命周期管理、MCP 工具注册与授权、调试与运行、审计与配额、模型统一接入。

**不做什么**（写进项目范围，避免无限扩张）：

- 不做模型训练与微调，模型能力由集团模型网关提供。
- 不做业务系统的数据治理，行情/财报/研报仍由原系统负责。
- 不直接产出投资建议、交易指令，输出物必须标注"AI 生成、人工复核"。
- 一期不做跨租户共享 Agent 市场，只做租户内上架。

## 角色与职责

| 角色 | 典型人 | 关键操作 | 权限边界 |
| --- | --- | --- | --- |
| 平台管理员 | 集团 IT | 租户开通、模型与配额配置、全局审计 | 不进入租户业务数据 |
| 租户管理员 | 部门负责人 / 数据管理员 | 审批 Agent 上架、启停 MCP、管理成员 | 仅本租户 |
| Agent 开发者 | 业务分析师 / 应用开发 | 注册 MCP、创建 Agent、调试、提交审核 | 只能用已授权工具 |
| 业务用户 | 研究员 / 客服 / 合规 | 调用已上线 Agent、反馈结果 | 只能调用已发布 Agent |
| 合规审计 | 合规部 | 查审计、抽查回答与工具调用 | 只读，跨租户需二次授权 |

> 平台遵循最小权限：**开发者能定义 Agent，但不能自己发布；管理员能发布，但不默认拥有业务数据权限**。这两个权限分离是金融场景的硬要求。

## 典型场景

| 场景 | 归属租户 | 输入 | 期望输出 | 依赖工具 | 调用方式 |
| --- | --- | --- | --- | --- | --- |
| 个股速览 | 研究所 | "宁德时代最近行情和研报观点" | 结论 + 事实 + 引用 | 行情、研报检索 | 同步，P95 ≤ 15s |
| 财报对比 | 研究所 | "对比三家公司近三年毛利率和现金流" | 结构化对比表 | 财报、计算器 | 同步/异步 |
| 合规审查 | 合规部 | 营销话术 / 投顾材料 | 命中条款 + 整改建议 | 合规规则库 | 同步，必须人工复核 |
| 固收晨报 | 资管 | 定时触发 | 晨报草稿 | 债券行情、研报检索 | 定时异步 |
| 客服工单 | 客服中心 | 客户问题 | 答复草稿 + 转人工判断 | 知识库、工单系统 | 同步，P95 ≤ 5s |

场景选择遵循一条原则：**先做"有明确工具、有可核验数据、有人工复核"的任务**。开放式创作、无数据支撑的判断，一期不做。

## 功能需求

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| FR-01 | 租户管理：开通、配额、成员与角色 | P0 | 跨租户数据不可见 |
| FR-02 | MCP 注册：名称、传输方式、端点、scope | P0 | 注册后默认未启用，管理员启用 |
| FR-03 | 工具目录：按租户聚合已启用工具 | P0 | 工具名全局唯一（租户内） |
| FR-04 | Agent 创建：名称、描述、系统提示词、选工具 | P0 | 只能选本租户已启用工具 |
| FR-05 | 生命周期：草稿 → 待审核 → 上线 / 驳回 / 下线 | P0 | 状态流转不可跳过 |
| FR-06 | 审核：通过、驳回、填写意见 | P0 | 只有租户管理员可操作 |
| FR-07 | 调试：选择已上线 Agent 运行，展示完整步骤 | P0 | thought/action/observation 可回溯 |
| FR-08 | 运行时鉴权：逐工具校验角色 scope | P0 | 越权调用被拦截并审计 |
| FR-09 | 审计：治理动作与拒绝事件留痕 | P0 | 可按租户、时间、操作人查询 |
| FR-10 | 版本管理：每次发布版本 +1 | P1 | 可回滚到上一版本 |
| FR-11 | 配额与限流：租户级 QPS、日 token 上限 | P1 | 超限返回明确错误 |
| FR-12 | 评测：上线前跑固定评测集 | P2 | 质量分低于阈值阻断发布 |

## 非功能需求

| 维度 | 要求 | 示例目标 |
| --- | --- | --- |
| 数据隔离 | 租户间不可见 | 请求上下文、存储、检索、日志四层 |
| 审计 | 全链路可追溯 | 治理动作 100% 留痕，日志不可篡改 |
| 延迟 | 同步调用 | P50 ≤ 3s，P95 ≤ 10s（不含长任务） |
| 可用性 | 核心链路 | 99.9% / 月 |
| 扩展性 | 新增 MCP | 业务方自助完成，平台零改代码 |
| 成本 | 单次调用 | 可归集到租户与 Agent，月度硬上限 |
| 合规 | 输出 | 100% 带"AI 生成"标识与免责声明 |

## 验收指标

| 类型 | 指标 | 目标 |
| --- | --- | --- |
| 北极星 | 月活跃业务方（租户内活跃开发者 + 业务用户） | ≥ 60% |
| 效率 | 从注册 MCP 到首个 Agent 上线耗时 | ≤ 2 人日 |
| 质量 | 已上线 Agent 的人工采纳率 | ≥ 55% |
| 风控 | 跨租户越权成功次数 | 0 |
| 治理 | 未审批即上线的 Agent 数 | 0 |
| 成本 | 单次调用成本 P95 | ≤ 预算阈值 |

## 关键决策

| 决策点 | 选择 | 放弃的方案 | 理由 |
| --- | --- | --- | --- |
| 自研 vs 开源 | 自研平台壳，复用开源运行时 | 直接部署 Dify/Coze | 金融多租户、审计、内网工具接入需深度定制 |
| 工具标准 | MCP | 自定义 HTTP 插件协议 | 生态统一，stdio/http/sse 都能接 |
| 租户隔离 | 逻辑隔离 + 大租户独立 namespace | 每租户独立集群 | 成本可控，当前规模足够 |
| Agent 编排 | 显式状态机 | 让模型自由规划 | 需要审批、断点续跑、可回放 |
| 发布权限 | 开发者提交、管理员审批 | 开发者直接发布 | 合规要求 |

## 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 业务方把平台当"万能 API" | 范围失控、成本飙升 | 场景准入清单 + 配额 + 成本看板 |
| 工具权限声明过宽 | 数据越权 | scope 最小化 + 发布前权限评审 + 运行时二次校验 |
| Agent 回答不可信 | 业务不敢用 | 强制引用、评测集、人工复核、反馈回流 |
| 平台成为新瓶颈 | 上线排队 | 自助注册 + 模板化 + 审核 SLA |
