# 08 日历会议与审批

## 一句话

日历、会议、审批、考勤是企业 OA 的核心四件套。飞书把它们原生打通，通过 API 你能：创建日程并邀请参会人、发起视频会议、提交审批实例并监听审批结果回调、拉取员工打卡数据 —— 让你的业务系统和飞书 OA 双向联动。

## 日历 Calendar

接口前缀 `/open-apis/calendar/v4`。

### 核心概念

| 概念 | 说明 |
| --- | --- |
| 日历（Calendar） | 一个日历容器，用户可有多个日历（主日历、共享日历） |
| 日程（Event） | 日历上的一条事件，有时间、地点、参会人、提醒 |
| 参会人（Attendee） | 日程的参与者，可设必选/可选、会议室 |

### 创建日程并邀请参会人

```http
POST /open-apis/calendar/v4/calendars/{calendar_id}/events
Authorization: Bearer <token>
{
  "summary": "项目启动会",
  "description": "讨论 Q1 项目排期",
  "start_time": { "timestamp": "1700000000", "timezone": "Asia/Shanghai" },
  "end_time":   { "timestamp": "1700003600", "timezone": "Asia/Shanghai" },
  "attendees": [
    { "type": "user", "user_id": "ou_xxx", "is_optional": false }
  ],
  "reminders": [
    { "minutes": 10 }   // 提前 10 分钟提醒
  ],
  "vchat": { "vchat_type": "vc", "setting": { "host_type": "calendar_event_host" } }
}
```

`vchat` 字段不为空会自动创建一个飞书视频会议链接，随日程通知发给参会人。

### 日历事件订阅

- `calendar.event.changed_v4`：日程变更（创建/更新/删除）
- `calendar.calendar.acl.changed_v4`：日历权限变更

## 视频会议 VC

飞书会议可通过 API 预约和管理：

| 能力 | 接口 | 说明 |
| --- | --- | --- |
| 预约会议 | `POST /vc/v1/reserves/apply` | 预约会议时间、参会人 |
| 会议列表 | `GET /vc/v1/reserves` | 查已预约会议 |
| 会议纪要（妙记） | `GET /vc/v1/minutes/...` | 拿会议转写文本、智能纪要 |

> 妙记是飞书会议的 AI 转写能力，会议结束后可通过 API 拿到逐字稿和 AI 摘要，接入你的知识库或项目管理系统。

## 审批 Approval

审批是飞书 OA 的核心，API 前缀 `/open-apis/approval/v4`。

### 核心概念

| 概念 | 说明 | 示例 |
| --- | --- | --- |
| **审批定义（approval_code）** | 审批模板的唯一标识，在后台创建审批模板后得到 | `7C468F13-XXXX` |
| **审批实例（instance_code）** | 一次具体的审批申请 | 每提交一次生成一个 |
| 审批任务 | 审批流中的一个节点（某审批人待处理） | 经理审批节点 |
| 表单数据 | 审批的表单字段值（JSON） | `{"金额":3200,"事由":"出差"}` |

### 1. 获取审批定义列表

先在飞书管理后台「审批」创建模板（请假/报销/自定义），得到 approval_code。也可通过 API 拉：

```http
GET /open-apis/approval/v4/approvals   // 列出当前企业的审批定义
```

### 2. 提交审批实例

让用户在你的系统里填表，提交到飞书走审批流：

```http
POST /open-apis/approval/v4/instances
{
  "approval_code": "7C468F13-XXXX",
  "user_id": "ou_xxx",          // 发起人
  "form": "[{\"id\":\"金额\",\"type\":\"number\",\"value\":\"3200\"}]",
  "node_approver_user_id_list": "{}",  // 可选，指定审批人
  "uuid": "unique-request-id"   // 幂等，防重复提交
}
```
返回 `instance_code`，存下来跟踪状态。

### 3. 查询审批实例状态

```http
GET /open-apis/approval/v4/instances/{instance_code}
```
返回 `status`：PENDING（审批中）/ APPROVED（通过）/ REJECTED（驳回）/ CANCELED（撤销）/ DELETED。

### 4. 监听审批结果（事件订阅）

实时感知审批状态变化，推荐用事件而不是轮询：

| 事件 | 触发时机 |
| --- | --- |
| `approval_instance` | 审批实例状态变更（通过/驳回/撤销） |
| `approval_task` | 审批任务状态变更（某人已审批） |
| `approval_cc` | 审批抄送 |

事件回调里带 `instance_code` + `status`，你的后端据此触发后续动作（如审批通过后自动打款、自动创建多维表格记录）。

### 5. 三方审批（反向）

如果你的系统是审批引擎，想让飞书用户在飞书里看到并审批你系统的单据，可以用「三方审批」：把你系统的审批实例同步到飞书，用户在飞书审批，结果回调你系统。

## 考勤打卡 Attendance

接口前缀 `/open-apis/attendance/v1`。

| 能力 | 接口 |
| --- | --- |
| 打卡数据 | `GET /attendance/v1/user_tasks/query`（按用户+日期查打卡记录） |
| 打卡结果 | `GET /attendance/v1/user_task_remedy/...`（补卡审批） |
| 排班 | `/attendance/v1/workschedules/...` |
| 考勤组 | `/attendance/v1/groups/...` |

拉取打卡数据示例：

```http
POST /open-apis/attendance/v1/user_tasks/query
{
  "user_ids": ["ou_xxx"],
  "check_date_from": "2024-01-01",
  "check_date_to": "2024-01-31",
  "need_overtime_result": true
}
```

> 考勤数据敏感度高，需要 `attendance:task` 等权限，且通常需要管理员授权。适合做考勤报表、对接工资系统。

## 实战：报销审批自动化

```
员工在你的报销系统填单 → 提交
  ↓ 调用 /approval/v4/instances 提交到飞书审批
飞书审批流走（经理 → 财务）→ 审批通过
  ↓ 事件 approval_instance 回调，status=APPROVED
你的后端：
  ① 调财务系统打款
  ② 写一条记录到多维表格「报销台账」
  ③ 发消息卡片通知员工「报销 ¥3,200 已打款」
  ④ 生成报销汇总文档（docx）发财务群
```

一条链路把「申请 → 审批 → 执行 → 记账 → 通知 → 归档」全打通。
