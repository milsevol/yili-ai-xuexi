# 09 小程序与工作台

## 一句话

飞书应用有三种前端形态：**小程序**（原生体验，运行在飞书客户端内）、**网页应用 H5**（复用 Web 技术栈）、**纯后端应用**（只发消息/调 API，没有前端页面）。选对形态，再挂到工作台让成员一键访问，应用才算真正「上线可用」。

## 三种前端形态对比

| 维度 | 飞书小程序 | 网页应用（H5） | 纯后端（无前端） |
| --- | --- | --- | --- |
| 技术栈 | TTML + TTSS + JS（类小程序 DSL） | HTML/CSS/JS，任意前端框架 | 无 |
| 运行环境 | 飞书客户端内置渲染引擎 | 飞书客户端内置浏览器（WebView） | 服务端 |
| 开发成本 | 中（需学小程序 DSL） | 低（复用现有 Web 应用） | 最低 |
| 原生能力 | 最丰富（tt.* API 全套） | 通过 JSAPI 调部分原生能力 | 无前端交互 |
| 体验 | 流畅、接近原生 | 依赖网络，体验略逊 | 仅消息卡片交互 |
| 发布 | 上传代码包 → 提交审核 → 发布 | 部署到 HTTPS → 配主页 URL | 只需后端服务 |
| 适合场景 | 高频工具（打卡/报修/查询） | 已有 Web 系统快速接入、复杂后台 | 通知机器人、数据同步 |

## 飞书小程序

### 开发流程

```
① 下载「飞书开发者工具」（IDE）
② 登录开发者后台 → 创建小程序应用 → 拿 App ID
③ IDE 里新建项目，填 App ID → 开发调试
④ 预览（扫码在手机飞书里看真机效果）
⑤ 上传代码 → 后台提交审核 → 发布
⑥ 配置可见范围 → 成员在工作台/搜索找到小程序
```

### 小程序能力（tt 命名空间）

飞书小程序 API 统一在 `tt.*` 命名空间（和微信小程序的 `wx.*` 类似但不同）：

```javascript
// 发起网络请求
tt.request({ url: 'https://api.example.com/data', success: res => {} })

// 扫码
tt.scanCode({ success: res => console.log(res.result) })

// 获取当前用户信息（需先登录）
tt.login({
  success: res => {
    // res.code → 后端换 user_access_token → 拿到用户身份
  }
})

// 发消息 / 打开文档 等原生能力
```

### 小程序登录

小程序内 `tt.login()` 拿到 code → 发给你后端 → 后端调 `/open-apis/authen/v1/access_token` 换 user_access_token → 拿到用户身份，建你自己的登录态。和第 03 章的 OAuth 流程一致，只是 code 来自小程序 API。

### 与多维表格/文档联动

小程序可以直接：
- 调服务端 API 读写多维表格（通过你后端中转，token 放后端）
- 打开飞书文档：`tt.openDocument({ url: 'https://xxx.feishu.cn/docx/...' })`
- 发消息卡片给当前用户

## 网页应用 H5

把已有 Web 应用接入飞书，成本最低：

### 接入步骤

```
① 把你的前端部署到 HTTPS 公网地址
② 开发者后台 → 创建应用 → 添加「网页应用」能力
③ 填「主页 URL」= 你的前端地址
④ 配置「网页授权域名 / JSAPI 安全域名」白名单
⑤ 在 H5 里引入 JSAPI SDK，做 tt.config 鉴权（见第 03 章）
⑥ 发布应用、配可见范围 → 成员在工作台点开就是你的 H5
```

### H5 能调的飞书能力

鉴权后通过 `window.tt.*` 可调用：

| 能力 | API |
| --- | --- |
| 扫码 | `window.tt.scanQRCode` |
| 选人 | `window.tt.contact.pickerUsers` |
| 选部门 | `window.tt.contact.pickerDepartments` |
| 拍照/选图 | `window.tt.chooseImage` |
| 预览文件 | `window.tt.previewFile` |
| 获取定位 | `window.tt.getLocation` |
| 调起日历 | `window.tt.openCalendar` |
| 分享到飞书 | `window.tt.share` |

> H5 的优势是「一次开发，飞书内外都能用」（在普通浏览器里就是个普通网站，在飞书里多了原生能力）。缺点是体验不如小程序流畅、部分高级 API 不支持。

## 工作台与快捷入口

应用发布后，成员在哪找到它？

| 入口 | 说明 |
| --- | --- |
| **工作台** | 飞书客户端「工作台」tab，应用默认出现在这里（按可见范围） |
| 搜索 | 成员搜应用名直接打开 |
| 快捷入口 / 置顶 | 用户可把常用应用置顶到飞书侧边栏 |
| 群快捷栏 | 可把应用挂到群聊的快捷栏，群成员一键打开 |
| 应用消息 | 应用主动推送消息，消息里带跳转链接直达应用 |

> 工作台是应用能否被员工真正用起来的关键，涉及上架流程、终端可见性、分组排序、管理员配置等一整套内容，单独成章讲解，见[第 10 章 工作台详解](./10-工作台详解)。

## 应用消息（推送）

即使是有前端的应用，也经常需要**主动推消息**把用户拉回来（通知、待办、提醒）：

```
后端有新待办 → 调 /im/v1/messages 发消息卡片给用户
  → 卡片带「查看详情」按钮 → 点击跳转到小程序/H5 的指定页面
  → 用户进入应用处理
```

卡片跳转链接：
- 小程序：`applink://app_id/...` 或小程序页面路径
- H5：直接填你的 H5 URL（在飞书内打开）

## 选型决策树

```
需要前端界面吗？
 ├─ 否 → 纯后端应用（机器人/数据同步/通知），只发消息卡片
 └─ 是 → 已有现成 Web 系统？
          ├─ 是 → 网页应用 H5（接入最快，复用代码）
          └─ 否 → 高频强交互工具？
                    ├─ 是 → 飞书小程序（体验最好）
                    └─ 否 → H5（开发快，先验证 MVP）
```
