# 10 工作台详解

## 一句话

**工作台是飞书面向员工的「应用门户」**：移动端底部导航的一个 tab、桌面端侧边栏的一个图标。所有自建应用、小程序、网页应用最终都要「上架」到这里，员工才能零安装、一键进入。对开发者来说，**工作台决定你的应用有没有人用**；对管理员来说，**工作台是数字化入口的治理中心**——分组、排序、推荐位、可见范围都在这里配置。

## 为什么工作台值得单独讲

很多团队把应用做完、API 调通就以为上线了，结果员工根本找不到入口，DAU 接近 0。工作台是「最后一公里」，它同时涉及三方：

| 角色 | 在工作台关心什么 |
| --- | --- |
| **员工（使用者）** | 打开飞书第一眼能不能看到我要用的应用；常用应用能不能置顶；能不能自己加应用 |
| **管理员（IT/HR）** | 应用怎么分组、排序；哪些部门看得到；哪些应用要推荐；能不能统一导航 |
| **开发者（你）** | 我的应用发布后为什么不出现；桌面端/移动端为什么一端看不到；怎么配置入口 URL；怎么让消息卡片一键跳转回应用 |

> 一句话记住：**「发布 + 可见范围 + 终端可见性 + 上架分组」四件事齐了，应用才会出现在工作台。**

## 工作台长什么样

```

├────────────────────────────────────┤
│  我的常用                            │

│  └────┘ └────┘ └────┘ └────┘      │
├────────────────────────────────────┤
│  人事服务（管理员配置的分组）          │
│  ┌────┐ ┌────┐ ┌────┐              │
│  │请假│ │报销│ │招聘│              │

```

### 桌面端布局

```
┌──────┬──────────────────────────────────┐
│ 消息  │  工作台                            │

```

### 工作台的组成要素

| 区域 | 谁配置 | 说明 |
| --- | --- | --- |
| **搜索框** | 飞书原生 | 按应用名/功能搜索，不受分组限制 |
| **我的常用** | 用户自己 | 员工手动添加/置顶的高频应用 |
| **应用分组** | 管理员 | 如「人事服务」「研发工具」「财务」，管理员在工作台设置里建分组并放应用 |
| **应用卡片** | 管理员 + 开发者 | 图标、名称来自应用配置；点击进入应用 |
| **推荐位 / 运营位** | 管理员 | 轮播、置顶推荐，用于推广重点应用 |
| **小组件（Widget）** | 开发者 + 用户 | 卡片式小组件，展示实时数据（待办数、看板指标），用户可添加到工作台 |

## 核心：应用如何「上架」到工作台

这是开发者最常踩坑的地方。完整链路：

```
① 应用开发完成（机器人 / 网页应用 / 小程序）
        ↓
② 配置「应用功能」——明确有哪些入口
   · 机器人：配置机器人能力（可被搜索、可发消息）
   · 网页应用：配置【桌面端主页 URL】+【移动端主页 URL】
   · 小程序：上传代码包并发布版本
        ↓
③ 配置「终端可见性」——勾选 桌面端 / 移动端
   （漏勾一端 = 那一端工作台看不到，最常见的坑）
        ↓
④ 创建版本 → 提交发布 → 管理员确认开通
        ↓
⑤ 配置「可用范围」——哪些部门/成员能用
        ↓
⑥ 管理员在【工作台设置】把应用加到分组 / 排序
        ↓
⑦ 员工在工作台看到应用 → 点击进入
```

### 第 ② 步细节：不同应用类型的入口配置

| 应用类型 | 需要配置什么 | 员工点击后发生什么 |
| --- | --- | --- |
| **机器人** | 机器人能力 + 消息卡片 | 进入与机器人的单聊会话 |
| **网页应用 H5** | 桌面端主页 URL + 移动端主页 URL + 安全域名 | 飞书内置浏览器打开你的 H5 |
| **小程序** | 上传代码包、配置首页路径、发布版本 | 飞书客户端原生渲染小程序 |
| **网页应用（多标签）** | 可配置多个页面（PC 侧边栏多 tab） | 侧边栏多标签打开不同页面 |

> 网页应用特别注意：**桌面端和移动端的主页 URL 是分开配置的**，可以填不同地址（比如 PC 填后台管理页、移动填轻量版 H5）。只填一端，另一端就是空白/不可用。

### 第 ③ 步：终端可见性（高频坑）

开发者后台「应用功能 → 网页应用 / 小程序」里，有一组**终端可见性**勾选项：

```
☑ 桌面端
☑ 移动端
```

- 只勾桌面端 → 手机工作台搜不到
- 只勾移动端 → 电脑工作台搜不到
- 两个都勾 → 两端都能用（推荐，除非有明确的端差异）

### 第 ⑤ 步：可用范围 vs 终端可见性

这两者经常被混淆，但作用完全不同：

| 配置项 | 回答的问题 | 配错的表现 |
| --- | --- | --- |
| **可用范围** | 「谁能用这个应用」（按人/部门） | API 调用报无权限、发消息失败、工作台看不到 |
| **终端可见性** | 「在哪个端能用」（桌面/移动） | 某一端工作台看不到应用 |
| **工作台分组** | 「应用摆在哪里、排第几」（展示位置） | 应用在但很难找，或不在一眼可见的分组 |

> 三者是**与关系**：范围包含该用户 + 终端包含该设备 + 已加入分组，三个都满足才完整可见。

## 管理员视角：工作台配置

管理员在 **飞书管理后台 → 工作台** 里做治理：

### 1. 工作台设置

| 配置能力 | 说明 |
| --- | --- |
| 新建/编辑分组 | 按业务域建分组（人事、财务、研发、销售…） |
| 应用加入分组 | 把已发布应用拖入分组，一个应用可出现在多个分组 |
| 排序 | 分组内拖拽排序，分组之间也可排序 |
| 推荐位 / 运营位 | 顶部推荐、轮播图，用于推广重点应用 |
| 自定义工作台 | 部分版本支持自定义工作台页面（企业品牌化入口） |
| 是否允许成员自定义 | 控制员工能否自行添加/隐藏应用 |
| 上架审核 | 自建应用需管理员确认开通后才进入可用状态 |

### 2. 分组设计建议

```
工作台分组（示例）
├─ 我的常用（用户自管，不干预）
├─ 高频办公：审批 / 日历 / 考勤 / 会议室
├─ 人事服务：请假 / 报销 / 招聘 / 入职
├─ 研发工具：发布系统 / 监控 / 工单
├─ 数据看板：经营日报 / 销售看板
└─ 其他应用（兜底，避免应用彻底找不到）
```

**原则**：
- 按「员工做事的场景」分组，而不是按「系统归属」分组（员工不关心哪个系统）
- 高频应用放最上面，低频的收进二级分组
- 给每个应用配清晰的图标和名称（图标是工作台的视觉主体）
- 预留「其他应用」兜底，新应用先放这里再逐步归类

### 3. 自定义导航（侧边栏）

桌面端还可配置**侧边栏导航**：把最核心的几个应用固定到飞书左侧快捷区，员工不用进工作台就能一键打开。适合「每天都用」的应用（审批、工单、看板）。

## 开发者视角：与工作台相关的 API

工作台本身的主体配置在管理后台完成，但开放平台提供了若干与应用信息、可用范围有关的服务端 API，方便你做自动化治理和巡检。

### 获取应用信息

```http
GET /open-apis/application/v6/applications/{app_id}?lang=zh_cn
Authorization: Bearer <tenant_access_token>
```

返回应用的名称、图标、描述、应用类型、状态等基础信息。适合做「应用资产盘点」「自动生成应用目录」。

### 获取应用版本信息

```http
GET /open-apis/application/v6/applications/{app_id}/app_versions
```

用于查询应用有哪些版本、当前线上版本、版本状态，配合发布流程做自动化校验。

> 可用范围、工作台分组等后台配置项，部分能力支持通过应用管理相关 API 查询，具体以[应用信息 API 文档](https://open.feishu.cn/document/server-docs/application-v6/application/get)为准。**上线前务必核对官方文档的 scope 与参数**，不要凭记忆写死路径。

### 工作台小组件（Widget）

飞书支持开发者把**卡片式小组件**放到工作台，展示实时信息（待办数量、销售看板、值班信息），用户可自行添加到工作台首屏。它的价值是把「需要点进去看」变成「一眼就能看到」。

```
用户打开工作台
  → 小组件卡片展示：待办 3 条 / 今日销售额 ¥12.8w
  → 点击某个数字 → 跳转到应用对应页面
```

> 工作台小组件属于相对新的开放能力，创建方式、可用版本、卡片协议请以官方文档为准（搜索「工作台小组件」）。若你的企业版本不支持，用「应用卡片 + 消息卡片推送」也能达到 80% 的效果。

## 让应用「被找到」的四个入口

工作台上架只是入口之一，实际员工可能从多个地方进入：

| 入口 | 怎么触达 | 适合 |
| --- | --- | --- |
| **工作台** | 发布 + 可见范围 + 终端可见性 + 分组 | 常规入口，员工主动找 |
| **搜索** | 应用名/功能关键词 | 员工知道名字，直接搜 |
| **侧边栏快捷导航** | 管理员固定到桌面端侧边栏 | 每天必用的核心应用 |
| **应用消息 / 卡片跳转** | 消息卡片按钮带 applink 直达页面 | 把用户「拉回」应用处理待办 |

### 卡片跳转链接写法

```
小程序：applink://{app_id}/page?path=pages/todo/index
H5    ：https://your-domain.com/todo?from=feishu
```

消息卡片是提升工作台应用活跃度最有效的手段：**用消息把人拉进来，用工作台让人留下来。**

## 常见问题排查

| 现象 | 最可能原因 | 排查动作 |
| --- | --- | --- |
| 发布后工作台完全看不到 | 没有加入分组 / 管理员未确认开通 | 后台「工作台设置」检查分组；确认应用已上架 |
| 电脑能看到，手机看不到 | 终端可见性只勾了桌面端 | 「应用功能」里补勾移动端并重新发版 |
| 某些员工看不到 | 可用范围不含该员工/部门 | 「应用发布 → 可用范围」补人；注意部门是否含子部门 |
| 应用在但点开空白 | 主页 URL 未配 / 安全域名未配 / HTTPS 不合规 | 检查两端主页 URL、JSAPI 安全域名、证书 |
| 改了配置不生效 | 改的是开发版，线上版未重新发布 | 创建新版本发布；必要时让管理员重新确认 |
| 员工反馈「找不到常用应用」 | 未引导加入「我的常用」 | 管理员配推荐位；或培训员工置顶 |

## 自测

1. 应用发布后在工作台看不到，最可能的三个原因是什么？
2. 「可用范围」和「终端可见性」分别解决什么问题？配错各自会出现什么现象？
3. 网页应用的桌面端和移动端主页 URL 是同一份配置吗？只配一端会怎样？
4. 你是管理员，要给一家 500 人公司设计工作台分组，你会按什么维度分？为什么不是按系统分？
5. 除了工作台，还有哪些入口能把员工带到你的应用？为什么说「消息卡片 + 工作台」是组合拳？
