# 06 文档与云空间

## 一句话

飞书的「文档」不只是文档——它是一个**可通过 API 操作的内容容器**。新版文档（docx）用 Block 模型组织内容，你可以像操作 DOM 一样创建、读取、编辑文档块；云空间（Drive）管文件与文件夹、权限、评论。文档 + 多维表格 + API，能搭出自动生成周报、知识库、报告系统。

## 云文档类型

飞书云空间里有这几类文件，每类有不同的 API：

| 类型 | 标识 | API 前缀 | 说明 |
| --- | --- | --- | --- |
| **新版文档** | docx | `/open-apis/docx/v1` | 推荐，Block 模型，功能最全 |
| 旧版文档 | doc | `/open-apis/doc/v2` | 旧版，逐步迁移到 docx |
| **电子表格** | sheet | `/open-apis/sheets/v3` | 类似 Excel，单元格 API |
| **多维表格** | bitable | `/open-apis/bitable/v1` | 见第 05 章 |
| 思维笔记 | mindnote | `/open-apis/docx/v1`（兼容） | 思维导图 |
| 普通文件 | file | `/open-apis/drive/v1` | 上传下载的任意文件 |

> 新建文档建议直接用 **docx（新版文档）**，API 能力最强、维护最活跃。

## 新版文档 docx：Block 模型

docx 把整篇文档拆成一个个 **Block（块）**，类似 HTML 的 DOM 树：

```
文档 (document_id)
 └─ 页面 Block (page)
     ├─ 标题 Block (heading1)
     ├─ 段落 Block (text)  ← 含文本元素 (text_run)
     ├─ 表格 Block (table)
     ├─ 图片 Block (image)
     ├─ 代码块 Block (code)
     ├─ 分割线 Block (divider)
     └─ 子页面 / 引用块 ...
```

每个 Block 有：
- `block_id`：唯一标识
- `block_type`：类型（1=页面，2=文本，3=标题1，…31=表格，…）
- 对应类型的内容字段（如 `text`、`heading1`、`table`）

## 文档 API 常用操作

接口前缀：`/open-apis/docx/v1`，需 scope `docx:document`。

### 1. 新建文档

```http
POST /open-apis/docx/v1/documents
{
  "title": "2024 Q4 周报",
  "folder_token": "fldcnXXXX"   // 可选，放到指定文件夹
}
```
返回 `document_id`（形如 `doxcnXXXX`），后续操作都用它。

### 2. 读取文档块列表

```http
GET /open-apis/docx/v1/documents/{document_id}/blocks
```
返回所有 Block，可递归拿整篇文档结构。

### 3. 在文档末尾追加内容（最常用）

```http
POST /open-apis/docx/v1/documents/{document_id}/blocks/{block_id}/children
{
  "children": [
    {
      "block_type": 3,
      "heading1": { "elements": [{ "text_run": { "content": "本周围棋" } }] }
    },
    {
      "block_type": 2,
      "text": { "elements": [{ "text_run": { "content": "完成了项目 A 的上线。" } }] }
    },
    {
      "block_type": 14,
      "code": { "elements": [{ "text_run": { "content": "print('hello')" } }], "style": { "language": 1 } }
    }
  ],
  "index": 0   // 插入位置
}
```

> block_type 数字对应关系见 [Block 类型](https://open.feishu.cn/document/server-docs/docs/docs/docx-v1/block-type)。常用：2=文本段落，3/4/5/6/7/8/9=标题1~7，14=代码，15=引用，17=待办，22=分割线，31=表格，33=图片。

### 4. 更新文本块内容

```http
PATCH /open-apis/docx/v1/documents/{document_id}/blocks/{block_id}
{
  "update_text_elements": {
    "elements": [{ "text_run": { "content": "更新后的文本" } }]
  }
}
```

## 电子表格 Sheet API

如果是电子表格（类似 Excel），用单元格维度操作：

```http
// 向 A1:C2 范围写入数据
PUT /open-apis/sheets/v2/spreadsheets/{spreadsheet_token}/values
{
  "valueRange": {
    "range": "sheetId!A1:C2",
    "values": [
      ["姓名", "部门", "绩效"],
      ["张三", "研发", "A"]
    ]
  }
}
```

也支持读取范围、追加行、批量更新、插入图表等。多维表格适合「记录型数据」，电子表格适合「计算型报表」。

## 云空间 Drive：文件与权限

云空间 API 管文件本身（不限于文档）：

| 能力 | 接口 | 说明 |
| --- | --- | --- |
| 上传文件 | `POST /drive/v1/files/upload_all` | 小文件一次性上传，返回 file_token |
| 分片上传 | `/drive/v1/files/upload_part` | 大文件分片，最后 complete |
| 下载文件 | `GET /drive/v1/files/{file_token}/download` | 流式下载 |
| 文件夹列表 | `GET /drive/v1/files` | 列目录、翻页 |
| 创建文件夹 | `POST /drive/v1/files/create_folder` | |
| 移动/复制 | `/drive/v1/files/...` | |
| 权限管理 | `/drive/v1/permissions/...` | 协作者、权限级别 |
| 评论 | `/drive/v1/files/{token}/comments` | 文档评论 |

### 上传文件示例（小文件）

```http
POST https://open.feishu.cn/open-apis/drive/v1/files/upload_all
Content-Type: multipart/form-data; boundary=xxx

--xxx
Content-Disposition: form-data; name="file_name"
report.pdf
--xxx
Content-Disposition: form-data; name="parent_type"
explorer
--xxx
Content-Disposition: form-data; name="parent_node"
fldcnXXXX
--xxx
Content-Disposition: form-data; name="file"; filename="report.pdf"
Content-Type: application/pdf
<binary>
--xxx--
```

返回 `file_token`，可发给消息（file 类型）、插入文档、或存进多维表格附件字段。

## 权限模型

云文档权限分几层：

| 层级 | 说明 |
| --- | --- |
| 云空间根权限 | 应用要能访问用户的云空间，需用户授权或应用有管理权限 |
| 单文档权限 | 每个文档可单独分享（链接分享 / 指定人），有 view/edit/manage 级别 |
| 应用身份访问 | tenant_access_token 默认只能访问**应用自己创建**或**被授权**的文档 |

> 常见坑：应用创建的文档，用户默认看不到 / 没权限。需要调权限 API 把用户加成协作者，或把文档放到用户有权限的文件夹。

## 实战：自动生成周报文档

```
每周五 18:00 定时任务触发
  ↓
① 从多维表格拉取本周完成的任务记录
② 调 docx 新建文档「2024-Wxx 周报」
③ 循环追加 Block：标题 → 任务列表表格 → 数据统计
④ 调权限 API 把周报群加成文档协作者
⑤ 发消息卡片到群，附文档链接 + 摘要
```

一条链路把「数据采集 → 文档生成 → 通知」全自动打通，这是飞书文档 API 的典型价值。
