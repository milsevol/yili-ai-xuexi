# 02 开放平台与应用注册

## 一句话

飞书所有开放能力都通过「应用」承载：在[开发者后台](https://open.feishu.cn/app)创建应用，拿到 **App ID + App Secret**，配置权限与事件订阅，发布后成员即可在工作台使用。这一章把「应用从 0 到能调 API」的全过程走通。

## 开放平台能做什么

[飞书开放平台](https://open.feishu.cn/)是飞书面向开发者的统一入口，提供：

| 能力 | 说明 |
| --- | --- |
| 应用管理 | 创建/配置/发布应用，管理凭证、权限、版本 |
| API 文档 | 所有开放接口的文档、调试台、错误码 |
| 事件订阅 | 接收飞书侧事件（消息、审批、通讯录变更等） |
| 消息卡片搭建 | 可视化搭建交互式消息卡片，导出 JSON |
| 小程序 IDE | 飞书小程序的开发、调试、上传工具 |
| 监控与日志 | 应用调用量、错误率、接口耗时统计 |

## 应用类型

飞书开放平台有三类应用，开发前先选对：

| 类型 | 定位 | 谁用 | 凭证 |
| --- | --- | --- | --- |
| **企业自建应用** | 企业内部自用，开发完直接装到自己企业 | 企业内部开发者 | App ID + App Secret → tenant_access_token |
| **商店应用（ISV）** | 上架飞书应用商店，卖给其他企业用 | SaaS 服务商 / ISV | app_access_token + 企业授权码 |
| **小程序** | 运行在飞书客户端内的轻应用，可独立也可挂在自建应用下 | 前端开发者 | App ID + App Secret |

> 本主题以**企业自建应用**为主线。商店应用多了「多租户授权」环节，见第 10 章 FAQ。

## 创建应用的完整流程

```
① 登录 open.feishu.cn → 开发者后台 → 创建企业自建应用
② 填写应用名称、图标、描述 → 得到 App ID + App Secret
③ 「权限管理」→ 勾选所需 scopes（如 im:message、bitable:app）
④ 「事件与回调」→ 配置事件订阅方式（HTTP 回调 或 WebSocket）
⑤ 「版本管理与发布」→ 创建版本 → 提交审核（自建应用免审，管理员确认即可）
⑥ 「应用发布」→ 配置可见范围（哪些部门/成员能用）→ 上线
```

## 凭证与基础信息

应用创建后，在「凭证与基础信息」页能看到：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| **App ID** | `cli_a1b2c3d4e5f6g7h8` | 应用唯一标识，公开可见，前端也能放 |
| **App Secret** | `xxxxxxxxxxxxxxxxxxxxxxxx` | 应用密钥，**只能放服务端**，用于换 token |
| **Encrypt Key** | （可选配置） | 事件回调加密密钥，配置后回调体会 AES 加密 |
| **Verification Token** | （可选配置） | 回调验证 token，HTTP 回调首验用 |

> ⚠️ **安全红线**：App Secret 绝不能提交到 Git、不能放前端代码、不能放客户端。泄露后任何人都能以你应用的身份发消息、改文档。建议存服务端环境变量或密钥管理服务。

## 权限管理（Scopes）

飞书 API 遵循**最小权限原则**：每个接口都要对应一个或多个 scope，应用必须在后台勾选并发布后才有权限调用。

```
┌─────────────────────────────────────────────┐
│  应用权限管理（部分高频 scope 示例）          │
├─────────────────────────────────────────────┤
│  im:message            发送/接收消息         │
│  im:message:send_as_bot  以应用身份发消息    │
│  im:chat               获取/管理群信息       │
│  bitable:app           多维表格读写          │
│  bitable:app:readonly  多维表格只读          │
│  docx:document         新版文档读写          │
│  drive:drive           云空间文件管理        │
│  contact:user:readonly 通讯录成员只读        │
│  contact:department    通讯录部门管理        │
│  calendar:calendar     日历读写              │
│  approval:approval     审批实例读写          │
│  auth:user.id          获取用户 user_id      │
└─────────────────────────────────────────────┘
```

**权限申请要点**：

- 勾选 scope 后需要**重新发布版本**才生效（线上版权限不会自动更新）
- 敏感权限（如读取通讯录手机号、邮箱）需要**企业管理员单独授权**
- 调试时可在后台「权限管理」页面直接用调试台调用，验证接口是否通

## 事件订阅

事件订阅让你的后端能**实时感知**飞书侧发生的事（用户发消息、审批通过、成员入群等）。飞书提供两种方式：

### 方式一：HTTP 回调（需公网 IP）

```
飞书服务器 ──POST 事件──▶ 你的回调 URL（公网可访问）
```

- 在后台填写「请求网址」，飞书会先发一个 `challenge` 验证请求，你返回 `{challenge: "..."}` 即验证通过
- 之后飞书把事件 POST 到该 URL，你需在 **3 秒内返回 200**，否则会重试
- 可用 Encrypt Key 加密回调体（AES-256-CBC）

### 方式二：WebSocket 长连接（推荐，无需公网）

```
你的后端 ──建立 WSS──▶ 飞书事件网关（长连接保持）
                      事件沿这条连接推下来
```

- 不需要公网 IP / 内网穿透，本地开发直接联调
- 飞书官方 SDK（lark-oapi）已封装好 WSS 客户端，几行代码启动
- 适合：本地开发、内网服务、不想暴露公网的场景

> 两种方式可同时配置，但同一应用推荐只用一种。事件列表见 [事件总览](https://open.feishu.cn/document/server-docs/event-subscription-guide/event-list)。

## 版本与发布

飞书应用有版本概念，类似 App 发版：

| 版本状态 | 说明 |
| --- | --- |
| **开发版** | 开发中，只有开发者可见，可随意改配置 |
| **线上版** | 已发布，企业成员可见。改配置/权限后需发新版才生效 |
| **灰度** | 商店应用支持按百分比灰度放量 |

**自建应用发布流程**：创建版本 → 填写更新说明 → 提交（自建应用无需商店审核，但企业管理员需在后台「确认」开通）→ 配置可见范围 → 生效。

## 可见范围

应用上线后，**只有在可见范围内的成员**才能在工作台看到、才能接收应用消息、API 才能操作其数据。在「应用发布 → 可用范围」配置：

- 按部门：选整个部门（含子部门）
- 按成员：指定具体人员
- 全员：企业所有成员

> 注意：即使 API 调用成功，如果目标用户不在应用可见范围，发消息也会失败（错误码提示无权限）。
