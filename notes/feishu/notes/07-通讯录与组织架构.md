# 07 通讯录与组织架构

## 一句话

通讯录是飞书的「组织底座」：部门、成员、用户组构成企业组织架构树。通过通讯录 API 你能读部门树、查成员信息、管理用户组；配合 OAuth 登录/扫码登录，让用户用飞书身份直接登录你的系统，实现「一次入职，处处通行」。

## 通讯录能做什么

| 能力 | 接口（前缀 `/open-apis/contact/v3`） | 说明 |
| --- | --- | --- |
| 获取部门列表 | `GET /departments` | 拿部门树，支持按父部门查子部门 |
| 获取单个部门 | `GET /departments/{department_id}` | 部门详情、部门负责人 |
| 创建/更新/删除部门 | `POST/PUT/DELETE /departments/...` | 管理组织架构 |
| 获取成员列表 | `GET /departments/{department_id}/members` | 查某部门下成员（分页） |
| 获取成员详情 | `GET /users/{user_id}` | 成员姓名、头像、邮箱、手机、直属上级 |
| 创建/更新/禁用成员 | `POST/PUT/DELETE /users/...` | 账号生命周期管理 |
| 用户组管理 | `/group/*` | 动态/静态用户组 |

> 通讯录权限较敏感（尤其是手机号、邮箱），需要企业管理员在后台**单独授权**应用，scope 如 `contact:user.base:readonly`（基础信息）、`contact:user.employee:readonly`（含手机邮箱）。

## 部门树结构

飞书部门是树形结构，每个部门有：

```
根部门 (department_id = 0)
 ├─ 研发部 (dep_xxx)
 │   ├─ 前端组 (dep_yyy)
 │   └─ 后端组 (dep_zzz)
 ├─ 产品部
 └─ 市场部
```

递归拉取部门树：

```python
def list_all_departments(client, parent_dep_id="0"):
    """递归获取所有部门"""
    result = []
    req = lark.api.contact.v3.DepartmentListRequest.builder() \
        .parent_department_id(parent_dep_id).build()
    resp = client.contact.v3.department.list(req)
    for item in resp.data.items or []:
        result.append(item)
        result += list_all_departments(client, item.department_id)
    return result
```

## 成员信息与三种 ID（再强调）

通讯录返回的成员会带三种 ID，务必存对：

| ID 字段 | 示例 | 唯一性 | 你的系统应存哪个 |
| --- | --- | --- | --- |
| `open_id` | `ou_abc123` | 应用内唯一 | 调飞书 API 时用 |
| `user_id` | `zhangsan` 或工号 | 企业内唯一 | 与 HR/内部系统映射时用 |
| `union_id` | `on_xyz789` | 同开发商多应用 | 多应用打通时用 |

> 最佳实践：内部系统的用户表同时存 `user_id`（业务主键映射）和 `open_id`（调 API 用）。发消息、写多维表格人员字段时用 `open_id`。

## 扫码登录

让用户用飞书扫码登录你的 Web 系统，免去注册：

```
① 你的登录页嵌入飞书二维码（或跳转飞书授权页）
   二维码地址：
   https://open.feishu.cn/open-apis/authen/v1/index
     ?redirect_uri=...&app_id=...&state=...
② 用户用飞书 App 扫码 → 确认登录
③ 飞书带 code 回调你的 redirect_uri
④ 后端用 code 换 user_access_token（见第 03 章）
   → 拿到 open_id / user_id / 姓名 / 头像
⑤ 在你系统里查/建用户 → 建立登录态（发你自己的 session/JWT）
```

> 扫码登录本质就是第 03 章的 OAuth2 授权码流程，只是入口是二维码。需开通「网页应用」能力并配置好回调域名。

## 网页应用免登

如果你的 H5 是嵌在飞书客户端里运行的（网页应用），还能做**免登**：用户已经登录飞书，H5 直接拿到身份，不用再扫一次码。

```
飞书客户端打开 H5 → URL 带 code
  → 后端用 code 换 user_access_token
  → 建立登录态
```

免登需要在开发者后台「网页应用」配置好主页 URL 和免登域名。

## 组织架构同步实战

很多企业要把飞书通讯录同步到自己的 HR/权限系统：

```
定时任务（每天凌晨）
  ↓
① 拉全量部门树 → 对比本地，新增/更新/标记删除
② 按部门拉成员 → 更新本地用户表（姓名、邮箱、部门、上级）
③ 成员离职（飞书里禁用）→ 本地回收权限、转交任务
④ 监听通讯录变更事件（可选，实时）：
   contact.user.created / updated / deleted
   contact.department.created / updated / deleted
```

> 全量同步 + 事件增量 结合，既保证最终一致，又能实时响应变更。
