# 02 市场微结构与交易规则

## 一句话定位

市场微结构研究的是「订单如何变成成交」：谁在挂单、以什么价格、按什么优先级撮合、成本从哪里来。策略的纸面收益再高，只要交易规则和摩擦成本处理错了，实盘就会把 Alpha 一点点吃掉。

## 市场分层：一级市场与二级市场

| 维度 | 一级市场 | 二级市场 |
| --- | --- | --- |
| 交易对象 | 新发行的股票、债券、基金份额 | 已上市的证券 |
| 主要参与者 | 发行人、承销商、机构投资者 | 所有合格投资者、做市商、券商 |
| 价格形成 | 询价、定价、配售 | 集合竞价、连续竞价、大宗交易 |
| 量化相关性 | 打新、定增、可转债申购 | 绝大多数策略的战场 |

二级市场的运行依赖三方：

| 角色 | 主要职责 | 对量化的影响 |
| --- | --- | --- |
| 交易所 | 提供撮合场所、制定交易规则、发布行情、实时监控 | 决定订单类型、涨跌停、申报限制、异常交易标准 |
| 券商 | 经纪通道、交易单元、两融、托管、研究服务 | 决定佣金、可用接口、券源、结算体验 |
| 中国结算 | 证券登记、清算、交收、分红派息 | 决定 T+1/T+2 交收、过户费、公司行为处理 |
| 做市商 | 持续双边报价，提供流动性 | 影响买卖价差、盘口深度、小盘股成交 |

```
投资者 ──委托──► 券商 ──报盘──► 交易所撮合 ──成交回报──► 券商 ──► 投资者
   │                              │
   └──── 资金/证券 ◄── 中国结算（清算交收）◄── 成交数据 ┘
```

## 订单簿与订单类型

### 订单簿

订单簿（Order Book）是按价格排序的未成交委托集合。买盘从高到低、卖盘从低到高排列，最优买价叫买一（bid1），最优卖价叫卖一（ask1）。

```
        卖五   10.04   10000
        卖四   10.03    8000
        卖三   10.02    5000
        卖二   10.01    3000
        卖一   10.00    2000
        ────────── 价差 0.01 ──────────
        买一    9.99    2500
        买二    9.98    4000
        买三    9.97    6000
        买四    9.96    9000
        买五    9.95   12000
```

几个基础量：

```
中间价 mid = (bid1 + ask1) / 2
绝对价差 spread = ask1 - bid1
相对价差 spread_bps = (ask1 - bid1) / mid × 10000
盘口不平衡 OBI = (Σ bid_vol - Σ ask_vol) / (Σ bid_vol + Σ ask_vol)
```

盘口深度越厚，单笔订单越不容易打穿；OBI 接近 +1 说明买盘挂单远多于卖盘，短期价格压力偏向上行，但它只是微观信号，不能单独当预测模型。

### 订单类型

| 订单类型 | 含义 | 成交确定性 | 价格确定性 | A 股可用性 |
| --- | --- | --- | --- | --- |
| 限价单 | 指定最高买价或最低卖价 | 不确定 | 确定（不优于限价） | 全部板块支持 |
| 市价单 | 以对手方最优价格立即成交 | 高 | 不确定 | 连续竞价可用，类型因板块而异 |
| 止损单 | 价格触发后转为市价单 | 触发后较高 | 不确定 | 交易所无原生类型，券商条件单模拟 |
| 止损限价单 | 触发后转为限价单 | 不确定 | 确定 | 同上，多为券商条件单 |
| IOC | 立即成交，未成交部分撤销 | 部分成交 | 限价可控 | 股票无原生，期货/港股/美股有 |
| FOK | 立即全部成交，否则整单撤销 | 全有或全无 | 限价可控 | 股票无原生，期货/港股/美股有 |
| 冰山单 | 只显示小部分数量，成交后补量 | 不确定 | 限价可控 | 无原生，算法拆单模拟 |

A 股的市价申报并不是「想买多少买多少」：不同板块支持的类型不同，常见的有最优五档即时成交剩余撤销、最优五档即时成交剩余转限价、对手方最优价格、本方最优价格等；集合竞价阶段通常只接受限价申报。**下单前先确认标的所在板块支持哪种订单类型，不要用期货/美股的订单语义套 A 股。**

### 撮合原则与交易时段

撮合遵循两条铁律：

1. **价格优先**：买方出价高的先成交，卖方要价低的先成交。
2. **时间优先**：同价位按申报时间先后排队。

例子：买盘有 10.01 元 1000 股（10:00 申报）、10.01 元 2000 股（10:01 申报）、10.00 元 5000 股。此时来一笔 10.00 元卖出 1500 股，会先成交 10.01 元那 1000 股，再成交 10.01 元中的 500 股；10.00 元的买单排在后面，不会被优先成交。

| 机制 | 集合竞价 | 连续竞价 |
| --- | --- | --- |
| 撮合方式 | 收集一段时间订单，按最大成交量原则确定单一价格 | 逐笔到达、逐笔撮合 |
| 成交价格 | 所有成交同一价格 | 每笔可能不同 |
| 典型时段 | 开盘、收盘 | 盘中 |
| 订单类型 | 通常只接受限价申报 | 限价、市价等 |
| 量化含义 | 开盘/收盘价容易受大单影响，回测要单独处理 | 滑点、排队、冲击成本的主要来源 |

A 股竞价交易的时间轴：

```
09:15 ─ 09:20 ─ 09:25 ─ 09:30 ───────── 11:30 ─ 13:00 ───── 14:57 ─ 15:00
  开盘集合竞价（可撤单）  开盘集合竞价（不可撤单）  连续竞价        连续竞价  收盘集合竞价
```

- 9:15—9:25 开盘集合竞价，9:20—9:25 不接受撤单，9:25 产生开盘价。
- 9:30—11:30、13:00—14:57 连续竞价。
- 14:57—15:00 收盘集合竞价，产生收盘价。
- 部分板块/品种另有盘后固定价格交易（如科创板 15:05—15:30），具体以交易所规则为准。

## A 股交易规则要点

以下为常用规则，**以交易所最新规则为准**；不同板块、不同品种差异很大。

| 项目 | 规则要点 |
| --- | --- |
| 交易机制 | 股票 T+1：当日买入、次一交易日才能卖出；卖出所得资金当日可用于买入，T+1 可取 |
| 涨跌幅 | 主板 ±10%，主板 ST/*ST ±5%；科创板、创业板 ±20%；北交所 ±30% |
| 最小价格变动 | 股票 0.01 元；基金、可转债等为 0.001 元（以规则为准） |
| 申报数量 | 主板/创业板买入 100 股整数倍；科创板 200 股起、1 股递增；北交所 100 股起、1 股递增 |
| 零股卖出 | 余额不足最小卖出单位的部分（主板/创业板 100 股、科创板 200 股、北交所 100 股）可一次性卖出 |
| 交易时间 | 9:15—9:25 开盘集合竞价；9:30—11:30、13:00—14:57 连续竞价；14:57—15:00 收盘集合竞价 |
| 印花税 | 卖出股票按成交金额 0.05% 收取（2023-08-28 起减半）；ETF、基金、债券通常免征 |
| 佣金 | 双向收取，约万分之 1 到万分之 3，最低 5 元（部分券商可协商免 5，以券商为准） |
| 过户费 | 双向收取，成交金额的 0.001%（2022-04-29 起下调后） |
| 两融/转融通 | 仅限标的证券；有保证金比例、维持担保比例、强制平仓要求；转融通提供券源 |
| 可转债 | T+0 回转交易，涨跌幅与临时停牌规则与股票不同，以交易所规定为准 |
| 特殊情形 | 新股上市初期、退市整理期、风险警示股票等另有涨跌幅和交易限制 |

板块差异可以放在一张表里看：

| 项目 | 主板 | 科创板 | 创业板 | 北交所 |
| --- | --- | --- | --- | --- |
| 涨跌幅 | ±10%（ST ±5%） | ±20% | ±20% | ±30% |
| 最小买入单位 | 100 股整数倍 | 200 股起，1 股递增 | 100 股整数倍 | 100 股起，1 股递增 |
| 市价申报 | 支持，类型有限 | 支持，类型较多 | 支持 | 支持 |
| 适当性门槛 | 无特别门槛 | 约 50 万元 + 24 个月交易经验 | 约 10 万元 + 24 个月交易经验 | 约 50 万元 + 24 个月交易经验 |
| 盘后固定价格 | 无 | 15:05—15:30 | 部分品种/安排 | 规则已引入，实施时间以公告为准 |

三条容易被忽略的规则：

- **涨跌停不是「不能交易」，而是「可能排队排不到」**。涨停时买单堆积，跌停时卖单堆积；回测里假设涨停仍能买入，是最常见的收益虚高来源之一。
- **连续竞价的限价申报可能受「价格笼子」约束**，申报价超出有效竞价范围会废单，具体比例和适用范围以交易所规则为准。
- **T+1 约束的是股票，不是资金**。当天卖出股票的钱可以继续买，但不能当天提现；可转债、部分 ETF 支持 T+0，不要和股票混为一谈。

## 港股与美股对比

| 维度 | A 股 | 港股 | 美股 |
| --- | --- | --- | --- |
| 日内回转 | 股票 T+1，不可当日卖出 | T+0 回转交易 | T+0 回转交易 |
| 交收 | T+1 | T+2 | T+1（2024-05-28 起） |
| 涨跌幅 | 有，按板块 10%/20%/30% | 无涨跌幅限制 | 无涨跌幅限制，但有 LULD 价格带与全市场熔断 |
| 做空 | 融券标的有限，券源紧张 | 仅限指定可卖空证券，需借券 | Reg SHO 框架下借券做空 |
| 盘前盘后 | 基本没有（盘后固定价格除外） | 开市前时段、收市竞价时段 | 盘前 4:00—9:30、盘后 16:00—20:00（券商不同） |
| 最小报价单位 | 0.01 元 | 按价格区间分档 | 0.01 美元；低于 1 美元可为 0.0001 美元 |
| 主要税费 | 印花税卖出 0.05%、佣金、过户费 | 印花税 0.1% 双边、交易费/征费另计 | 无印花税；SEC Section 31 费、FINRA TAF 等（费率会调整） |

港股和美股都是 T+0，但「T+0」指日内可回转，不代表交收也是当天；港股 T+2、美股 T+1 交收，资金和证券的实际到账时间要按交收日算。美股的日内交易还受 PDT（Pattern Day Trader）等保证金规则约束，现金账户另有交收限制。美股没有涨跌停，不等于没有波动控制：LULD 会在价格偏离价格带时触发短暂停牌，指数层面还有 7%/13%/20% 的熔断阈值。

## 交易成本模型

交易成本分显性和隐性两部分：

```
总成本 = 显性成本 + 隐性成本

显性成本 = 佣金 + 印花税（仅卖出股票）+ 过户费 + 经手费/证管费
隐性成本 = 买卖价差成本 + 滑点 + 冲击成本 + 机会成本
```

用 bps（万分之一）统一度量：

```
cost_bps = side × (P_exec - P_decision) / P_decision × 10000

side = +1（买入），-1（卖出）
P_decision：决策时的参考价（如下单前的中间价）
P_exec：实际成交均价
```

| 成本类型 | 来源 | 是否容易低估 |
| --- | --- | --- |
| 佣金 | 券商通道费 | 小资金容易低估最低 5 元的影响 |
| 印花税 | 卖出股票 0.05% | 高频策略容易忽略 |
| 过户费 | 双向 0.001% | 金额小但不可省略 |
| 买卖价差 | 买在卖一、卖在买一 | 用中间价回测会系统性低估 |
| 滑点 | 下单到成交之间的价格变化 | 波动越大越明显 |
| 冲击成本 | 自己的订单改变了价格 | 大资金最致命 |
| 机会成本 | 没成交、排队靠后、涨跌停买不到 | 回测几乎从不建模 |

冲击成本常用平方根模型估计：

```
impact ≈ k · σ · sqrt(Q / V)

k：经验系数，通常在 0.5—1 量级，因市场、算法、时段而异
σ：标的日波动率
Q：本次委托数量（或金额）
V：同期市场成交量（或成交额）
```

直觉：冲击与波动率成正比，与「参与率」的平方根成正比。参与率从 1% 提到 4%，冲击大约翻倍；从 4% 提到 16%，再翻倍。平方根模型适合中等参与率，参与率极高时真实冲击会更陡。

算例：某股票日波动率 2%，日成交额 2 亿元，计划买入 1000 万元，参与率 5%，取 k=0.7：

```
impact ≈ 0.7 × 0.02 × sqrt(0.05) ≈ 0.00313 = 31.3 bp ≈ 3.13 万元
```

这还没算价差、佣金和印花税。**一个日频策略如果年化超额只有 5%，31 bp 的单边冲击就足以吃掉很大一块。**

## 流动性指标

| 指标 | 计算方式 | 解读 |
| --- | --- | --- |
| 绝对价差 | ask1 - bid1 | 越小越流动 |
| 相对价差 | (ask1 - bid1) / mid | 跨股票可比 |
| 有效价差 | 2 × \|P_trade - mid\| / mid | 实际成交相对中间价的偏离 |
| 盘口深度 | 前 N 档挂单量或金额之和 | 能承接多大的单 |
| 订单簿不平衡 | (买量 - 卖量) / (买量 + 卖量) | 短期价格压力 |
| Amihud 非流动性 | 平均 \|r_t\| / 成交额_t | 单位成交额带来的价格冲击 |
| 换手率 | 成交量 / 流通股本 | 交易活跃度 |
| 零成交天数 | 区间内成交量为 0 的天数 | 小盘股/冷门股的流动性风险 |

Amihud 指标写成公式：

```
ILLIQ_i = (1/T) × Σ_t |r_{i,t}| / Amount_{i,t}
```

Amount 用成交金额（元），ILLIQ 越大表示流动性越差。它的优点是只用日频行情就能算，适合做全市场流动性因子；缺点是对极端收益敏感，通常要先缩尾。

## 实践一：五档订单簿吃单

用 numpy 构造一个五档订单簿，模拟 12000 股市价买单逐档吃单，计算成交均价、相对中间价的滑点，以及显性 + 隐性总成本。

```python
import numpy as np

# 五档订单簿：价格（元）与挂单量（股）
asks_px = np.array([10.00, 10.01, 10.02, 10.03, 10.04])
asks_vol = np.array([2000, 3000, 5000, 8000, 10000])
bids_px = np.array([9.99, 9.98, 9.97, 9.96, 9.95])
bids_vol = np.array([2500, 4000, 6000, 9000, 12000])

mid = (asks_px[0] + bids_px[0]) / 2
spread = asks_px[0] - bids_px[0]
print(f"买一 {bids_px[0]:.2f}，卖一 {asks_px[0]:.2f}，中间价 {mid:.3f}")
print(f"绝对价差 {spread:.3f} 元，相对价差 {spread / mid * 1e4:.2f} bp")

def market_buy(qty, asks_px, asks_vol):
    """市价买单逐档吃单，返回成交量、未成交量、成交额、均价、明细。"""
    remain, cost, filled, detail = qty, 0.0, 0, []
    for px, vol in zip(asks_px, asks_vol):
        take = min(remain, int(vol))
        if take <= 0:
            continue
        cost += take * px
        filled += take
        remain -= take
        detail.append((float(px), take))
        if remain == 0:
            break
    avg = cost / filled if filled else 0.0
    return filled, remain, cost, avg, detail

qty = 12000
filled, remain, amount, avg, detail = market_buy(qty, asks_px, asks_vol)
print("逐档成交:", detail)
print(f"成交 {filled} 股，剩余 {remain} 股，成交额 {amount:.2f} 元，均价 {avg:.4f} 元")
print(f"相对中间价滑点 {(avg - mid) / mid * 1e4:.2f} bp")
print(f"相对卖一价滑点 {(avg - asks_px[0]) / asks_px[0] * 1e4:.2f} bp")

# 显性费用：买入无印花税；佣金万 2.5、最低 5 元；过户费 0.001%
commission = max(amount * 2.5e-4, 5.0)
transfer = amount * 1e-5
explicit = commission + transfer
implicit = (avg - mid) * filled
total = explicit + implicit
print(f"显性费用 {explicit:.2f} 元（佣金 {commission:.2f} + 过户费 {transfer:.2f}）")
print(f"隐性滑点 {implicit:.2f} 元，总成本 {total:.2f} 元，"
      f"总成本率 {total / (mid * filled) * 1e4:.2f} bp")
```

输出会显示：均价约 10.0158 元，相对中间价滑点约 20.8 bp，总成本率约 23.5 bp。**如果按卖一价 10.00 元假设全部成交，成本会被低估到约 5 bp，差了四倍。**

## 实践二：A 股单笔交易成本

把显性费用封装成函数，重点看最低佣金对小资金的影响。

```python
def a_share_cost(price, shares, side="buy",
                 commission_rate=2.5e-4, min_commission=5.0,
                 stamp_rate=5e-4, transfer_rate=1e-5):
    """A 股单笔费用估算；默认假设经手费/证管费已包含在佣金中。"""
    assert side in ("buy", "sell")
    amount = price * shares
    commission = max(amount * commission_rate, min_commission)
    stamp = amount * stamp_rate if side == "sell" else 0.0
    transfer = amount * transfer_rate
    total = commission + stamp + transfer
    return {
        "amount": amount,
        "commission": commission,
        "stamp": stamp,
        "transfer": transfer,
        "total": total,
        "bps": total / amount * 1e4,
    }

for shares in (100, 1000, 10000):
    buy = a_share_cost(10.0, shares, "buy")
    sell = a_share_cost(10.0, shares, "sell")
    print(f"{shares:>5} 股 @ 10 元："
          f"买入 {buy['total']:.2f} 元（{buy['bps']:.1f} bp），"
          f"卖出 {sell['total']:.2f} 元（{sell['bps']:.1f} bp），"
          f"往返 {buy['total'] + sell['total']:.2f} 元")
```

100 股（1000 元）的往返成本约 10.5 元，折合约 105 bp；10000 股（10 万元）的往返成本约 102 元，折合约 10.2 bp。**同样的费率，小资金的实际成本可能是大资金的十倍。**这也是小账户不适合高换手策略的直接原因。

## 常见误区与坑

| 误区 | 后果 | 正确做法 |
| --- | --- | --- |
| 用收盘价当可成交价 | 回测收益虚高，实盘买不到 | 用下一期开盘价、VWAP 或盘口模拟成交 |
| 涨停仍假设能买入 | 热门股收益被严重高估 | 涨停/跌停日标记为不可成交或按排队概率成交 |
| 忽略停牌 | 回测能卖出，实盘被锁死 | 停牌期间冻结仓位，复牌后按真实价格处理 |
| 以为市价单一定成交 | 大单可能只成交一部分 | 建模逐档吃单、剩余撤销或转限价 |
| 只算佣金 | 印花税、过户费、冲击全漏掉 | 显性 + 隐性成本一起算 |
| 忽略 T+1 | 日内策略在 A 股股票上根本不成立 | 股票按 T+1，T+0 品种单独处理 |
| 忽略整手和零股 | 目标权重无法精确执行 | 下单前按 100 股/200 股规则取整 |
| 用中间价成交 | 系统性低估价差成本 | 买入按卖一、卖出按买一，或加半价差 |

## 常见问题 Q&A

**Q：市价单和限价单怎么选？**

A：确定性强、金额小、盘口厚时用市价单；大单、流动性差、价格敏感时用限价单或算法拆单。A 股集合竞价通常只能限价，别把连续竞价的习惯带过去。

**Q：涨停板排队能买到吗？**

A：概率问题，不是规则保证。涨停时买单按时间优先排队，成交取决于封单量和卖盘；回测里应当把涨停买入视为低概率甚至不可成交。

**Q：佣金万 2.5 和万 1.5 差多少？**

A：10 万元交易，单边差约 10 元，往返约 20 元，折合 2 bp。对低频策略影响有限，对高频策略和最低佣金约束下的小单影响很大。具体费率以券商为准。

**Q：A 股股票能做 T+0 吗？**

A：普通股票不能，当日买入次日才能卖。可转债、部分 ETF（跨境、债券、货币等）支持 T+0；融资融券的「日内回转」也不是无条件 T+0，需要券源和负债约束。

**Q：港股和美股最大的规则差异是什么？**

A：港股 T+0 回转、T+2 交收、无涨跌停、卖空需借券；美股 T+0 回转、T+1 交收、无涨跌停但有 LULD 和全市场熔断、卖空受 Reg SHO 约束。A 股则是 T+1、有涨跌停、融券券源有限。

**Q：为什么用 VWAP 回测仍然偏乐观？**

A：VWAP 是事后统计量，真实下单时你不知道当天的 VWAP；而且大单本身会推高 VWAP。更稳妥的做法是用盘口模拟、加入冲击成本，并做保守/中性/乐观三档情景。
