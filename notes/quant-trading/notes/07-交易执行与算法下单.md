# 07 交易执行与算法下单

## 一句话定位

执行是把「纸面 alpha」换成「账户收益」的最后一段路：**信号决定赚不赚，执行决定剩下多少**。同样一个因子，用收盘价假设成交的回测和真实逐笔成交之间，差的往往不是几个 bp，而是一半以上的超额收益。

## 解决什么问题

- 回测里 `close` 一填就成交，实盘却发现大单打出去把价格推高，成交均价远差于预期。
- 不知道该用 TWAP、VWAP 还是 POV，也不清楚各自在什么场景会失效。
- 订单发出去后状态混乱：重复下单、断线重连后不知道哪些单还活着、撤单撤不掉。
- 无法量化「这次交易到底执行得好不好」，只能拍脑袋说滑点大。

## 执行成本从哪里来

一笔订单从决策到成交，成本由四块构成，且互相拉扯：

| 成本来源 | 含义 | 典型量级（A 股中大盘） | 与执行速度的关系 |
| --- | --- | --- | --- |
| 买卖价差 | 主动成交要付半价差，挂单可能赚价差但有不成交风险 | 1~5 bp | 越快越确定付价差 |
| 冲击成本 | 自己的成交量吃掉盘口深度，把价格推向不利方向 | 5~50 bp，随下单速率上升 | 越快越大 |
| 择时风险 | 从决策到全部成交之间价格漂移 | 日波动 2% 时，延迟 1 小时约 20~40 bp | 越慢越大 |
| 机会成本 | 挂单没成交，错过后续行情 | 依赖 alpha 衰减速度 | 越慢越大 |

一个直观的算术：年化 alpha 15%，每天换手 10%，单边成本 15 bp，一年 250 个交易日，成本约 `10% × 250 × 15bp = 375bp = 3.75%`，直接吃掉四分之一的超额。若单边成本 30 bp，则吃掉一半。**执行不是细节，是 alpha 的分母。**

## 实现落差（Implementation Shortfall）

Perold（1988）把「纸面组合收益」与「实际组合收益」的差定义为 Implementation Shortfall（IS），这是执行评估的基准语言。

设：

- `P_decision`：策略做出决策时的价格（通常是信号生成时的收盘价或开盘前参考价）
- `P_arrival`：订单到达市场时的价格
- `P_fill`：实际成交均价
- `P_end`：评估期末价格（用于未成交部分）
- `Q_order`、`Q_fill`：委托量与成交量
- `side = +1` 买入、`-1` 卖出

则（单位 bps，统一用决策价作分母）：

```text
IS = delay + trading + opportunity + fees

delay       = side * (P_arrival - P_decision) / P_decision * 10000
trading     = side * (P_fill    - P_arrival) / P_decision * 10000
opportunity = side * (Q_order - Q_fill) / Q_order
              * (P_end - P_decision) / P_decision * 10000
fees        = 佣金 + 印花税 + 过户费，折算成 bps
```

数值例子：买入 10 万股，决策价 10.00，到达价 10.05，成交均价 10.08，成交 9 万股，期末价 10.20。

```text
delay       = (10.05 - 10.00) / 10.00 * 10000 = 50 bp
trading     = (10.08 - 10.05) / 10.00 * 10000 = 30 bp
opportunity = 0.1 * (10.20 - 10.00) / 10.00 * 10000 = 20 bp
合计（不含费） = 100 bp
```

这 100 bp 告诉你两件事：**延迟已经付了 50 bp**，说明信号生成到下单的链路太慢；**未成交的 10% 又贡献 20 bp**，说明挂单过于被动。只看「成交部分滑点 80 bp」会漏掉一半问题。

## 算法交易：把大单拆成小单

### TWAP：时间等分

把委托量按时间均匀切片：

```text
q_t = Q / N,  t = 1..N
```

优点是实现简单、可预测、不依赖行情；缺点是假设成交量在时间上均匀，而真实市场是 U 形分布，午间挂单可能长时间不成交，尾盘又被迫加速。适合流动性稳定、时间不敏感、需要给 benchmark 一个「时间中性」基准的场景。

### VWAP：按历史成交量分布切片

```text
q_t = Q * v_t / Σ v_t
```

`v_t` 是历史同时段的成交量占比（通常取过去 20 日均值）。它跟踪的是市场成交量曲线，目标是让自己的成交均价接近当日 VWAP。适合**以 VWAP 为考核基准**的机构单，以及流动性分布稳定的标的。坑在于：历史分布不等于今天，遇到突发新闻、指数调仓、半日市，曲线会失真。

### POV / 参与率：跟着实时成交量走

```text
q_t = min(Q_remaining, ρ * V_t)
```

`V_t` 是当前时段的市场成交量，`ρ` 是参与率上限（如 5%、10%）。POV 不预设完成时间，市场放量就多成交，缩量就等待，因此**冲击可控但完成时间不可控**。适合流动性差、绝对不能留下明显足迹的票；若 `ρ` 设得过低，可能收盘都做不完，尾部只能市价扫单，反而更差。

### IS / Arrival Price：在冲击与风险之间求最优

Almgren-Chriss（2001）把执行写成优化问题：

```text
min  E[执行成本] + λ * Var[执行成本]
```

其中 `λ` 是风险厌恶系数。解出的最优剩余持仓路径近似为双曲正弦：

```text
x_j = X * sinh(κ(T - t_j)) / sinh(κT)
κ ≈ sqrt(λ σ² / η)
```

`σ` 是价格波动率，`η` 是临时冲击系数。关键结论：

- `λ → 0`（完全不关心风险）时，`κ → 0`，路径退化为线性，即 TWAP。
- `λ` 越大，`κ` 越大，**越前置执行**：宁可多付冲击，也要缩短暴露在价格波动中的时间。
- 波动率越高、冲击系数越低，越应该快；流动性越差（`η` 大），越应该慢。

这就是「Arrival Price / IS 算法」的直觉：它以到达价为基准，动态权衡「快一点多付冲击」与「慢一点多担风险」。

### 冰山单与智能路由

- **冰山单（Iceberg）**：只显示小部分数量，成交后自动补量，隐藏真实规模。交易所原生冰山与「自己拆单模拟冰山」是两回事，后者更容易被识别。
- **智能订单路由（SOR）**：多交易所/多柜台环境下，按价格、深度、延迟、费率选择目的地。A 股是单一交易所，SOR 更多用于海外市场或同一券商的多条通道。
- **收盘集合竞价**：A 股 14:57–15:00 集中撮合，大单可借助收盘价流动性完成，但要注意 14:57 后不可撤单（以交易所规则为准）。

### 算法适用场景对比

| 场景 | 首选 | 备选 | 原因 |
| --- | --- | --- | --- |
| 大单、追求低冲击 | IS / Arrival Price | POV（低参与率） | 显式权衡冲击与风险 |
| 流动性差的票 | POV 5% 以下 + 冰山 | TWAP 拉长 | 不能暴露规模，宁慢勿砸 |
| 尾盘流动性好 | VWAP 偏尾盘 / 收盘竞价 | TWAP | 利用收盘放量 |
| 波动剧烈 | IS 前置 | POV 提高参与率 | 减少暴露时间 |
| 以 VWAP 考核 | VWAP | POV | 直接对标基准 |
| 时间敏感（事件驱动） | 限价激进单 / 市价 | IS | 先成交再谈成本 |

## 交易系统组件

```text
策略信号
   │
   ▼
┌─────────┐   订单意图    ┌─────────┐   标准化报文   ┌──────────┐
│  策略层  │ ───────────> │   OMS   │ ───────────> │  EMS/网关 │
└─────────┘               │ 订单管理 │ <─────────── │ 执行管理  │
                          └────┬────┘   成交回报     └────┬─────┘
                               │ 持仓/资金                  │ FIX / 券商 API
                               ▼                            ▼
                          风控与账务                    交易所 / 柜台
```

- **OMS（Order Management System）**：维护订单全生命周期、持仓、资金、委托去重。核心是「状态机 + 持久化」。
- **EMS（Execution Management System）**：把母单拆成子单，执行算法，选择通道，控制节奏。
- **FIX 协议**：行业标准报文。会话层有 `Logon`、`Heartbeat`、`TestRequest`、`Logout`；业务层常用 `NewOrderSingle`（新建订单）与 `ExecutionReport`（执行回报）。关键字段：

| 字段 | 含义 |
| --- | --- |
| `ClOrdID` | 客户端订单号，幂等键 |
| `Symbol` / `Side` / `OrdType` | 标的、买卖方向、订单类型（限价/市价） |
| `OrderQty` / `Price` / `TimeInForce` | 数量、价格、有效期 |
| `ExecType` / `OrdStatus` | 回报类型、订单状态 |
| `CumQty` / `AvgPx` / `LeavesQty` | 累计成交、均价、剩余量 |

- **券商通道**：A 股常见 QMT（迅投）、Ptrade（恒生）等客户端/API；期货以 CTP 为主；海外可用 IB API 或 FIX/REST。通道差异主要在报单字段、限频、回报延迟、是否支持算法单。

## 订单生命周期与状态机

```text
                    ┌──────────┐
       submit ────> │ PENDING  │  待报（本地已生成，未确认）
                    └────┬─────┘
                         │ 柜台受理
                    ┌────▼─────┐
                    │   NEW    │  已报
                    └──┬────┬──┘
             部分成交  │    │ 全部成交
                  ┌───▼──┐ └────────> FILLED 全成
                  │ PART │
                  └───┬──┘
         撤单成功     │
             ┌────────▼────────┐
             │    CANCELED     │ 已撤（可含部分成交）
             └─────────────────┘

  任何阶段异常 ───────────────> REJECTED 废单
  （风控拒绝、涨跌停、参数错误、资金不足）
```

工程上必须处理的边界：

- **重复下单**：网络超时后重试，柜台其实已受理，结果买了两倍。解决：客户端订单号 `ClOrdID` 做幂等键，重试前先查询。
- **断线重连**：重连后先拉「当前委托 + 当前成交」做全量对齐，再恢复增量推送。
- **乱序回报**：成交回报可能晚于撤单回报到达，状态机要允许「已撤但仍有成交」的终态。
- **部分成交后撤单**：终态是「已撤 + 成交量 > 0」，不是「全撤」。

## 执行质量评估

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| 成交率 | 成交量 / 委托量 | 判断是否错过 |
| 滑点（bps） | `side*(成交均价 - 基准价)/基准价*10000` | 最常用的单笔评估 |
| 相对 VWAP 偏差 | 成交均价 / 当日 VWAP - 1 | 机构考核基准 |
| 参与率 | 成交量 / 同期市场成交量 | 评估足迹与冲击 |
| 冲击成本回归 | 成交后价格变化对参与率回归 | 估计长期冲击系数 |
| 完成时间 | 从下单到全部成交的时长 | 评估机会成本 |

注意：滑点的「基准价」必须事先约定。用决策价、到达价、VWAP 还是收盘价，结论可能完全相反。评估体系要能同时看「这笔单」和「这个策略一个月的执行质量」，否则容易被单笔噪声带偏。

## 实践一：U 形成交量曲线下的 TWAP 与 VWAP 拆单

A 股一天 240 个交易分钟（9:30–11:30、13:00–15:00）。用指数衰减构造 U 形历史成交量，再按两种算法切片：

```python
import numpy as np
import pandas as pd

# 构造 A 股 240 分钟交易时段
morning = pd.date_range("2024-01-02 09:30", "2024-01-02 11:29", freq="1min")
afternoon = pd.date_range("2024-01-02 13:00", "2024-01-02 14:59", freq="1min")
minutes = morning.append(afternoon)
t = np.arange(len(minutes))
n = len(minutes)

# U 形：开盘、收盘放量，午间低谷；叠加轻微正弦波动
shape = 1.0 + 2.2 * np.exp(-t / 25) + 1.6 * np.exp(-(n - 1 - t) / 20) \
        + 0.15 * np.sin(np.pi * t / n)
rng = np.random.default_rng(20240102)
volume = (shape * 100_000 * rng.lognormal(mean=0.0, sigma=0.15, size=n)).round().astype(int)

df = pd.DataFrame({"minute": minutes, "hist_volume": volume})
df["bucket"] = np.arange(n) // 10  # 每 10 分钟一个切片，共 24 片

bucket = df.groupby("bucket", as_index=False).agg(
    start=("minute", "first"), hist_volume=("hist_volume", "sum")
)
bucket["hist_weight"] = bucket["hist_volume"] / bucket["hist_volume"].sum()

order_qty = 1_000_000                 # 10 万股母单
bucket["twap_qty"] = int(order_qty / len(bucket))
bucket["vwap_qty"] = (order_qty * bucket["hist_weight"]).round().astype(int)
# 取整误差统一补到最后一个切片
bucket.loc[bucket.index[-1], "twap_qty"] += order_qty - bucket["twap_qty"].sum()
bucket.loc[bucket.index[-1], "vwap_qty"] += order_qty - bucket["vwap_qty"].sum()
bucket["start"] = bucket["start"].dt.strftime("%H:%M")

print(bucket[["start", "hist_volume", "hist_weight", "twap_qty", "vwap_qty"]]
      .rename(columns={"start": "时间", "hist_volume": "历史量",
                       "hist_weight": "权重", "twap_qty": "TWAP", "vwap_qty": "VWAP"})
      .to_string(index=False))
print("\nTWAP 单切片: 最大 %d / 最小 %d" % (bucket.twap_qty.max(), bucket.twap_qty.min()))
print("VWAP 单切片: 最大 %d / 最小 %d" % (bucket.vwap_qty.max(), bucket.vwap_qty.min()))
print("VWAP 首片占比 %.1f%%，末片占比 %.1f%%" % (
    100 * bucket.vwap_qty.iloc[0] / order_qty,
    100 * bucket.vwap_qty.iloc[-1] / order_qty))
```

输出会看到：TWAP 每个切片约 4.17 万股（最后一片吸收取整误差）；VWAP 首片和末片明显更大，午间切片只有三万多股。**如果今天收盘成交量突然放大，VWAP 的历史曲线会低估尾盘，导致尾盘被动追单**，这是 VWAP 最常见的失效点。

## 实践二：POV 拆单模拟

POV 不预设完成时间，只约束「每期不超过市场成交量的 `ρ`」：

```python
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
n = 240
t = np.arange(n)
shape = 1.0 + 2.0 * np.exp(-t / 25) + 1.5 * np.exp(-(n - 1 - t) / 20)
market_volume = (shape * 200_000 * rng.lognormal(0, 0.2, n)).round().astype(int)

order_qty = 8_000_000
participation = 0.10          # 最多吃掉每分钟成交量的 10%
remaining = order_qty
rows = []

for i in range(n):
    cap = int(market_volume[i] * participation)
    qty = min(remaining, cap)
    remaining -= qty
    rows.append((i, market_volume[i], cap, qty, remaining))
    if remaining == 0:
        break

pov = pd.DataFrame(rows, columns=["分钟", "市场量", "上限", "本单成交", "剩余"])
pov["累计成交"] = pov["本单成交"].cumsum()
pov["累计参与率"] = pov["累计成交"] / pov["市场量"].cumsum()

print(pov.head(8).to_string(index=False))
print("\n完成用时: %d 分钟, 完成率 %.2f%%" % (
    len(pov), 100 * (order_qty - remaining) / order_qty))
print("全程平均参与率: %.2f%%" % (100 * pov["累计参与率"].iloc[-1]))
```

关键观察：

- 市场放量的开盘段成交快，午间几乎不动，**完成时间由市场流动性决定，而不是由你的计划决定**。
- 平均参与率贴近但不超过 `ρ`；本示例订单约占全天成交量的 13%，即使 `ρ=10%`，到收盘也只完成约 79%。
- 因此 POV 必须设置「未完成兜底」：尾盘转限价/市价、提高参与率、跨日继续，或在信号层就按可成交量缩减目标仓位。只盯着 `ρ` 不管完成率，是 POV 最常见的生产事故。

## 实践三：一次性市价 vs TWAP 的冲击对比

用五档盘口逐档吃单模拟。一次性打 48 万股会吃穿五档并产生额外冲击；TWAP 拆成 12 片，每片只吃前两档，但要承担 12 个区间的价格波动。跑 300 条随机路径比较分布：

```python
import numpy as np
import pandas as pd

P0 = 10.0
ORDER = 480_000
N_SLICE = 12
LEVELS = np.array([20_000, 40_000, 60_000, 80_000, 100_000])  # 五档挂单量
TICK = 0.01

def walk_book(mid, qty):
    """从卖一逐档吃单，返回成交均价；超过五档按线性惩罚估算。"""
    filled, notional = 0, 0.0
    for i, depth in enumerate(LEVELS):
        take = min(qty - filled, depth)
        notional += take * (mid + TICK * (i + 1))
        filled += take
        if filled >= qty:
            break
    if filled < qty:
        extra = qty - filled
        px = mid + TICK * 6 + TICK * 2 * np.ceil(extra / 100_000)
        notional += extra * px
    return notional / qty

def path_cost(rng, mode):
    mid = P0
    if mode == "market":
        return (walk_book(mid, ORDER) / P0 - 1) * 1e4
    notional = 0.0
    for _ in range(N_SLICE):
        mid *= 1 + rng.normal(0, 0.0010)      # 每区间 10bp 波动
        q = ORDER // N_SLICE
        notional += q * walk_book(mid, q)
    return (notional / (q * N_SLICE) / P0 - 1) * 1e4

rng = np.random.default_rng(42)
twap = np.array([path_cost(rng, "twap") for _ in range(300)])
market = np.array([path_cost(rng, "market") for _ in range(300)])

summary = pd.DataFrame({
    "均值bps": [market.mean(), twap.mean()],
    "标准差bps": [market.std(), twap.std()],
    "95分位bps": [np.percentile(market, 95), np.percentile(twap, 95)],
    "最差bps": [market.max(), twap.max()],
}, index=["一次性市价", "TWAP 12片"])
print(summary.round(2).to_string())
print("\nTWAP 比一次性市价更差的路径占比: %.1f%%" % (100 * (twap > market).mean()))
```

典型结果：一次性市价均值约 60 bp，方差几乎为 0；TWAP 均值约 14 bp，但择时风险带来 21 bp 左右的标准差，95 分位约 48 bp，少量路径会反超一次性市价（本示例约 1%）。**结论不是「TWAP 一定更好」，而是：当冲击弹性大、波动可控时拆单划算；当 alpha 衰减极快或波动极高时，慢反而更贵。**

## 常见误区与坑

1. **用收盘价假设成交**：回测里 `close` 必然成交，实盘尾盘可能涨停、停牌、流动性枯竭。至少用次日开盘价 + 滑点，并对涨跌停做可成交性判断。
2. **忽略涨跌停与停牌**：涨停买不进、跌停卖不出，停牌期间信号仍然存在。回测要显式过滤，实盘要有「废单/未成交」处理。
3. **把历史成交量当可成交量**：历史成交量是全市场的事后统计，你的订单本身会改变成交量，也会被其他算法单抢先。
4. **拆单越细越好**：切片太细会撞上最小交易单位、固定费用、撤单限频，还拉长暴露时间。A 股最小 100 股，切片数量要满足 `单切片 ≥ 100 股` 且覆盖固定成本。
5. **只看成交部分滑点**：未成交部分的机会成本常被忽略，而它可能才是亏损主因。
6. **基准价随意换**：这次用 VWAP、下次用收盘价，执行评估永远「表现良好」，无法定位问题。
7. **忽略交易规则**：集合竞价不可撤单时段、盘中临时停牌、价格笼子，都会让「理论上可撤」的订单实际撤不掉。

## 常见问题 Q&A

**Q1：小资金也需要算法交易吗？**
资金量小于单票日成交量的万分之一时，冲击成本很小，算法交易的主要价值是「避免一次性打穿盘口」和「减少情绪化操作」。几十万的单用限价单分 2–3 笔即可，不必上完整 EMS。

**Q2：TWAP 和 VWAP 怎么选？**
有明确 VWAP 考核基准、标的流动性稳定，选 VWAP；需要时间中性、不想依赖历史成交量分布，选 TWAP；流动性差且不能暴露规模，选 POV；对风险敏感、有明确 alpha 衰减，选 IS。

**Q3：算法单保证成交吗？**
不保证。所有算法都只是「控制节奏」，不是「保证流动性」。必须设计兜底：尾盘转激进限价、设置最大参与率、允许跨日完成，或在信号层就按可成交量缩减目标仓位。

**Q4：回测滑点设 10 bp 就够了吗？**
取决于标的和规模。大盘股、小单可能 5 bp 够；小市值、大单可能 50 bp 以上。更可靠的做法是用「参与率 → 冲击」的回归模型，按每日成交量和下单量动态计算，而不是全市场统一常数。

**Q5：涨跌停和停牌怎么在回测里处理？**
买入时若 `open == 涨停价` 或全天一字板，视为不可买；卖出时若 `open == 跌停价`，视为不可卖；停牌日不生成订单。用「次日开盘价 + 是否触及涨跌停」判断，比用收盘价更接近实盘。

**Q6：自研 OMS 还是买？**
个人/小团队直接用券商 QMT/Ptrade 的订单管理能力，自己只做信号和风控；当出现多账户、多策略、跨市场、需要统一风控和审计时，才值得自研 OMS。自研的第一优先级不是功能，而是幂等、持久化、对账。

1. 买入 10 万股，决策价 20.00，到达价 20.02，成交均价 20.06，成交 8 万股，期末价 20.20。请分解 IS 的 delay、trading、opportunity（bps）。
2. 为什么 Almgren-Chriss 在风险厌恶趋于 0 时退化为 TWAP？`κ` 的物理含义是什么？
3. POV 参与率设为 20%，但订单量占全天成交量 40%，会发生什么？应如何兜底？
4. 断线重连后，为什么不能只依赖增量回报恢复状态？正确的恢复流程是什么？
5. 某策略回测夏普 2.0，实盘执行后降到 1.2。列出至少三种可能的执行侧原因，并说明如何用数据验证。
6. 冰山单和「自己拆小单」在信息泄露上有什么区别？

参考答案要点：1）delay 10 bp、trading 20 bp、opportunity 0.2×100 bp=20 bp，合计 50 bp。2）`λ→0 ⇒ κ→0`，`sinh` 比值趋于线性；`κ` 衡量「前瞻执行强度」，越大越前置。3）做不完，尾盘被迫加速，实际参与率远超上限；兜底是尾盘转限价/市价、跨日、或在信号层缩量。4）增量可能丢失且乱序；应全量拉取当前委托与成交，按 `ClOrdID` 对齐后再接增量。5）滑点假设过低、成交率不足、延迟导致价格漂移、涨跌停未过滤；用成交回报做 IS 分解验证。6）交易所原生冰山不暴露真实数量但仍有固定标识；自己拆单会被对手从订单节奏、价格行为识别，信息泄露更强。
