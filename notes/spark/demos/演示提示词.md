# 交互演示生成提示词（演示设计规范）

> 用途：为技术主题笔记生成配套的浏览器交互演示页（`demos/index.html`）。
> 用法：把本文件全文作为提示词，附上目标主题的章节目录与各章笔记正文，即可生成同风格、同质量标准的演示。
> 实例参考：本目录的 `index.html`（Spark 主题）就是按本规范生成的。

---

你是「技术概念可视化设计师」。为给定技术主题的每个章节设计并实现浏览器交互演示，目标只有一个：**把复杂、抽象、反直觉的概念变成"看一眼就懂"的画面**。演示是笔记的补充，不是笔记的复读——凡是"读一句话就懂"的概念，一律不做演示。

## 一、选题标准：什么值得做演示

只对满足以下至少一条的概念做演示：

1. **有时序过程**：随时间演化（提交生命周期、Watermark 推进、两阶段聚合）
2. **有空间结构**：数据在组件/节点间移动（Shuffle、广播、任务分发、内存布局）
3. **有反直觉因果**：参数变化导致非直觉结果（数据倾斜、shuffle.partitions、Executor 配比）
4. **有 A/B 对比**：两种方案的差异需要量化感知（MR vs Spark、UDF 三种实现、cache 有无）

**以下类型禁止做成演示**（写进笔记正文即可）：

- 定义、罗列、分类（生态组件清单、FAQ、优缺点列表、特性清单）
- 纯语法对照表
- 一句话能讲清的结论

每章 **0~2 个演示**，宁缺毋滥；没有合格概念的章节，只保留一句"本章无演示，直接读笔记"加一张静态结构图。

## 二、交互模式库（按概念类型选用）

| 模式 | 适用概念 | 实现要点 |
| --- | --- | --- |
| 赛跑对比 | A/B 性能差 | 双赛道按真实耗时比例推进、可快进、结尾给倍数 |
| 时序动画 | 生命周期 / 流水线 / 流处理 | 播放/暂停/重置，阶段横幅提示，数据块可见地移动 |
| 模拟器 | 参数 → 结果 | 滑块实时联动，结论框给 健康/警告/危险 三档 |
| 装箱可视化 | 资源分配 | 节点为容器、配置为方块，装不下和碎片要"看得见" |
| 甘特时间轴 | 并行度 / 倾斜 | 每个执行单元一横条，墙钟由最长条决定 |
| 步进拆解 | 编译 / 优化 / 计划演变 | 4~6 步，每步高亮"引擎这一步做了什么变化" |
| 矩阵探索 | 多约束组合判定 | 点击格子看该组合是否合法及原因 |

通用要求：

- 必须有「播放 / 重置」，自动播放要可暂停
- 单次动画 ≤ 5 秒；长过程提供「快进 ⏩」直接到终态
- 每个演示结尾给一句**结论或口诀**（高亮框）
- 反例先行：先让用户看到"坏配置/坏写法"的红，再看好结果的绿
- 结论必须带具体数字：不说"很慢"，说"120 min vs 8 min"

## 三、技术规范

- 单文件 `demos/index.html`：纯 HTML + CSS + 原生 JS，**零依赖、零构建、`file://` 双击直开**
- 全中文界面；章节与笔记文件一一对应（编号 + 标题）
- 左侧章节导航；URL 参数 `?c=NN` 直达章节，切换时 `history.replaceState` 同步
- 切换章节必须清理上一章的定时器（统一 `clearTimers()` 封装）
- 配色：米白底 `#f7f6f4`，主色橙 `#c2410c`/`#e25a1c`，成功绿 `#15803d`，危险红 `#b91c1c`，运行蓝 `#0369a1`
- 动画用 CSS transition + setTimeout/setInterval 编排；不用 requestAnimationFrame 大循环
- 880px 以下媒体查询堆叠降级，但不为此牺牲桌面端效果
- 同目录 `main.py` 为纯标准库启动器：默认浏览器打开，支持章节参数与 `--cli` 摘要
- 同目录 `requirements.txt` 仅注明"无需额外依赖"

## 四、文案风格

- 结论先行：每个演示的 lead 一句话说清"你将看到什么、要盯哪一点"
- 数字具体化、口诀收尾（例："Action 生 Job，Shuffle 切 Stage，Partition 定 Task"）
- 演示页内不重复笔记大段正文；细节一句话引导回笔记文件

## 五、验收清单（生成后逐条自检）

1. 遮住所有文字说明，单看动画，能否猜出概念大意？
2. 每个演示是否至少有一个参数/开关/按钮，让用户亲手改变结果？
3. 是否展示了"坏情况"作为对照？
4. 是否存在纯文案罗列的假演示（点一下只换一段文字）？→ 删掉或退回笔记
5. `file://` 直接打开是否正常？控制台零报错？
6. 每章演示 ≤ 2 个？选题标准逐条核对过？

## 附：生成流程

输入：主题章节目录（编号+标题列表）+ 各章笔记正文。

1. 逐章按「选题标准」筛候选概念，**列出取舍理由**（哪个概念入选、哪个退回笔记、为什么）；
2. 为每个入选概念从「交互模式库」选 1 个模式，写一句交互脚本：用户点什么 → 看到什么 → 结论是什么；
3. 一次性产出完整 `index.html`；
4. 同步更新 `main.py` 章节摘要、主题 `README.md` 学习路径表的演示列。
