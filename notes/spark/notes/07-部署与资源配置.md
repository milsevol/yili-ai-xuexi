# 07 部署与资源配置

## 一句话

**部署 = 选运行模式（local/standalone/YARN/K8s）+ 配资源（内存/核数/并行度）+ 管依赖（jar/whl/配置）**：三者决定了你的作业「跑在哪、跑多快、稳不稳」。

## 四种运行模式对比

| 模式 | 命令 | 特点 | 适用 |
| --- | --- | --- | --- |
| **local** | `--master local[N]` | Driver/Executor 同进程多线程 | 开发调试、CI 测试 |
| **standalone** | `--master spark://host:7077` | Spark 自带简易集群 | 无 YARN/K8s 时的独立小集群 |
| **YARN** | `--master yarn` | 复用 Hadoop 集群资源 | 国内生产主流 |
| **Kubernetes** | `--master k8s://https://...` | 容器化，弹性隔离 | 云原生团队，趋势 |

```bash
# YARN 生产提交（cluster 模式）
spark-submit \
  --master yarn \
  --deploy-mode cluster \
  --name dwd_trade_etl \
  --num-executors 20 \
  --executor-memory 8G \
  --executor-cores 4 \
  --driver-memory 4G \
  --conf spark.sql.shuffle.partitions=400 \
  --conf spark.sql.adaptive.enabled=true \
  --queue etl_queue \
  --py-files deps.zip \
  main.py
```

## spark-submit 核心参数速查

| 参数 | 含义 | 经验值/说明 |
| --- | --- | --- |
| `--num-executors` | Executor 个数 | 静态分配时用；开动态分配后只是初始值 |
| `--executor-memory` | 单个 Executor 堆内存 | 4~16G 常见；>32G 后 GC 收益递减 |
| `--executor-cores` | 单个 Executor 并发 Task 线程数 | **4~6 最佳**；太多会争抢 HDFS/网络吞吐 |
| `--driver-memory` | Driver 堆内存 | collect/广播大表时需调大；生产 4~8G |
| `--queue` | YARN 队列 | 决定资源配额与优先级 |
| `--conf k=v` | 任意 Spark 配置 | 优先级高于 `spark-defaults.conf` |
| `--py-files` | Python 依赖（zip/egg/whl） | 会分发到所有节点 |
| `--packages` | Maven 坐标依赖 | 联网拉取，离线环境用 `--jars` |
| `--files` | 需要分发的普通文件 | 如配置、词典 |

## 资源计算的「小数学」（必会）

总资源 = num-executors × (executor-cores, executor-memory)

```
例：20 executors × 4 cores × 8G
  → 总并发 Task 线程 = 20 × 4 = 80
  → 总堆内存 = 20 × 8G = 160G
  → YARN 还会为每个 Executor 申请 overhead（默认 max(384M, 10%×8G)）
```

**经验法则**：

1. **宁可多 Executor 少核，不要少 Executor 多核**：5 个 × 4 核 优于 1 个 × 20 核（后者 HDFS 吞吐打不满、GC 严重）。
2. **executor-memory 不是越大越好**：超过 32G 触发 JVM 大堆 GC 问题；16G 左右是甜点。
3. **driver-memory 看两件事**：collect 回来的数据量、广播表大小。

## Executor 内存的「内部结构」（OOM 排查基础）

```
executor-memory (8G)
 ├── Execution 内存：Shuffle/聚合/排序的缓冲区（可溢写磁盘）
 ├── Storage 内存：cache 的 RDD/DataFrame
 │    （两者默认各占 50%，可互相借用：unified memory）
 └── User 内存：你的对象、UDF 开销、广播变量…

+ overhead（堆外，网络/Native/PySpark worker 用）
```

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `spark.memory.fraction` | 0.6 | 堆内存中给 Execution+Storage 的比例 |
| `spark.memory.storageFraction` | 0.5 | 上者中 Storage 的保底比例 |
| `spark.executor.memoryOverhead` | max(384M, 0.1×executor) | 堆外内存，PySpark 任务建议调大 |
| `spark.executor.pyspark.memory` | 无 | Python worker 进程的内存上限 |

**PySpark 特别提示**：Python worker 进程的内存**不占 JVM 堆**，走 overhead。普通 UDF 吃 Python 内存，OOM 在 JVM 里看不到——要关注 `memoryOverhead` 和 `pyspark.memory`。

## 动态资源分配（Dynamic Allocation）

```python
spark.conf.set("spark.dynamicAllocation.enabled", True)
spark.conf.set("spark.dynamicAllocation.minExecutors", 2)
spark.conf.set("spark.dynamicAllocation.maxExecutors", 50)
spark.conf.set("spark.shuffle.service.enabled", True)   # 必须！否则回收 Executor 丢 Shuffle 数据
```

| 优点 | 代价 |
| --- | --- |
| 忙时扩、闲时缩，不占着集群 | 扩容器有启动延迟；Task 迁移有开销 |
| 多租户集群利用率高 | 需要外排服务（ESS）配合 |

生产常见做法：**定时大作业关动态分配、固定资源保证可预期**；交互式/即席查询开动态分配。

## 依赖管理（PySpark 三大方式）

| 方式 | 命令 | 适用 |
| --- | --- | --- |
| **纯 Python 包** | `--py-files my_pkg.zip` 或 `--archives env.tar.gz#env` | 业务自定义模块、少量三方库 |
| **Maven 坐标** | `--packages org.apache.spark:spark-sql-kafka-0-10_2.12:3.5.1` | 有外网/私服；自动解决传递依赖 |
| **虚拟环境打包** | conda-pack / venv-pack + `--archives` | 重依赖（pandas/numpy 特定版本） |

conda-pack 示例（生产常用）：

```bash
conda create -n spark_env python=3.11 pandas pyarrow
conda pack -n spark_env -o env.tar.gz

spark-submit \
  --archives env.tar.gz#environment \
  --conf spark.pyspark.driver.python=./environment/bin/python \
  --conf spark.pyspark.python=./environment/bin/python \
  main.py
```

## 生产提交模板（YARN）

```bash
#!/bin/bash
set -euo pipefail

APP=dwd_trade_daily
DT=${1:-$(date -d "yesterday" +%Y-%m-%d)}     # 业务日期，调度平台传入

spark-submit \
  --master yarn --deploy-mode cluster \
  --name "${APP}_${DT}" \
  --queue etl_high \
  --num-executors 30 --executor-cores 4 --executor-memory 8G \
  --driver-memory 4G \
  --conf spark.sql.adaptive.enabled=true \
  --conf spark.sql.shuffle.partitions=600 \
  --conf spark.serializer=org.apache.spark.serializer.KryoSerializer \
  --conf spark.executor.memoryOverhead=2G \
  --conf spark.dynamicAllocation.enabled=false \
  --conf spark.yarn.maxAppAttempts=2 \
  --conf spark.yarn.am.attemptFailuresValidityInterval=1h \
  --archives env.tar.gz#environment \
  --py-files common.zip \
  main.py --dt "${DT}"
```

要点：**失败重试**（maxAppAttempts）、**业务日期外部传入**（配合 DolphinScheduler 的 `${dt}` 变量）、**资源参数化**（不同队列不同配额）。

## 与调度平台的配合（DolphinScheduler）

| 对接点 | 做法 |
| --- | --- |
| 任务类型 | Shell 节点调 `spark-submit`，或用 DS 的 Spark 任务插件（可视化填参） |
| 业务日期 | DS 时间变量 `${yyyy-MM-dd}` 传给脚本参数 |
| 失败重试 | DS 任务级重试 + spark-submit 的 `maxAppAttempts` 双保险 |
| 日志 | cluster 模式日志在 YARN，`yarn logs -applicationId` 拉取；DS 可配置日志采集 |
| 资源隔离 | 不同业务线提交到不同 YARN 队列 |

## 本地开发与生产的一致性

```python
# main.py：一套代码，两种跑法
import argparse
from pyspark.sql import SparkSession

def build_spark(app: str, master: str | None):
    b = SparkSession.builder.appName(app)
    if master:                       # 本地调试时传入 local[*]
        b = b.master(master)
    return b.getOrCreate()

if __name__ == "__main__":
    p = argparse.ArgumentParser()
    p.add_argument("--dt", required=True)
    p.add_argument("--master", default=None)   # 生产不传，走 spark-submit --master
    args = p.parse_args()

    spark = build_spark("dwd_trade_daily", args.master)
    run(spark, args.dt)
    spark.stop()
```

调试：`python3 main.py --dt 2026-10-31 --master 'local[*]'`；生产：`spark-submit ... main.py --dt 2026-10-31`。
