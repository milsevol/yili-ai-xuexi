# 01 概述与定位

## 一句话

**Apache Spark**：一个通用的大数据分布式计算引擎——把「一份数据切很多块、放到很多机器上并行算」这件事抽象成几行代码，并且用**内存计算 + DAG 调度**把速度做到极致，一套引擎同时覆盖批处理、SQL、流处理和机器学习。

## 它解决什么问题

在 Spark 之前，大数据计算的主流传法是 Hadoop MapReduce。MapReduce 的核心痛点：

| 痛点 | MapReduce 的表现 | Spark 的解法 |
| --- | --- | --- |
| 慢 | 每个 Map/Reduce 阶段都要读写 HDFS，磁盘 IO 是瓶颈 | 中间结果尽量放内存，迭代计算快 10~100 倍 |
| 编程模型笨 | 一切都要翻译成 Map + Reduce 两步，一个 join 写几百行 | RDD/DataFrame 提供 map、filter、join、groupBy 等几十个算子 |
| 只能离线批 | 干不了迭代计算（机器学习）、流处理、交互式查询 | 批 + 流 + SQL + ML + 图计算，一套引擎 |
| 调度死板 | 只有两个阶段，无法优化全局执行计划 | 先构建完整 DAG，再全局切分 Stage 调度 |

一句话总结 Spark 的思想：**把分布式计算抽象成「分布式集合上的函数式操作」，让引擎去操心切分、调度、容错。**

## 经典的速度来源：内存 + DAG

```
MapReduce:  HDFS → Map → [写盘] → Reduce → [写盘] → Map → [写盘] ...
Spark:      内存数据 → map → filter → reduceByKey → ... （DAG 流水线，内存传递）
```

- **内存计算**：迭代算法（如梯度下降要反复扫同一份数据）把数据 cache 在内存，避免反复读盘。
- **DAG 调度**：先记录用户的全部操作构成 DAG，再做全局优化（算子流水线、谓词下推等），而不是边做边看。

> 注意：Spark ≠ 「全内存数据库」。数据放不放内存由你控制（cache）；放不下就走磁盘 + Shuffle，照样能算 TB/PB 级数据。

## 发展简史（了解即可）

- **2009** 诞生于 UC Berkeley AMPLab，2010 开源，2013 进 Apache 孵化器，**2014 毕业为顶级项目**。
- **1.x**：RDD 为核心抽象；1.3 引入 DataFrame；1.6 引入 Dataset（仅 Scala/Java）。
- **2.x**（2016）：DataFrame/Dataset 成为一等公民，底层全部走 Catalyst + Tungsten；Structured Streaming 诞生。
- **3.x**（2020 起）：**AQE 自适应查询执行**、动态分区裁剪、Pandas API on Spark、Join 策略大幅优化、K8s 支持 GA。**本系列以 3.5 为准。**
- 近年趋势：Spark Connect（瘦客户端）、与湖仓格式（Delta / Iceberg）深度集成。

## 生态组件：一套引擎，四种计算形态

| 组件 | 干什么 | 典型场景 |
| --- | --- | --- |
| **Spark Core** | RDD、DAG 调度、内存管理、容错 | 一切的基础，其他组件都建立在它之上 |
| **Spark SQL** | DataFrame / SQL 查询结构化数据 | 数仓 ETL、报表、交互式分析（最常用） |
| **Structured Streaming** | 微批 + 持续处理的流计算 | 实时数仓、实时监控、CDC 同步 |
| **MLlib** | 分布式机器学习库 | 特征工程、LR/RF/GBT、ALS 推荐 |
| **GraphX** | 图计算（Scala 为主） | 关系网络、PageRank |

周边重要伙伴：数据源连接器（HDFS / S3 / Kafka / JDBC / HBase）、湖仓格式（Delta Lake / Apache Iceberg / Hudi）、集群管理器（YARN / K8s / Standalone）。

## 和同类产品怎么选

| 维度 | Spark | Flink | Hadoop MapReduce | DuckDB / Polars |
| --- | --- | --- | --- | --- |
| 定位 | 通用分布式计算引擎 | 流优先的流批引擎 | 第一代分布式批处理 | 单机/嵌入式分析引擎 |
| 强项 | 批处理、SQL、ML、生态 | 低延迟实时、状态管理 | 历史存量（已式微） | 单机秒级分析 GB 级数据 |
| 流处理 | 微批（秒级），3.x 有持续模式 | 原生流（毫秒级） | 不支持 | 不支持 |
| 上手语言 | PySpark / Scala / SQL | Java / Scala / SQL | Java | Python / SQL |
| 集群规模 | 单机到上万台 | 单机到上万台 | 集群 | 单机 |
| 典型用户 | 数仓、数据平台、算法 | 实时风控、实时数仓 | 遗留系统 | 数据科学个人分析 |

**经验法则**：

- **离线数仓 / 批 ETL / 数据科学** → Spark 是默认答案，社区和岗位需求最大
- **强实时（亚秒延迟）/ 复杂状态流处理** → Flink
- **单机内存放得下、只想快速分析文件** → DuckDB / Polars 更轻快，别上集群
- MapReduce 新项目基本不用再学，看懂概念即可

## Spark 不是什么（常见误解）

1. **不是存储系统**：它没有自己的存储，数据在 HDFS / S3 / 对象存储 / 数据库里。
2. **不是调度平台**：定时触发、依赖编排交给 DolphinScheduler / Airflow，Spark 只管「这一跑」。
3. **不是数据库**：没有事务、没有索引、不适合点查（点查走 HBase / OLAP 库）。
4. **不是银弹**：小数据量（GB 级以下）单机工具往往更快更省。

## 学习主线

本系列围绕这条链路展开：

```
业务问题 → 选择抽象(RDD/DataFrame/SQL) → 编写转换逻辑
       → 提交(spark-submit) → Driver 构建 DAG → 切分 Stage
       → Executor 并行执行 Task → Shuffle / 缓存 / 容错
       → 写出结果 → 观察 UI → 调优
```

先记住两个词：**转换（Transformation）是惰性的，行动（Action）才真正开跑。** 这是理解 Spark 一切行为的钥匙。

## 动手体验

```python
from pyspark.sql import SparkSession

spark = SparkSession.builder.master("local[*]").appName("ch01").getOrCreate()

# 3 行代码完成分布式 WordCount
text = spark.read.text("README.md")
counts = (text.selectExpr("explode(split(value, ' ')) as word")
              .groupBy("word").count()
              .orderBy("count", ascending=False))
counts.show(10)

spark.stop()
```
