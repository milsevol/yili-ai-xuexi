# 11 管理后台常见操作

## 一句话

管理后台（https://work.weixin.qq.com/）是企微的「总控室」：管理员体系、通讯录、应用、客户联系、安全设置、审计日志都在这里。开发 API 之前，先熟悉后台能让你少走一半弯路。

## 管理员体系：三类角色

企微的管理员不是「非黑即白」，而是分了三层权限：

```
                ┌───────────────────────┐
                │   创建者（Creator）     │
                │  注册企业的那个人        │
                │  拥有所有权，可转让      │
                └───────────┬───────────┘
                            │
              ┌─────────────┼─────────────┐
              ▼             ▼             ▼
       ┌──────────┐  ┌──────────┐  ┌──────────┐
       │ 超级管理员 │  │ 分级管理员 │  │ 应用管理员 │
       │  全部权限  │  │ 部分权限   │  │ 单个应用   │
       │ (除转让)  │  │ (按模块)  │  │  管理员    │
       └──────────┘  └──────────┘  └──────────┘
```

| 角色 | 人数上限 | 权限范围 | 典型场景 |
| --- | --- | --- | --- |
| **创建者** | 1 人 | 全部权限 + 可转让/解散企业 | 企业法人 / IT 一把手 |
| **超级管理员** | 不限 | 除「转让/解散」外全部权限 | IT 部门负责人 |
| **分级管理员** | 不限 | 按模块分配（通讯录/应用/审批/...） | HR 管通讯录、行政管审批 |
| **应用管理员** | 每个应用可设 | 只管某个应用的可见范围/回调/菜单 | 业务线负责人 |

> ⚠️ **关键差异**：创建者和超级管理员都能进「我的企业 → 权限管理」配权限，但只有**创建者**能转让/注销企业。

## 操作 1：设置超级管理员

路径：**管理后台 → 我的企业 → 权限管理 → 超级管理员**

### 步骤

1. 用创建者账号登录管理后台（work.weixin.qq.com，扫码登录）
2. 顶部菜单点「我的企业」
3. 左侧选「权限管理」
4. 「超级管理员」标签页 → 点「+ 添加」
5. 选择成员（必须是通讯录中已激活的成员）
6. 设置权限范围：
   - ✅ 通讯录管理
   - ✅ 应用管理
   - ✅ 客户联系管理
   - ✅ 审批管理
   - ⬜ 仅查看权限（不给编辑）
7. 保存

### 常见坑

- 添加的成员必须是**已激活**状态（成员列表里显示「已加入企业」）
- 手机号脱敏的成员不能当管理员（隐私要求）
- 被加为超级管理员后，对方企微会收到通知

## 操作 2：转让创建者

**这个操作不可逆**，谨慎使用。

路径：**我的企业 → 企业信息 → 创建者信息 → 转让**

### 步骤

1. 创建者本人登录
2. 我的企业 → 企业信息
3. 找到「创建者」一栏 → 点「转让」
4. 选择新创建者（必须满足：已是超级管理员 + 已实名）
5. 扫码 + 短信双重验证
6. 转让成功后，原创建者变成超级管理员

### 适用场景

- 企业法人变更
- 原 IT 负责人离职
- 公司被收购

> ⚠️ **风险**：转让后原创建者**永久失去**企业所有权。建议先把所有 Secret、审批模板、客户联系配置导出备份。

## 操作 3：设置分级管理员（按模块授权）

路径：**我的企业 → 权限管理 → 分级管理员**

### 常见的分级管理员角色

| 角色 | 授权模块 | 适用对象 |
| --- | --- | --- |
| HR 管理员 | 通讯录管理、成员入职/离职 | HR |
| 应用运维 | 应用管理（全部自建应用） | IT 运维 |
| 审批管理员 | 审批模板配置、审批数据查询 | 行政 |
| 客户管理员 | 客户联系配置、离职继承 | 销售总监 |
| 打卡管理员 | 打卡规则、考勤数据 | HR / 行政 |
| 会议管理员 | 会议管理、会议室资源 | 行政 |

### 授权步骤

1. 「分级管理员」标签页 → 「+ 添加」
2. 选择成员
3. 勾选权限模块（可组合）
4. **可限定部门范围**：比如「只能管技术部的通讯录」
5. 保存

## 操作 4：应用管理员（单个应用授权）

路径：**应用管理 → 自建应用 → 选择应用 → 应用详情 → 权限管理**

### 步骤

1. 进入某个自建应用详情页
2. 找到「应用管理员」一栏
3. 点「+ 添加管理员」
4. 选择成员（可以同时是其他应用的管理员）

### 应用管理员能做什么

- ✅ 修改应用可见范围
- ✅ 配置应用主页 URL、菜单
- ✅ 查看应用 Secret（重要！）
- ✅ 设置回调 URL / Token / AES Key
- ❌ 不能删除应用
- ❌ 不能转让应用所有权

> 💡 **最佳实践**：每个自建应用至少配 2 个管理员，避免单点故障（一个人离职导致应用没人管）。

## 操作 5：通讯录管理

路径：**通讯录**

### 子操作 5.1：批量导入成员

1. 通讯录 → 「批量导入/导出」
2. 下载 Excel 模板
3. 填好成员信息（姓名/手机/邮箱/部门）
4. 上传 Excel → 系统自动创建账号
5. 给成员发邀请短信/邮件激活

### 子操作 5.2：部门调整

1. 通讯录 → 选中成员 → 「编辑」
2. 在「部门」字段勾选新部门
3. 支持多部门归属（一个人属于多个部门）
4. 保存

### 子操作 5.3：成员离职

1. 通讯录 → 选中成员 → 「删除」/「禁用」
2. 两种区别：
   - **删除**：彻底移除，无法恢复
   - **禁用**：保留记录，可恢复，但员工无法登录

> ⚠️ **重要**：删除成员会触发「客户联系离职继承」流程。建议先在客户联系里分配好客户，再删人。

### 子操作 5.4：标签管理

1. 通讯录 → 「标签」
2. 创建标签（比如「外包」「实习生」「VIP」）
3. 给成员打标签（应用可见范围、消息推送可以按标签过滤）

## 操作 6：应用管理

路径：**应用管理**

### 子操作 6.1：调整应用可见范围

1. 应用管理 → 自建应用 → 选应用
2. 应用详情 → 「可见范围」
3. 添加/移除部门、标签、成员
4. 保存后**立即生效**（员工企微会实时刷新）

### 子操作 6.2：停用/启用应用

- **停用**：员工工作台看不到应用图标，但应用还在
- **启用**：恢复展示
- **删除**：永久删除，所有 Secret 失效

### 子操作 6.3：调整应用排序

工作台应用的显示顺序：
1. 应用管理 → 自建应用列表
2. 拖拽调整顺序
3. 或设置「常用应用」置顶

### 子操作 6.4：重置 Secret

如果 Secret 泄露了：

1. 应用详情 → Secret → 「重置」
2. 确认重置（会立即让旧 Secret 失效）
3. 立即更新后端配置
4. 排查旧 Secret 泄露来源

> ⚠️ **注意**：重置 Secret 会让所有用旧 Secret 的服务立即报错。生产环境操作前要做好切换方案。

## 操作 7：客户联系管理

路径：**客户联系**

### 子操作 7.1：开通客户联系功能

1. 客户联系 → 「开始使用」
2. 设置可使用成员（建议先小范围测试）
3. 配置客户联系的 Secret（独立于自建应用 Secret）

### 子操作 7.2：配置「联系我」二维码

1. 客户联系 → 「联系我」→ 「新建联系方式」
2. 选择成员（多人时支持轮询）
3. 下载二维码，可放到官网/名片/广告
4. 客户扫码 → 自动添加成员为好友

### 子操作 7.3：离职继承规则

1. 客户联系 → 「离职继承」
2. 设置自动分配规则：
   - 按部门分配（同部门优先）
   - 按标签分配（同行业客户给同行业销售）
   - 手动分配（管理员指定）
3. 开启「离职自动分配」开关

### 子操作 7.4：客户群管理

1. 客户联系 → 「客户群」
2. 查看所有客户群列表
3. 群主离职时，可以一键把群主转让给其他成员

## 操作 8：安全设置

路径：**我的企业 → 安全与保密**

### 子操作 8.1：登录验证

| 设置项 | 说明 | 推荐 |
| --- | --- | --- |
| **二次验证** | 登录需短信/扫码二次确认 | ✅ 必开 |
| **登录 IP 限制** | 只允许公司 IP 段登录后台 | 推荐 |
| **成员设备限制** | 限制员工只能在工作设备登录企微 | 视情况 |

### 子操作 8.2：应用 IP 白名单

1. 应用详情 → 「企业可信 IP」
2. 添加调用 API 的服务器 IP
3. 不在白名单里的 IP 调 API 会报错

> 💡 **坑**：云服务器 IP 经常变（弹性 IP、容器重启）。建议用固定 IP 或 NAT 出口。

### 子操作 8.3：会话内容存档

1. 安全与保密 → 「会话内容存档」
2. 开启后，员工和客户的聊天记录会被存档（需要购买）
3. 金融、医疗行业合规必备

### 子操作 8.4：文件水印

1. 安全与保密 → 「文件水印」
2. 开启后，企微内查看的文件会带上访问者姓名水印
3. 防止截屏外泄

## 操作 9：数据统计与审计

### 子操作 9.1：使用统计

路径：**数据统计**

- 成员活跃度
- 应用使用次数
- 审批处理时长
- 打卡数据汇总
- 客户联系增长趋势

### 子操作 9.2：操作日志（审计）

路径：**我的企业 → 操作日志**

记录：
- 谁登录了后台
- 谁改了什么配置
- 谁导出了数据
- 谁重置了 Secret

> 💡 **合规要求**：金融/上市公司建议开启操作日志，保留至少 1 年。

### 子操作 9.3：API 调用统计

路径：**应用管理 → 自建应用 → API 调用统计**

- 每个接口的调用次数
- 错误率
- access_token 获取次数（盯紧 2000 次/天上限）

## 操作 10：常见应急操作

### 场景 1：员工 Secret 泄露

1. 立即重置 Secret（应用详情 → Secret → 重置）
2. 更新后端配置
3. 查操作日志看谁访问过 Secret
4. 评估泄露窗口期内的 API 调用记录

### 场景 2：管理员离职

1. 立即撤销其超级管理员权限
2. 检查他管理过的应用，把 Secret 全部重置
3. 把他负责的应用分配给其他管理员
4. 客户联系里做离职继承
5. 通讯录里禁用账号

### 场景 3：误删应用

**应用删除不可恢复**！只能重新创建：
- 重新创建同名应用
- 获取新的 AgentID 和 Secret
- 重新配置可见范围、回调 URL
- 通知所有接入方更新配置

### 场景 4：误删部门

- 部门删除会**把部门下的成员移到上级部门**（不会丢失成员）
- 但需要手动把成员重新分配到正确部门
- 重建部门后，成员要重新加入
